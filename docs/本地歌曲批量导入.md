# 本地歌曲批量导入（mp3 / flac / wav）

> 适用版本：2026-10-26 起。脚本：`scripts/import-local-songs.mjs`（零依赖，Node 18+）。
> 相关接口：`POST /api/v1/admin/files/audio`（上传）、`POST /api/v1/admin/songs/import`（导入）、
> `PUT /api/v1/admin/songs/{id}/lyric`（只补歌词）。

## 1. 它解决什么

后台原生的「JSON 导入」要求先把 **歌名、歌手 ID、音频 URL** 手写成数组：

```json
{ "rows": [{ "name": "晴天", "artistId": 1000000000000003001, "audioStandard": "https://..." }] }
```

本地文件本来就有这些信息，却要人工抄一遍。这个脚本改成「**给一个文件夹**」：

1. 递归扫描目录下的 `mp3 / flac / wav`；
2. 直接解析**文件内嵌标签**（拿不到标签时按文件名兜底）；
3. 找歌词：同目录同名 `.lrc`（UTF-8 / GBK 都能解），或音频内嵌歌词
   （ID3 `USLT` / `TXXX:LYRICS`、FLAC `LYRICS`、WAV `ILYR` 或内嵌 id3）；
4. 逐个调上传接口拿 `/media/uploads/...` URL；
5. 按 ≤200 行一批提交现有导入接口（歌词随行提交），输出逐文件报告。

它**不改后端**，也不新增「按路径读服务器文件系统」的入口——那会把目录穿越、权限与审计风险带进后台。
脚本跑在开发机上，文件本来就在本地。

## 2. 前置条件

| 项 | 要求 |
| --- | --- |
| 后端 | 已启动（默认 `http://127.0.0.1:8081`） |
| 验证码回显 | `NEWMUSIC_ADMIN_CAPTCHA_ECHO=true`（脚本要自动过图形验证码） |
| 后台账号 | 默认 `admin / admin123`；可用 `--user/--password` 或环境变量覆盖 |
| 权限 | 上传需 `admin:song:create`；`--publish` 需 `admin:song:online`；`--create-artist` 需 `admin:artist:manage` |
| 文件 | 单个 ≤50MB（与 `AdminFileController.MAX_AUDIO` 一致），仅 mp3/flac/wav |

口令只从参数或 `NEWMUSIC_ADMIN_PASSWORD` 读取，不写进报告。

## 3. 快速开始

```powershell
# 1) 先看解析结果：不登录、不上传、不写库
node scripts/import-local-songs.mjs "D:\Music\周杰伦" --dry-run

# 2) 确认无误后导入（下架 + 待审，默认不改变线上内容）
node scripts/import-local-songs.mjs "D:\Music\周杰伦"

# 3) 导入并直接上架（写 auditStatus=1 / copyrightStatus=1，落库即进 ES 索引）
node scripts/import-local-songs.mjs "D:\Music\周杰伦" --publish

# 4) 已经导入过、只是缺歌词：只补歌词，不上传、不新建歌曲
node scripts/import-local-songs.mjs "D:\Music\周杰伦" --lyrics-only --dry-run
node scripts/import-local-songs.mjs "D:\Music\周杰伦" --lyrics-only
```

> 不带 `--publish` 导入的歌曲是「下架 + 待审」，会自动出现在管理后台的**审核工作台**
> （任务类型 `SONG`）；审核通过后再去歌曲管理点「上架」。

整批同一个歌手、文件没有标签时：

```powershell
node scripts/import-local-songs.mjs "D:\Music\Unknown" --artist 周杰伦 --language 国语
```

目录里出现新歌手时（默认会记失败，不擅自建数据）：

```powershell
node scripts/import-local-songs.mjs "D:\Music" --create-artist
```

## 4. 目录怎么放

脚本对层级没有要求，递归扫描；标签优先，文件名兜底。两种常见结构都支持：

```
D:\Music\周杰伦\叶惠美\01. 晴天.flac      ← 标签齐全：歌名/歌手/专辑都从标签取
D:\Music\下载\阿杜 - 他一定很爱你.flac    ← 无标签：从文件名拆出"阿杜"和"他一定很爱你"
```

文件名兜底规则：

- 去掉开头的曲序前缀：`01.` `1-` `02、` `(03)`；
- 用 ` - `（或 `–` `—`）切成「歌手 - 歌名」；
- 没有分隔符时整段当歌名，歌手取标签 / `--artist`，都没有则**记失败**
  （不会生成「未知歌手」这种脏数据）。

## 5. 元数据映射

| 目标字段 | mp3 | flac | wav |
| --- | --- | --- | --- |
| 歌名 | `TIT2` / ID3v1 | `TITLE` | `LIST/INFO INAM` 或内嵌 id3 |
| 歌手 | `TPE1`（其次 `TPE2`）/ ID3v1 | `ARTIST`（其次 `ALBUMARTIST`） | `IART` 或内嵌 id3 |
| 专辑 | `TALB` / ID3v1 | `ALBUM` | `IPRD` 或内嵌 id3 |
| 时长（秒） | `TLEN`，否则 MPEG 帧头估算（取值优先 Xing/Info 帧数，否则 CBR 码率换算） | `STREAMINFO` 精确总样本数 | `data` 大小 ÷ `fmt.byteRate` |
| 流派 | `TCON` / ID3v1 | `GENRE` | `IGNR` |
| 年份 → `era` | `TDRC`/`TYER` | `DATE` | `ICRD` |
| ISRC | `TSRC` | `ISRC` | `ISRC` |
| BPM | `TBPM` | `BPM` | `IBPM` |
| 歌词 | `USLT`、`TXXX:LYRICS` | `LYRICS` / `UNSYNCEDLYRICS` | `ILYR` 或内嵌 id3 |
| 歌词（外挂） | 同目录同名 `.lrc`（优先级最高，UTF-8 / GBK / UTF-16 BOM 自动识别） | 同左 | 同左 |

补充：

- **曲序**（`TRCK` / `TRACKNUMBER` / `ITRK`）只写进报告，`t_song` 没有对应字段。
- 只有「歌手名」是不够的：脚本会按名字查后台歌手（`/admin/artists?keyword=`）拿 `artistId`；
  专辑同理按「专辑名 + 歌手」精确匹配，匹配不到就不填 `albumId`（不会瞎猜）。
- `releaseDate` 只在标签是完整 `YYYY-MM-DD` 时填；只有年份时只推导 `era`，不编造月日。
- 语种不从标签猜，默认交给后端（`国语`）；可用 `--language` 统一指定。
- 歌词内容按是否含 `[mm:ss` 时间轴自动判定 `contentType`（1 标准 LRC / 3 纯文本）；
  超过 20 万字的歌词会被跳过并写入报告（后端 `@Size` 上限），不影响歌曲本身导入。

## 6. 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `<文件夹>` | — | 必填，扫描根目录 |
| `--dry-run` | 关 | 只解析打印，不登录不上传不写库 |
| `--publish` | 关 | 导入即上架（`status=1`、`auditStatus=1`、`copyrightStatus=1`） |
| `--create-artist` | 关 | 歌手不存在时自动创建（只建歌手，不建专辑） |
| `--skip-existing` / `--no-skip-existing` | 开 | 库中已有「同名 + 同歌手」时跳过；关闭则重复导入 |
| `--artist <名称>` | — | 统一歌手，优先级低于标签，高于文件名 |
| `--language <语种>` | — | 统一语种 |
| `--no-album` | — | 不按标签匹配专辑 |
| `--lyrics-only` | 关 | 只补歌词：按「歌名 + 歌手」找已有歌曲，调 `PUT /admin/songs/{id}/lyric` |
| `--no-lyrics` | — | 不读取 `.lrc` / 内嵌歌词 |
| `--no-recursive` | — | 只扫当前目录 |
| `--limit <n>` | 0 | 只处理前 n 个文件 |
| `--max-size <MB>` | 50 | 本地体积上限（与服务端一致） |
| `--report <path>` | `.tmp/import-report-<时间戳>.json` | 报告路径 |
| `--base <url>` | `http://127.0.0.1:8081/api/v1` | 后端地址 |
| `--user/--password` | `admin/admin123` | 后台账号 |
| `--self-test` | — | 用合成文件自测解析器与歌词解码（35 项，不联网） |

## 7. 输出与报告

```
扫描 D:\Music\周杰伦
  发现音频 12 个（含子目录）
  已登录 admin（角色 ADMIN，权限 67 项）
  ↑ [1/12] 叶惠美\01. 晴天.flac：上传完成 /media/uploads/20261026/3f9c….flac
  ⊘ [2/12] 叶惠美\02. 以父之名.flac：已存在，跳过
  导入批次 1：成功 10 / 失败 1

================ 汇总 ================
  导入成功 10 / 跳过 1 / 失败 1（共 12 个）
  失败原因：
    ×1 歌手不存在：某某（加 --create-artist 可自动创建）
  报告：…\.tmp\import-report-20261026-0315.json
```

报告是 JSON，逐文件包含 `file/title/artistName/albumName/duration/artistId/albumId/audioUrl/status/reason`，
有歌词时另有 `lyricSource`（`lrc-file` / `id3-USLT` / `flac-LYRICS` / `wav-ILYR` …）与 `lyricChars`，
便于二次核对或补导。退出码：有失败行返回 `1`，全部成功/跳过返回 `0`（可直接用于 CI 或批处理）。

## 8. 边界与坑

- **不转码**：本机没有 ffmpeg，上传即原文件。`audioStandard` 指向 flac/wav 也能播
  （`player/url` 会带出 `format`），但线上建议先转 mp3 再导入。
- **50MB 上限**：单文件超过 50MB（如高码率整轨 FLAC）会被本地拦下并提示；
  可用 `--max-size 60` 放宽，但服务端仍会按 `AdminFileController.MAX_AUDIO`（50MB）拒，
  除非同步调大该常量与 `spring.servlet.multipart.max-file-size`。
- **导入 ≠ 上架**：不带 `--publish` 时落库是「下架 + 待审」，C 端与 ES 都不会出现；
  歌曲进入待审后会自动生成一条 `SONG` 审核任务，在后台「审核工作台」通过后再上架。
- **歌词不会凭空产生**：音频文件不带平台歌词，必须靠同名 `.lrc` / 内嵌歌词 / 后台文本域；
  已经导入的歌曲用 `--lyrics-only` 补，不要重复导入。
- **`--publish` 会跳过审核留痕**，只适合「已确认版权、批量铺库」；正式环境建议不吃这个开关。
- **重复导入**：默认按「歌名 + 歌手 ID」跳过；同名不同版本（live/remaster）请用 `--no-skip-existing`
  并自行在文件名里区分，否则会被当成同一首。
- **上传的文件不会随歌曲删除**：`media/uploads/<日期>/<uuid>.<ext>` 需要手工清理；
  服务端没有删除文件接口。
- **ES 写穿透**：`--publish` 后走 `SearchIndexSyncService`（事务 afterCommit + `refresh=true`），
  一般返回时已可搜；未启用 ES 时自动只写 MySQL。
- **中文与编码**：脚本内部全程 UTF-8 构造 JSON 与 multipart，不受 Windows 终端代码页影响；
  但**文件名本身**建议避免控制字符。

## 9. 自测与常见报错

```powershell
node scripts/import-local-songs.mjs --self-test
# 自测：通过 35 / 失败 0
# （WAV/FLAC/MP3 标签与时长、三种格式内嵌歌词、.lrc UTF-8/GBK 解码、文件名兜底、年代推导）
```

| 现象 | 原因 / 处理 |
| --- | --- |
| `后端未回显验证码` | 后端未以 `NEWMUSIC_ADMIN_CAPTCHA_ECHO=true` 启动 |
| `登录失败：80016` | 管理员被锁定（连续失败 5 次锁 30 分钟）或 TOTP 账号需 `totpCode` |
| `歌手不存在：xxx` | 加 `--create-artist`，或先用后台建歌手 |
| `无法确定歌手` | 文件无标签且文件名不含「歌手 - 歌名」，用 `--artist` 指定 |
| `超过 50MB` | 转码或调 `--max-size`（服务端限制另改） |
| `上传失败：80021` | 扩展名与内容不符（被改了后缀的假音频） |
| 导入成功但 C 端搜不到 | 没加 `--publish`（下架 + 待审），或审核/版权未通过 |
| 导入成功但没有歌词 | 同目录没有同名 `.lrc`，音频也没有内嵌歌词；用 `--dry-run` 看 `lyricSource` 是否为空，或加 `--lyrics-only` 补词 |

## 10. 与「JSON 导入」的关系

两者是同一套后端能力，脚本只是把「手写 JSON」换成「读文件」：

```
脚本 ──上传──► /admin/files/audio ──► media/uploads/…（UUID 命名）
     ──导入──► /admin/songs/import ──► t_song + 歌手/专辑计数 + ES 写穿透
```

需要精细控制字段（多音质、标签、封面、版权方等）时，仍可直接调 JSON 接口或后台页面。
