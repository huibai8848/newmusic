## 2. 本轮补的代码注释

注释只写在「读代码会误判」的位置，不重复方法名能表达的信息。

| 文件 | 位置 | 注释说明 |
|---|---|---|
| `module/music/service/impl/LyricServiceImpl.java` | `upsertContent` | 三段「不破坏已有数据」的逻辑：正文 trim、新建 vs 补丁更新、指针回写 + ES 刷新；并发首写的撞键重试与墓碑复活（第二轮补全） |
| 同上 | 显式类型分支 | 逐字 LRC 与标准 LRC 正文都含时间轴，不能从文本反推，必须显式传 `contentType` |

### 3.3 专项端到端（37 项）

`scripts/verify-lyrics-audit.mjs`，零依赖、只通过 HTTP 操作：

1. **登录与旧 Cookie 回归**：带失效 `ml_admin_access` 仍能取验证码；受保护接口仍返回 401/403。
2. **导入带歌词**：临时歌曲创建成功、`auditStatus=0`、`lyricId` 已回写、C 端能读到同一份正文、类型识别为 LRC(1)。
3. **后台歌词覆盖**：改成纯文本后自动识别 3；`contentType=9` 与纯空格正文都返回 10001。
4. **删除后重传（本轮新增）**：C 端超管逻辑删除歌词后，按歌曲写入应**复活原墓碑行**并复用原 ID；
   再次逻辑删除后并发发起两次写入，两个请求都应成功（不返回 99001），最终只留一份歌词。
5. **审核工作台**：任务出现在 `taskType=SONG&status=0`；类型/场景、标题、24h SLA、无提交人；
   领取 → 通过 → 歌曲 `auditStatus=1`；留痕至少包含领取与处理。
6. **上架**：审核通过后 `status=1`。
7. **清理**：C 端超管软删歌曲；歌词级联删除；带 `MYSQL_PASSWORD` 时按本轮 `taskId`
   精确删除审核任务与留痕（SQL 全部带 `newmusic.` 限定）。

运行：

# 后端 8081 已启动，且 NEWMUSIC_ADMIN_CAPTCHA_ECHO=true

# 额外精确清理审核任务/留痕
$env:MYSQL_PASSWORD = "<你的MySQL口令>"; node scripts/verify-lyrics-audit.mjs

## 4. 本轮定位并修复的 9 个问题

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | 上传的歌曲没有歌词 | 导入链路只写 `t_song`，没有写 `t_lyric`；音频内嵌歌词也没有入口 | `SongSaveReq.lyric` 随歌曲写歌词；新增后台 `GET/PUT /admin/songs/{id}/lyric`；导入脚本解析 `.lrc` / ID3 USLT / FLAC LYRICS / WAV ILYR |

| 3 | 待审歌曲不在审核列表 | 新增/导入只改 `audit_status`，从不创建 `t_audit_task` | `SongSubmittedForAuditEvent`（AFTER_COMMIT）+ `SongAuditTaskService`：建任务、按歌去重、启动回填 |

### 5.1 数据库升级（必须执行一次）

新增唯一索引属于 DDL，**已有库不能只替换 jar**：

```powershell

Remove-Item Env:MYSQL_PWD
```

脚本行为（全部限定 `newmusic.`）：

1. 统计当前未完成任务与重复组（只读）；
2. 把每组 `(task_type, target_id)` 中除 `MAX(id)` 外的未完成任务置为「4 自动关闭」，
   不物理删除，保留审核轨迹；
3. 若不存在则添加生成列 `open_key`；
4. 若不存在则添加唯一索引 `uk_audit_open_target`；
5. 再查一次索引与重复组，输出 `index_columns=1`、`duplicate_groups_after=0`。

脚本可重复执行。新库直接执行最新 `sql/schema.sql` 即可，无需再跑增量脚本。

### 5.2 仍然保留的刻意设计

- 导入/后台写入的歌词不进入歌词审核队列（见 #5），不是遗漏；
- `isPlayable` 的本地判定只用于置灰/跳过，真正播放仍以服务端 `/player/url` 为准；
- 审核任务的历史记录（已完成/已关闭）不清理，唯一索引只约束未完成任务。
