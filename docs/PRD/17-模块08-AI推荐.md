---

## 1. 模块目标

1. 为**每个用户**提供个性化的每日推荐，做到"千人千面"。
2. 为新用户/新歌解决**冷启动**问题。
3. 让推荐**可解释**，增强用户信任与点击率。

**衡量指标**：

| 指标 | 目标 | 说明 |
|---|---|---|
| 每日推荐点击率（CTR） | ≥ 25% | 点击歌曲数 / 曝光歌曲数 |
| 每日推荐完播率 | ≥ 55% | 播放 ≥ 60% 的比例 |
| 猜你喜欢 CTR | ≥ 20% | — |
| 推荐结果覆盖率（有结果用户/总用户） | 100% | 含冷启动兜底 |
| 推荐多样性（单一歌手占比） | ≤ 20% | 防止推荐同质化 |
| 推荐新鲜度（30 天内新歌占比） | ≥ 15% | — |
| 推荐接口 P95 | ≤ 300ms（缓存命中） / ≤ 1s（实时计算） | — |
| 推荐去重率（推荐已听过的占比） | ≤ 30% | — |

## 5. 每日推荐

### FR-17-001 每日推荐生成 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 每天 0 点为每个活跃用户生成 30 首个性化推荐 |
| **使用角色** | 登录用户 |
| **前置条件** | 用户有行为数据；推荐服务可用 |

**生成流程**：

```
每日 00:00（XXL-Job 触发，分批执行）
   ↓
[1] 筛选目标用户
     活跃用户定义：过去 7 天有 ≥ 1 次有效播放
     预计规模：10 万用户（分批，每批 1000，共 100 批，并发 10）
   ↓
[2] 多路召回（每路 100 首）
     ┌─ 协同过滤召回：相似用户喜欢的歌（Item-CF / User-CF）
     ├─ 内容召回：用户偏好标签/风格/语种/年代的歌
     ├─ 向量召回：基于用户历史歌曲向量的平均，ANN 检索相似
     ├─ 热度召回：全站热门 + 上升期歌曲
     ├─ 新鲜召回：近期新歌（发布 ≤ 30 天）
     ├─ 场景召回：基于用户常听时段（早/午/晚/夜）匹配场景标签
     └─ 社交召回：关注的人收藏/分享的歌
   ↓
[3] 粗排（规则 + 轻量模型）
     融合各路召回（加权 RRF），过滤已听过/不喜欢/下架/无版权
     → 得到 300 首候选
   ↓
[4] 精排（模型或 LLM）
     特征：用户画像、歌曲特征、交叉特征（用户对歌手/风格的历史偏好）
     输出：每首的预测 CTR/完播率
   ↓
[5] 重排（业务规则）
     - 去重：同一歌手最多 2 首
     - 打散：相邻两首不能同风格/同语种
     - 插入：保留 2 首新歌 + 1 首经典老歌 + 1 首冷门探索
     - 置顶：运营置顶歌曲插到指定位置
     - 多样性：Top 30 覆盖 ≥ 10 个歌手
   ↓
[6] 生成推荐理由（每首一句话）
   ↓
[7] 写入 Redis：ml:rec:daily:{userId}:{date}  (List, TTL 48h)
     同时落库 t_recommend_slot（用于效果分析，异步）
   ↓
[8] 推送通知（可选，见 [19 章](./19-模块10-社交基础.md)）
```

**推荐理由生成**：

| 类型 | 模板 |
|---|---|
| 相似歌手 | "你常听周杰伦" / "和周杰伦相似" |
| 相似歌曲 | "因为你听过《晴天》" |
| 风格偏好 | "你喜欢的流行风格" |
| 场景匹配 | "适合深夜听" |
| 热度 | "最近 10 万人都在听" |
| 新歌 | "周杰伦的新歌" |
| 冷门探索 | "小众但好听" |
| 社交 | "你关注的 @小明 收藏了" |

**业务规则**：

- `BR-17-001`：每日推荐**固定 30 首**，不足时用热度召回补足（**必须**凑够 30 首）。
- `BR-17-002`：**每天 0 点更新**（未来日期按当前时间取最近一次生成结果）。
- `BR-17-003`：用户当天**看过但未点击**的歌曲，**不重复**出现在同一天（前端记录曝光）。
- `BR-17-004`：**已听过的歌曲**可以出现，但占比 ≤ 30%（老歌重听是合理需求）。
- `BR-17-005**：**不喜欢**（用户点"不感兴趣"）的歌曲**永久排除**（`ml:rec:dislike:{userId}`，Set）。
- `BR-17-006`：**屏蔽歌手**（用户设置）的歌曲**排除**。
- `BR-17-007`：同一歌手**最多 2 首**（防止刷屏）。
- `BR-17-008`：推荐结果**随机化扰动**：生成时对 Top 30 内部做轻微洗牌（保持分档），避免"榜单化"。
- `BR-17-009`：**缓存 48 小时**（覆盖跨日场景，用户当天未打开时次日仍可看到昨日推荐直到新推荐生成完成）。
- `BR-17-010`：生成耗时**必须**在 4 小时内完成（0:00 - 4:00），失败的用户使用兜底热门推荐。
- `BR-17-011`：**生成失败的用户**在用户请求时**实时兜底**（先返回热门推荐，异步补生成）。
- `BR-17-012`：推荐**必须**过滤下架、无版权、审核未通过的歌曲。
- `BR-17-013`：推荐理由**必须**真实反映推荐依据（不编造），且 ≤ 20 字。
- `BR-17-014`：**运营置顶**的歌曲**强制**出现在每日推荐中（最多 3 首，位于第 1/8/15 位）。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-17-001-1` | 推荐服务不可用 | 返回热门榜单 Top 30，标记 `fallback: true` |
| `EX-17-001-2` | 用户无行为数据（冷启动） | 走新人推荐流程（FR-17-006） |
| `EX-17-001-3` | 生成任务部分失败 | 失败用户使用兜底，任务告警，下次重试 |
| `EX-17-001-4` | 召回结果不足 30 首 | 热度召回补足；仍不足则允许少于 30 首 |
| `EX-17-001-5` | 用户封禁/注销 | 跳过该用户，不生成 |
| `EX-17-001-6` | Redis 写入失败 | 任务重试；用户请求时实时生成 |

**验收标准**：

- `AC-17-001-1`：每日推荐固定 30 首
- `AC-17-001-2`：每天 0 点后推荐更新
- `AC-17-001-3`：同一歌手不超过 2 首
- `AC-17-001-4`：每首歌带推荐理由，且 ≤ 20 字
- `AC-17-001-5`："不感兴趣"的歌曲不再出现
- `AC-17-001-6`：推荐不含下架/无版权歌曲
- `AC-17-001-7`：运营置顶歌曲出现在指定位置
- `AC-17-001-8`：推荐接口 P95 ≤ 300ms（缓存命中）
- `AC-17-001-9`：冷启动用户也能拿到 30 首推荐
- `AC-17-001-10`：全量用户推荐生成在 4 小时内完成

### FR-17-002 推荐反馈（喜欢/不喜欢）【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 采集反馈信号，形成闭环优化 |
| **使用角色** | 登录用户 |

**反馈类型**：

| 操作 | 含义 | 数据落点 | 时效 |
|---|---|---|---|
| **喜欢**（❤） | 正向强信号 | `t_like` + 特征库 | 立即影响后续推荐 |
| **不喜欢**（👎） | 负向强信号 | `ml:rec:dislike:{userId}` + `t_recommend_feedback` | 永久排除该曲 |
| **不感兴趣**（歌手） | 负向（歌手级） | `ml:rec:dislike:artist:{userId}` | 永久排除该歌手 |
| **跳过**（< 10s） | 弱负向 | 埋点 | 影响排序权重 |
| **完整播放** | 正向 | 埋点 | 影响排序权重 |
| **收藏/加入歌单** | 强正向 | `t_collect` | 立即影响 |
| **分享** | 强正向 | `t_share` | 立即影响 |

**接口**：

```
POST /api/v1/recommend/feedback
{
  "songId": "1857...",
  "action": "DISLIKE",        // LIKE | DISLIKE | DISLIKE_ARTIST | UNDO
  "scene": "DAILY",            // DAILY | GUESS | SIMILAR | RADIO
  "position": 5                // 在列表中的位置（用于位置偏差分析）
}
```

**业务规则**：

- `BR-17-015`：**不喜欢**立即从当前列表**移除**该歌曲（前端动画消失）。
- `BR-17-016`：**不喜欢**支持**撤销**（5 秒内提示"已减少此类推荐 · 撤销"）。
- `BR-17-017`：**不喜欢**的歌曲**永久排除**（除非用户主动搜索或从歌单进入）。
- `BR-17-018`：**不喜欢歌手**需**二次确认**（"将减少周杰伦的推荐？"），因为影响较大。
- `BR-17-019`：反馈数据**必须**上报埋点（用于模型训练）。
- `BR-17-020`：反馈**必须**实时影响"猜你喜欢"与"私人电台"（下一次请求即生效），但**不影响**当日已生成的每日推荐（当日缓存不变，次日生效）。
- `BR-17-021`：用户可在设置中**管理**屏蔽列表（查看/移除）。
- `BR-17-022`：屏蔽列表**上限 200 首 / 50 位歌手**。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-17-002-1` | 重复标记不喜欢 | 幂等（Set 去重） |
| `EX-17-002-2` | 屏蔽列表超上限 | `80010`，提示清理 |
| `EX-17-002-3` | 撤销超时（> 5s） | 提示"撤销超时"，需手动恢复 |
| `EX-17-002-4` | 反馈上报失败 | 前端重试 2 次，仍失败提示"操作失败" |

**验收标准**：

- `AC-17-002-1`：不喜欢后歌曲立即从列表消失
- `AC-17-002-2`：5 秒内可撤销
- `AC-17-002-3`：不喜欢的歌曲不再出现在推荐中
- `AC-17-002-4`：不喜欢歌手需二次确认
- `AC-17-002-5`：屏蔽列表可查看与管理
- `AC-17-002-6`：反馈实时影响猜你喜欢

### FR-17-003 猜你喜欢 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 基于用户最近行为**实时**推荐 |
| **使用角色** | 登录用户 |
| **前置条件** | 用户有 ≥ 5 条历史行为 |

**生成策略**：

```
实时请求（不走定时任务）
   ↓
[1] 取用户最近 50 条播放历史 / 20 条收藏 / 10 条点赞
   ↓
[2] Item-CF 召回：找与历史歌曲最相似的歌曲（离线预计算的 item-item 相似矩阵）
   ↓
[3] 向量召回：用户历史歌曲向量加权平均（近期行为权重更高）→ ANN 检索
   ↓
[4] 过滤：已不喜欢 / 已屏蔽歌手 / 下架 / 无版权 / 近期已推荐过
   ↓
[5] 排序：相似度 × 新鲜度 × 热度 加权
   ↓
[6] 缓存 30 分钟：ml:rec:guess:{userId}  (List, TTL 30min)
```

**时间衰减权重**：

```
行为权重 = 基础权重 × e^(-λ × 天数)
其中：
  基础权重：完整播放 1.0 / 收藏 1.5 / 点赞 1.2 / 跳过 0.2
  λ = 0.05（约 14 天衰减一半）
```

**业务规则**：

- `BR-17-023`：猜你喜欢**实时性**更强（30 分钟缓存），**响应**用户的即时行为。
- `BR-17-024`：**最近行为权重更高**（时间衰减，见上）。
- `BR-17-025`：返回 **20 首**，支持滚动加载更多（每次追加 20 首）。
- `BR-17-026`：**已听过的歌曲权重降低**但仍可能出现（占比 ≤ 20%）。
- `BR-17-027`：结果**必须**多样化（同一歌手 ≤ 2 首，同一专辑 ≤ 1 首）。
- `BR-17-028`：行为数据不足 5 条时降级为热度 + 新人推荐。
- `BR-17-029`：**新增行为**时**主动失效**缓存（用户播放/收藏后 `DEL ml:rec:guess:{userId}`），保证实时性。
  - **权衡**：失效会导致下次请求重新计算（约 200ms），但保证实时性。若计算成本高，可改为"标记脏 + 定时刷新 5 分钟"。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-17-003-1` | 行为数据 < 5 条 | 降级新人推荐 |
| `EX-17-003-2` | 相似矩阵不可用 | 降级标签/向量召回 |
| `EX-17-003-3` | 召回结果不足 | 热度补足 |
| `EX-17-003-4` | 计算超时（> 1s） | 返回缓存旧结果或热门 |

**验收标准**：

- `AC-17-003-1`：猜你喜欢返回 20 首且可滚动加载
- `AC-17-003-2`：播放新歌后 30 分钟内推荐变化
- `AC-17-003-3`：同一歌手 ≤ 2 首
- `AC-17-003-4`：新用户（< 5 条行为）不报错
- `AC-17-003-5`：P95 ≤ 300ms（缓存命中）

### FR-17-004 相似歌曲 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 在歌曲详情页推荐"听起来像这首"的歌 |
| **使用角色** | 全部 |

**生成策略（离线预计算 + 在线查询）**：

```
离线（每日）：为每首歌计算 Top 50 相似歌曲
  相似度 = 0.4 × 向量余弦相似度
         + 0.3 × 标签 Jaccard 相似度
         + 0.2 × 风格/语种/年代 匹配度
         + 0.1 × 协同过滤共现度
  存储：Redis  ml:rec:similar:{songId}  (ZSet, TTL 7d) + MySQL t_song_similar
   ↓
在线：直接读取，实时过滤不可播放的歌曲，返回 Top 20
```

**业务规则**：

- `BR-17-030`：相似歌曲**离线预计算**（每日凌晨），在线**只读**（保证性能）。
- `BR-17-031`：返回 **20 首**，**排除**当前歌曲本身。
- `BR-17-032`：**过滤**下架/无版权/审核不通过的歌曲。
- `BR-17-033`：**同一歌手 ≤ 2 首**（避免全是同一歌手的歌）。
- `BR-17-034`：**排序**：相似度优先，其次热度。
- `BR-17-035**：**新歌**（无相似数据）实时降级：用标签 + 风格匹配（ES `more_like_this`）。
- `BR-17-036`：预计算数据**保留 7 天**，每日更新；新歌上线后**增量计算**（MQ 触发，30 秒内可用）。
- `BR-17-037`：相似歌曲是**私人电台**的数据源（REC-09）。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-17-004-1` | 无相似数据 | ES `more_like_this` 实时降级 |
| `EX-17-004-2` | 相似结果全部不可播放 | 返回热度推荐 |
| `EX-17-004-3` | 预计算任务失败 | 使用前一日数据；连续 3 天失败告警 |
| `EX-17-004-4` | 冷门歌曲（无标签/无播放） | 按风格 + 语种 + 年代匹配 |

**验收标准**：

- `AC-17-004-1`：相似歌曲 20 首，不含自身
- `AC-17-004-2`：相似度合理的歌曲排在前面（人工抽检）
- `AC-17-004-3`：同一歌手 ≤ 2 首
- `AC-17-004-4`：新歌 30 秒内有相似推荐
- `AC-17-004-5`：结果不含不可播放歌曲

### FR-17-005 场景/情绪歌单推荐 【P1】

| 项 | 内容 |
|---|---|
| **功能目标** | 按场景与情绪提供歌单，降低选择成本 |
| **使用角色** | 全部 |

**场景与情绪维度**：

| 类型 | 取值 |
|---|---|
| **场景** | 运动 / 睡眠 / 通勤 / 学习 / 工作 / 聚会 / 驾车 / 深夜 / 清晨 / 雨天 |
| **情绪** | 开心 / 伤感 / 治愈 / 活力 / 平静 / 孤独 / 激昂 / 怀旧 |

**生成策略**：

```
[1] 场景 → 条件映射（复用 AI 搜索的条件补全规则，见 [15 章](./15-模块06-搜索与AI搜索.md)）
    运动 → bpm ≥ 120, energy ≥ 0.6
    睡眠 → bpm ≤ 90,  energy ≤ 0.4
    学习 → 纯音乐 or energy ≤ 0.5, 无人声优先
    ...
   ↓
[2] 条件 + 热度 + 个性化 混合排序
   ↓
[3] 每个场景固定 40 首，缓存 6 小时
   ↓
[4] 运营可**人工编辑**每个场景的歌曲（覆盖算法结果）
```

**业务规则**：

- `BR-17-038`：每个场景歌单固定 **40 首**，支持"换一批"（随机偏移重新取）。
- `BR-17-039`：歌曲按**热度 + 场景匹配度**排序（不完全随机）。
- `BR-17-040`：**个性化**：登录用户在基础歌单上做**置换**——用用户偏好曲目替换 30% 的位置。
- `BR-17-041`：场景歌单**缓存 6 小时**，运营编辑后**立即失效**缓存。
- `BR-17-042**：**同一场景**在不同时段的默认排序不同（如"通勤"早高峰偏活力、晚高峰偏放松）。
- `BR-17-043`：运营可**置顶**歌曲（最多 5 首）。
- `BR-17-044`：场景歌单**必须**有封面图与描述（运营配置，无配置时用默认模板）。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-17-005-1` | 场景歌曲不足 40 首 | 允许少于 40 首，最少 10 首 |
| `EX-17-005-2` | 场景配置缺失 | 使用默认条件（热度） |
| `EX-17-005-3` | 运营编辑后歌曲下架 | 自动剔除，用算法结果补位 |

**验收标准**：

- `AC-17-005-1`：10 个场景均可展示 40 首歌单
- `AC-17-005-2`："换一批"结果不同
- `AC-17-005-3`：运动场景歌曲 BPM 明显高于睡眠场景（抽检）
- `AC-17-005-4`：运营置顶歌曲出现在首位
- `AC-17-005-5`：运营编辑后立即生效

### FR-17-006 冷启动推荐 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 无行为数据的新用户也能获得合理推荐 |
| **使用角色** | 新注册用户 / 无行为老用户 |

**冷启动阶段划分**：

| 阶段 | 条件 | 策略 |
|---|---|---|
| **S0 完全空白** | 注册后未做任何操作 | 注册偏好问卷 + 全站热门 |
| **S1 兴趣引导** | 完成问卷，行为 < 5 条 | 基于问卷偏好（风格/语种/歌手）召回 |
| **S2 初步画像** | 行为 5~20 条 | 内容召回 + 相似用户协同 |
| **S3 稳定画像** | 行为 > 20 条 | 完整个性化 |

**注册偏好问卷（S0）**：

```
注册后首屏（可跳过）：
  1. 你喜欢哪些音乐风格？（多选，最多 3 个）
     流行 / 摇滚 / 说唱 / 民谣 / 电子 / 古风 / 爵士 / R&B / 轻音乐
  2. 你常听哪些语种？（多选）
     国语 / 粤语 / 英语 / 日语 / 韩语 / 纯音乐
  3. 选几个你喜欢的歌手（可选，搜索选择，最多 5 个）
  4. 你现在的状态？（单选，用于首次场景推荐）
     专注工作 / 放松休息 / 运动健身 / 心情低落 / 只是想听点音乐
```

**业务规则**：

- `BR-17-045`：问卷**可跳过**（跳过后走纯热门推荐）。
- `BR-17-046`：问卷结果**存储并作为长期画像的初始值**（随行为数据积累逐渐稀释其权重）。
- `BR-17-047`：初始画像权重**衰减**：问卷偏好权重从 1.0 开始，每 10 条真实行为衰减 20%，直至 0.2（保底）。
- `BR-17-048`：**S0/S1 用户**的每日推荐**混入 50% 热门**（保证质量兜底）。
- `BR-17-049`：**新人推荐**（REC-06）为 S0/S1 用户的专属首页模块。
- `BR-17-050`：**探索比例**：所有用户的推荐中保留 **10% 的探索位**（推荐用户画像外的歌曲），用于拓宽兴趣并采集反馈。
- `BR-17-051`：**新歌冷启动**：新歌上线后**强制**进入推荐池（热度召回给初始曝光），前 24 小时给 1000 次曝光，根据 CTR 决定是否继续加权。
- `BR-17-052`：**新歌保护期**：上线 7 天内**不受**"已听过"过滤（鼓励尝鲜）。
- `BR-17-053`：新歌冷启动数据不足（曝光 < 100）**不得**进入精排（避免模型噪声）。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-17-006-1` | 问卷未提交 | 走纯热门推荐 |
| `EX-17-006-2` | 问卷选的歌手全部下架 | 按风格推荐 |
| `EX-17-006-3` | 新歌曝光后 CTR 极低 | 停止加权，回归正常池 |
| `EX-17-006-4` | 全新平台（无热门数据） | 使用运营预置的初始推荐池 |

**验收标准**：

- `AC-17-006-1`：新注册用户首页有推荐（非空）
- `AC-17-006-2`：问卷选择"摇滚"后推荐含摇滚歌曲
- `AC-17-006-3`：跳过问卷也能拿到推荐
- `AC-17-006-4`：新歌上线 24 小时内获得曝光
- `AC-17-006-5`：推荐中含约 10% 探索位

### FR-17-008 私人电台（无限流）【P1】

| 项 | 内容 |
|---|---|
| **功能目标** | 一键开启"永不停止"的个性化播放 |
| **使用角色** | 登录用户 |

**流程**：

```
用户点击"私人电台"
   ↓
[1] 初始化队列：
     种子 = 最近 20 首播放 + 收藏中随机 10 首
     首屏 = 猜你喜欢 Top 30
   ↓
[2] 播放中，剩余 ≤ 5 首时**异步追加**下一批
   ↓
[3] 追加策略：
     - 优先相似歌曲（基于最近播放的 3 首）
     - 混入 20% 探索（新风格）
     - 混入 10% 用户历史最爱（怀旧）
     - 过滤已不喜欢/已屏蔽/本会话已播
   ↓
[4] 无更多可推荐时：放宽过滤（允许重复历史歌曲），提示"已为你循环推荐"
```

**业务规则**：

- `BR-17-060`：电台**可无限播放**（队列自动续接）。
- `BR-17-061`：**提前预取**（剩余 ≤ 5 首时追加 20 首），保证不断流。
- `BR-17-062`：**同一会话内不重复**（`sessionId` 维度去重，存 Redis Set，TTL 12h）。
- `BR-17-063`：电台支持**切换风格**（"换个口味"）→ 清空队列重新初始化（保留当前播放）。
- `BR-17-064`：电台播放**支持**"喜欢"与"不喜欢"反馈，实时影响后续追加。
- `BR-17-065`：电台**不写入**每日推荐池（独立会话）。
- `BR-17-066`：电台**必须**记录埋点（`radio_start`、`radio_append`、`radio_end`）。
- `BR-17-067**：电台也可基于**单首歌曲**启动（"以此歌开始电台"），种子为单曲。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-17-008-1` | 追加失败 | 重试 2 次，仍失败提示"网络异常"并暂停 |
| `EX-17-008-2` | 无可推荐歌曲 | 放宽过滤，允许重复（打乱顺序） |
| `EX-17-008-3` | 种子歌曲全部下架 | 用热门初始化 |
| `EX-17-008-4` | 用户快速连续切歌（> 10 首/分钟） | 视为"不感兴趣"，减少该类推荐 |

**验收标准**：

- `AC-17-008-1`：电台可持续播放不中断
- `AC-17-008-2`：同会话内不重复
- `AC-17-008-3`：剩余 5 首时自动追加
- `AC-17-008-4`：切换风格后推荐变化
- `AC-17-008-5`：反馈实时影响后续曲目

## 8. 性能与容量

| 项 | 预估 | 说明 |
|---|---|---|
| 每日推荐生成 | 10 万用户 × 30 首 | 4 小时内完成，需 ~10 并发 worker |
| 每日推荐存储 | 10 万 × 30 × ~50B ≈ 150MB | Redis 内存可接受 |
| 相似歌曲预计算 | 100 万首歌 × Top50 | 需离线计算集群，~2 小时 |
| 推荐接口 QPS | 峰值 2000 | 主要走缓存 |
| 猜你喜欢计算 | ~200ms/用户 | 缓存后 QPS 压力小 |
| 精排模型 | 300 候选 × 10 万用户 = 3000 万次打分 | 需批量推理（GPU 或高效 CPU 模型） |

## 9. 降级策略

| 依赖 | 故障 | 降级 |
|---|---|---|
| 推荐服务 | 不可用 | 返回全站热门 Top 30 |
| 精排模型 | 不可用 | 使用粗排结果（规则打分） |
| 协同过滤 | 数据缺失 | 仅用内容召回 + 热度 |
| 向量库 | 不可用 | 标签相似度 |
| 相似歌曲预计算 | 未完成/失败 | ES `more_like_this` 实时 |
| 个性化数据不足 | 冷启动 | 热门 + 问卷偏好 |
| Redis | 不可用 | 实时计算（性能下降）或热门兜底 |
| 全部推荐依赖 | 不可用 | 运营配置的兜底推荐池 |
