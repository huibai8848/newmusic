## 1. 统一响应格式

### 1.1 成功响应

```json
{
  "code": 0,
  "message": "success",
  "data": { },
  "traceId": "a1b2c3d4e5f6",
  "timestamp": 1760246400000
}
```

### 1.2 失败响应

```json
{
  "code": 40101,
  "message": "未登录或登录已过期",
  "data": null,
  "traceId": "a1b2c3d4e5f6",
  "timestamp": 1760246400000
}
```

### 1.3 字段定义

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | int | ✅ | `0` 表示成功；非 0 为业务错误码（见第 2 节） |
| `message` | string | ✅ | 人类可读提示，可直接展示给用户（已国际化处理） |
| `data` | any | ❌ | 业务数据，失败时为 `null` |
| `traceId` | string | ✅ | 链路追踪 ID，前端出错时展示便于排查 |
| `timestamp` | long | ✅ | 服务端毫秒时间戳 |

### 1.4 后端实现（Java）

```java
// common/result/R.java
@Data
public class R<T> implements Serializable {
    private int code;
    private String message;
    private T data;
    private String traceId;
    private long timestamp;

    public static <T> R<T> ok(T data) { ... }
    public static <T> R<T> ok() { ... }
    public static <T> R<T> fail(ResultCode rc) { ... }
    public static <T> R<T> fail(int code, String message) { ... }
}
```

**约定**：

- Controller **必须**返回 `R<T>`；禁止直接返回实体或 `ResponseEntity<实体>`。
- `traceId` 由 `TraceIdFilter` 从 MDC 取，无则生成。
- HTTP 状态码**恒为 200**（除网关级错误），业务错误通过 `code` 区分。**例外**：鉴权失败返回 401、无权限返回 403（便于前端拦截器统一处理）。

### 2.3 前端错误处理约定

```typescript
// axios 响应拦截器伪代码
if (res.data.code === 0) return res.data.data;
if (res.data.code === 40101) { await refreshToken(); retry(); }
else if (res.data.code >= 20005 && code <= 20006) { redirectToBanPage(); }
else if (res.data.code === 10004) { showRateLimitToast(); }
else { showErrorToast(res.data.message); }
```

**规则**：

- `40101`（未登录）→ 静默刷新 token，失败跳登录并记录 `redirect`
- `40102`（已封禁）→ 跳独立页面，不弹 Toast
- `40301`/`40302` → 跳 403 页或 Toast（按场景）
- `10004`（限流）→ 显示倒计时
- 其余 → 统一 Toast + 上报（含 traceId）

## 3. 分页规范

### 3.1 请求参数

| 参数 | 类型 | 默认 | 约束 | 说明 |
|---|---|---|---|---|
| `pageNum` | int | 1 | ≥ 1 | 页码，**从 1 开始** |
| `pageSize` | int | 20 | 1 ~ 100 | 每页条数，超 100 强制为 100 |
| `sortBy` | string | — | 白名单字段 | 排序字段，**禁止前端任意传**（SQL 注入风险） |
| `sortOrder` | string | `desc` | `asc`/`desc` | 排序方向 |

### 3.2 响应结构

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [],
    "total": 1234,
    "pageNum": 1,
    "pageSize": 20,
    "pages": 62,
    "hasNext": true
  }
}
```

### 3.3 分页实现约束

- **深分页**：`pageNum > 100` 时，后端强制改用**游标分页**（`lastId` + `LIMIT n`），避免 `LIMIT 2000000, 20`。
- **游标分页接口**（信息流、私信、动态）：单独提供 `cursor` 字段，返回 `nextCursor`。
- **总数为近似值**：数据量 > 100 万时，`total` 可返回近似值（`SHOW TABLE STATUS` 或缓存计数），并在响应中标记 `totalApproximate: true`。
- `sortBy` 必须通过**白名单枚举**校验：

```java
Set<String> ALLOWED = Set.of("create_time", "play_count", "hot_score", "publish_time");
if (!ALLOWED.contains(sortBy)) sortBy = "create_time";
```

## 4. 鉴权与上下文规范

### 4.1 请求头

| Header | 必填 | 说明 |
|---|---|---|
| `Authorization` | 写操作必填 | `Bearer {accessToken}` |
| `X-Device-Id` | ✅ | 设备唯一标识（游客态、风控） |
| `X-Client-Version` | ✅ | 客户端版本，用于功能灰度 |
| `X-Request-Id` | ❌ | 客户端请求 ID（幂等、去重） |
| `X-Trace-Id` | ❌ | 上游透传，无则服务端生成 |
| `Accept-Language` | ❌ | 一期仅 `zh-CN` |

### 4.2 用户上下文

```java
// 通过 ThreadLocal 传递，请求结束清理
public class UserContext {
    private static final ThreadLocal<LoginUser> HOLDER = new ThreadLocal<>();
    public static LoginUser get() { return HOLDER.get(); }
    public static Long getUserId() { ... }   // 未登录返回 null
    public static Long requireUserId() {     // 未登录抛 40101
        Long id = getUserId();
        if (id == null) throw new BizException(ResultCode.UNAUTHORIZED);
        return id;
    }
}
```

**使用约束**：

- 业务代码**禁止**从 `HttpServletRequest` 直接取用户信息，统一用 `UserContext`。
- 异步线程（`@Async`、MQ 消费、线程池）**必须**手动传递上下文（`UserContext.copyTo()`），或用 TransmittableThreadLocal。
- WebSocket 会话的用户信息由 `WsSessionRegistry` 维护，不依赖 ThreadLocal。

### 4.3 权限注解

```java
@PreAuthorize("hasAuthority('music:song:create')")   // 单权限
@PreAuthorize("hasAnyAuthority('music:song:update','music:song:audit')")
@PreAuthorize("hasRole('SUPER_ADMIN')")
```

**数据级权限**必须在 Service 层再校验（例：只能编辑自己的歌单）：

```java
Playlist p = playlistMapper.selectById(id);
if (!p.getUserId().equals(UserContext.getUserId()) && !hasPerm("music:playlist:manage")) {
    throw new BizException(NO_PERMISSION_EDIT_PLAYLIST);
}
```

## 5. 幂等规范

### 5.1 需要幂等的场景

| 场景 | 幂等键 | 实现 |
|---|---|---|
| 创建订单/支付 | `bizType + bizId` | Redis `SETNX` + TTL 24h |
| 点赞/收藏/关注 | `userId + targetType + targetId` | **唯一索引**（DB 层天然幂等） |
| 播放上报 | `eventId` | 客户端生成 UUID，服务端去重 |
| MQ 消费 | `eventId` | Redis 消费记录表 + TTL 7d |
| 加入房间 | `userId + roomId` | 唯一索引 |
| 文件上传 | 文件 MD5 | Redis 缓存 MD5 → URL |

### 5.2 通用幂等切面

```java
@Idempotent(key = "#req.bizId", expire = 86400, message = "请勿重复提交")
public R<Void> createOrder(@RequestBody OrderReq req) { ... }
```

- 前端也需做按钮防抖（提交后禁用 1.5s），但不能替代服务端幂等。
- 幂等键冲突返回 `10005`，HTTP 200，前端**静默忽略**。

## 6. 参数校验规范

### 6.1 校验分层

| 层 | 手段 | 示例 |
|---|---|---|
| 前端 | 表单规则 + TS 类型 | 必填、长度、格式 |
| Controller | `@Valid` + JSR-303 | `@NotBlank`, `@Size`, `@Pattern` |
| Service | 业务校验 | 状态机、权限、配额 |
| DB | 唯一索引、非空、外键（逻辑） | 兜底 |

### 6.2 常用校验注解

```java
public class SongCreateReq {
    @NotBlank(message = "歌曲名称不能为空")
    @Size(max = 200, message = "歌曲名称不能超过200字")
    private String name;

    @NotNull(message = "歌手不能为空")
    @Positive(message = "歌手ID不合法")
    private Long artistId;

    @Min(0) @Max(65535)
    private Integer duration;

    @Pattern(regexp = "^[a-zA-Z0-9\\u4e00-\\u9fa5]{0,50}$")
    private String isrc;

    @Valid   // 嵌套校验
    private List<LyricItem> lyrics;
}
```

### 6.3 全局异常处理

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(BizException.class)          // 业务异常 → 原样返回 code
    @ExceptionHandler(MethodArgumentNotValidException.class) // 参数校验 → 10001
    @ExceptionHandler(AccessDeniedException.class)  // 权限 → 40301
    @ExceptionHandler(AuthenticationException.class)// 认证 → 40101
    @ExceptionHandler(DuplicateKeyException.class)  // 唯一键 → 幂等/重复
    @ExceptionHandler(Exception.class)              // 兜底 → 99001 + 告警 + 打印堆栈
}
```

**规则**：

- 兜底异常**必须**打 ERROR 日志 + 上报监控 + 返回 `99001`，**禁止**把堆栈返回前端。
- 业务异常日志级别：`WARN`（可预期）/ `ERROR`（不可预期）。

## 7. 日志规范

### 7.1 日志级别使用

| 级别 | 使用场景 | 示例 |
|---|---|---|
| `ERROR` | 系统异常、需要人工介入 | DB 连接失败、第三方不可用、兜底异常 |
| `WARN` | 可预期的业务异常、降级 | 限流触发、缓存未命中率过高、AI 降级 |
| `INFO` | 关键业务节点、状态变更 | 用户注册、房间创建、订单态变更、MQ 消费成功 |
| `DEBUG` | 调试细节（生产默认关闭） | 请求参数、SQL、缓存 Key |

### 7.2 日志格式（JSON 结构化）

```json
{
  "ts": "2026-10-12T14:30:00.123+08:00",
  "level": "INFO",
  "app": "newmusic-api",
  "instance": "10.0.1.15:8080",
  "traceId": "a1b2c3d4e5f6",
  "spanId": "0012",
  "userId": "1857032849571328001",
  "thread": "http-nio-8080-exec-3",
  "logger": "c.e.n.m.s.service.impl.SongServiceImpl",
  "msg": "歌曲创建成功",
  "biz": { "songId": "1857...", "name": "晴天", "costMs": 45 }
}
```

### 7.3 强制规则

- **禁止** `System.out.println`；**禁止** 字符串拼接日志（用占位符 `{}`）。
- **禁止**打印完整手机号、身份证、密码、Token；须脱敏（`138****8888`）。
- 关键业务入口/出口必须打点（含耗时 `costMs`）。
- 异常日志必须包含 `traceId`、入参摘要、异常堆栈。
- 日志保留：应用日志 15 天（ES），归档 90 天；审计日志 1 年。

## 8. 时间与序列化规范

| 项 | 规范 |
|---|---|
| 服务端时区 | `Asia/Shanghai`（`-Duser.timezone=Asia/Shanghai`） |
| 存储 | MySQL `DATETIME(3)`，UTC+8 |
| 传输 | ISO-8601：`2026-10-12T14:30:00.123+08:00` |
| 前端解析 | `dayjs` 统一解析，展示按本地时区 |
| 长整型 | Long 序列化为 **String**（防 JS 精度丢失） |

```java
@JsonSerialize(using = ToStringSerializer.class)
private Long id;
```

> **重要**：所有 ID（雪花算法生成，19 位）必须序列化为字符串，否则前端 JS `Number` 精度丢失导致 ID 错乱。

## 9. 缓存使用规范（详见 12 章）

| 规范 | 说明 |
|---|---|
| Key 命名 | `ml:{域}:{子域}:{标识}`，全小写 |
| TTL 必设 | 所有 Key 必须显式设 TTL，禁止永久 Key（除白名单结构） |
| 空值缓存 | 查询为空时缓存 `__NULL__`，TTL 60s，防穿透 |
| 序列化 | 统一 JSON（`GenericJackson2JsonRedisSerializer`），禁止 JDK 序列化 |
| 大 Key | String ≤ 10KB；Hash/Set/ZSet ≤ 5000 元素 |
| 热 Key | 本地 Caffeine 缓存 + 逻辑过期，防单 Key 打爆 |
| 批量 | 用 `pipeline` / `mget` 替代循环单次调用 |

## 10. MQ 使用规范（详见 28 章）

| 规范 | 说明 |
|---|---|
| Topic 命名 | `ml_{域}_{事件}_{版本}`，示例 `ml_play_event_v1` |
| 消息体 | 必须含 `eventId`（幂等）、`eventTime`、`traceId`、`payload` |
| 消费幂等 | 消费前查 `eventId` 是否已处理（Redis Set + TTL 7d） |
| 重试 | 消费失败重试 3 次（指数退避），仍失败入**死信队列** + 告警 |
| 顺序 | 需顺序的场景（房间控播）用**顺序消息**（同 roomId 同一队列） |
| 积压告警 | 消费延迟 > 10000 条 或 > 5 分钟 触发告警 |
| 消息大小 | ≤ 512KB，超出则传引用（存 OSS/DB，消息带 URL） |

## 11. 接口文档规范

- 使用 **Knife4j**（`/doc.html`），所有 Controller/DTO 必须有 Swagger 注解。
- 分组：`c端接口`、`后台接口`、`WebSocket 协议`、`内部接口`。
- 每个接口必须标注：功能说明、作者、请求方式、参数说明（含示例）、响应示例、错误码列表。

```java
@Api(tags = "歌曲管理")
@RestController
@RequestMapping("/api/v1/music/songs")
public class SongController {

    @ApiOperation(value = "分页查询歌曲", notes = "支持按名称模糊、歌手、专辑、标签筛选")
    @ApiImplicitParams({
        @ApiImplicitParam(name = "keyword", value = "关键词", dataType = "string"),
        @ApiImplicitParam(name = "artistId", value = "歌手ID", dataType = "long")
    })
    @GetMapping
    public R<PageResult<SongVO>> page(SongQueryReq req) { ... }
}
```

**上线要求**：生产环境 `/doc.html` 需**鉴权**或**内网限制**，禁止公网裸暴露。

## 12. 前端通用规范

### 12.1 目录结构

```
src/
├── api/            接口定义（按模块分文件）
├── assets/         静态资源
├── components/     通用组件
│   ├── common/     Button/Modal/Empty 等
│   └── business/   SongCard/PlayerBar/RoomCard 等
├── hooks/          自定义 Hook
├── layouts/        布局（MainLayout/AdminLayout）
├── pages/          页面（按路由组织）
├── router/         路由配置 + 守卫
├── stores/         Zustand store
├── services/       WebSocket/埋点/存储 等服务
├── styles/         全局样式 + 主题变量
├── types/          TS 类型定义
├── utils/          工具函数
└── constants/      常量/枚举
```

### 12.2 请求封装

```typescript
// api/song.ts
export const songApi = {
  page: (params: SongQuery) => request.get<PageResult<Song>>('/api/v1/music/songs', { params }),
  detail: (id: string) => request.get<Song>(`/api/v1/music/songs/${id}`),
};
```

- 统一 `request` 实例：baseURL、超时（15s）、token 注入、刷新、错误处理、埋点。
- 使用 **React Query** 管理服务端状态：`useQuery` / `useMutation`，配置 `staleTime`、`retry`。

### 12.3 组件规范

- 函数组件 + Hooks，**禁止** class 组件（除 ErrorBoundary）。
- Props 必须定义 TS `interface`，可选属性用 `?`。
- 列表渲染必须给稳定 `key`（用业务 ID，禁用 index）。
- 大列表（> 100 项）使用 `react-window` 虚拟滚动。
- 图片必须懒加载 + 占位图 + 错误兜底。

### 12.4 播放器全局状态（核心）

播放器状态**必须**提升到 Zustand 全局 store，与路由解耦，保证跨页面持续播放：

```typescript
interface PlayerState {
  currentSong: Song | null;
  playlist: Song[];        // 当前播放队列
  playMode: 'order' | 'loop' | 'single' | 'shuffle';
  isPlaying: boolean;
  currentTime: number;
  duration: number;
  volume: number;
  quality: 'standard' | 'high' | 'lossless';
  playbackRate: number;
}
```

- `<audio>` 元素挂载在 `MainLayout` 顶层，**不在**页面组件内，避免路由切换销毁。
- 歌词组件通过 `currentTime` 订阅渲染，用 `requestAnimationFrame` 节流。
