## 1. 模块目标

[19 章](./19-模块10-社交基础.md) 建立了"能互动"的社交基础（评论、点赞、关注、私信、通知）。本模块将其升级为**"能形成关系与内容循环"的社区**。

**核心升级点**：

| 维度 | 19 章（V1.0） | 本章（V1.1） |
|---|---|---|
| 用户表达 | 无（只有头像昵称） | **用户主页**：个人资料、听歌统计、动态、歌单 |
| 内容生产 | 无（用户不能发内容） | **动态（Feed）**：用户可发布音乐动态 |
| 内容分发 | 无 | **关注流**：看关注的人的动态 |
| 消息 | 分类通知 | **消息聚合 + 会话增强** |
| 提及 | 无 | **@ 提及**：动态/评论中 @ 用户 |
| 私信 | 基础文本/图片/歌曲 | **群组私信、消息搜索、会话归档** |
| 关系 | 单向关注 | **关系链推荐、粉丝榜、亲密度** |
| 圈子 | 无 | **音乐圈（兴趣社区）** 二期 |

**衡量指标**：

| 指标 | 现状（V1.0） | 目标（V1.1） |
|---|---|---|
| 有社交行为用户占比 | 15% | ≥ 30% |
| 人均关注数 | 3 | ≥ 8 |
| 人均粉丝数 | 2 | ≥ 5 |
| 动态日发布量 | 0 | ≥ 5000（10 万 DAU） |
| 动态互动率（点赞+评论/曝光） | — | ≥ 8% |
| 私信 7 日留存会话数 | — | ≥ 3 个/活跃用户 |
| 社交用户次留 | 40% | ≥ 50% |
| 被 @ 用户回访率 | — | ≥ 60% |

## 4. 用户主页

### FR-25-001 个人主页 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 用户展示自我、沉淀内容的中心页 |
| **使用角色** | 全部（游客可看公开部分） |

**页面结构**：

```
┌──────────────────────────────────────────────┐
│  [封面图]                                     │
│    [头像]  昵称  [认证标识]                    │
│            用户ID: 12345678   [关注][私信]     │
│            简介文本（最多 100 字）              │
│            IP属地 · 加入时间                   │
├──────────────────────────────────────────────┤
│  关注 128  粉丝 256  获赞 1.2万                │
├──────────────────────────────────────────────┤
│  [动态] [歌单] [喜欢] [最近在听] [关于]         │
├──────────────────────────────────────────────┤
│  标签页内容区                                  │
└──────────────────────────────────────────────┘
```

**听歌统计卡片（"关于"或主页顶部）**：

| 统计 | 说明 | 隐私 |
|---|---|---|
| 累计听歌时长 | 总时长（小时） | 可设公开/仅自己 |
| 本周听歌数 | 本周播放歌曲数 | 可设 |
| 常听歌手 Top 3 | 最常听的歌手 | 可设 |
| 常听风格分布 | 风格饼图 | 可设 |
| 听歌天数 | 连续听歌天数 | 可设 |
| 年度听歌报告 | 年度总结（见下） | 分享用 |

**业务规则**：

- `BR-25-001`：用户主页**默认公开**，用户可设为"仅关注者可看"或"仅自己"。
  - **注意**：即使设为私密，**昵称、头像、关注数、粉丝数**仍公开（这是社交基础）。
- `BR-25-002`：**主页 URL**：`/user/{userId}`（数字 ID）与 `/u/{userCode}`（用户自定义短码，可选）。
- `BR-25-003`：**认证标识**：音乐人认证（蓝 V）、达人认证（黄 V）、官方账号（官方标识），由运营授予。
- `BR-25-004`：**听歌统计隐私**：**每项独立设置**（可只公开部分），默认全部公开。
- `BR-25-005`：**被封禁用户**：主页仍可访问，但显示"该用户已被封禁"，内容全部隐藏。
- `BR-25-006`：**已注销用户**：主页 404 或显示"用户已注销"。
- `BR-25-007`：**黑名单用户访问**：如果 A 拉黑了 B，B 访问 A 的主页时**看不到动态**（只显示基础信息与提示）。
- `BR-25-008`：**主页防爬**：单 IP 主页访问频率限制（100 次/分钟）。
- `BR-25-009`：**主页必须 SSR 友好**（OG 标签，见 [19 章 分享](./19-模块10-社交基础.md)）。
- `BR-25-010`：**"最近在听"**：展示用户最近 7 天播放的歌曲（默认关闭，用户主动开启）。
- `BR-25-011`：**主页空态**：新用户无内容时展示引导"发布第一条动态"。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-25-001-1` | 用户不存在 | 404 页面 |
| `EX-25-001-2` | 用户已注销 | 显示"用户已注销" |
| `EX-25-001-3` | 主页仅关注者可见，当前用户未关注 | 显示"关注后可查看" |
| `EX-25-001-4` | 被对方拉黑 | 显示基础信息 + "对方已设置隐私" |
| `EX-25-001-5` | 访问频率超限 | 429 + 验证码 |

**验收标准**：

- `AC-25-001-1`：主页展示完整（头像、资料、统计、标签页）
- `AC-25-001-2`：可编辑个人资料
- `AC-25-001-3`：听歌统计可独立设置隐私
- `AC-25-001-4`：主页可设可见范围
- `AC-25-001-5`：黑名单双向隐藏生效
- `AC-25-001-6`：被封禁用户主页正确处理
- `AC-25-001-7`：主页有 OG 标签
- `AC-25-001-8`：主页 P95 加载 ≤ 500ms

### FR-25-002 个人资料编辑 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 用户维护个人展示信息 |
| **使用角色** | 登录用户 |

**可编辑字段**：

| 字段 | 限制 | 审核 |
|---|---|---|
| 头像 | 图片 ≤ 5MB，建议 1:1，自动裁剪为 200×200 与 800×800 | 机审（涉黄涉暴） |
| 昵称 | 2-20 字符，支持中英文数字下划线，不含敏感词 | 机审 |
| 简介 | ≤ 100 字 | 机审 + 敏感词 |
| 性别 | 男/女/保密（默认保密） | 无 |
| 生日 | 年月日（可选，不展示具体日期只展示星座/年龄段） | 无 |
| 地区 | 省市（可选） | 无 |
| 个人标签 | 最多 5 个（如"摇滚爱好者""深夜听歌"），从预置标签中选择 | 无 |
| 背景封面 | 图片 ≤ 5MB，建议 16:9 | 机审 |
| 主页可见性 | 公开/仅关注者/仅自己 | 无 |
| 短码 | 4-20 字符字母数字，唯一 | 敏感词 |

**业务规则**：

- `BR-25-012`：**昵称修改频率**：**30 天一次**（防止频繁改名逃避识别）。
- `BR-25-013`：**简介修改频率**：**每天 3 次**。
- `BR-25-014`：**头像修改频率**：**每天 5 次**。
- `BR-25-015`：**头像必须机审**，审核中显示"审核中"占位，不通过则恢复原头像并通知。
- `BR-25-016`：**昵称唯一性**：允许重名（社交平台惯例），但**短码唯一**。
- `BR-25-017`：**敏感词**：昵称与简介必须过敏感词库（见 [27 章](./27-模块18-内容安全.md)），命中则拒绝。
- `BR-25-018`：**禁止冒充**：昵称不得包含"官方""客服""管理员"等（除非认证账号）。
- `BR-25-019`：**生日隐私**：默认不公开具体日期，仅用于年龄计算与生日祝福（用户可关）。
- `BR-25-020`：**地区**：可选填，用于"同城"功能。
- `BR-25-021`：**修改必须记录日志**（尤其昵称、头像，用于治理改名规避）。
- `BR-25-022`：**被限制用户**（见 [27 章](./27-模块18-内容安全.md)）：昵称/签名改为提示文本，不可编辑。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-25-002-1` | 昵称含敏感词 | `30010`，提示具体原因 |
| `EX-25-002-2` | 昵称修改过于频繁 | `30011`，提示剩余天数 |
| `EX-25-002-3` | 头像审核不通过 | 通知 + 恢复原头像 |
| `EX-25-002-4` | 短码已被占用 | `30012`，建议其他 |
| `EX-25-002-5` | 图片格式不支持 | `40010` |
| `EX-25-002-6` | 图片过大 | `40011` |
| `EX-25-002-7` | 审核服务不可用 | 进入人工队列（不阻塞用户操作，先展示） |

**验收标准**：

- `AC-25-002-1`：资料字段可编辑并保存
- `AC-25-002-2`：昵称/简介/头像频率限制生效
- `AC-25-002-3`：头像机审生效
- `AC-25-002-4`：敏感词拦截生效
- `AC-25-002-5`：短码唯一性校验
- `AC-25-002-6`：修改记录日志
- `AC-25-002-7`：生日隐私默认保护
- `AC-25-002-8`：审核服务故障有降级

## 5. 动态（Feed）

### FR-25-003 发布动态 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 用户发布音乐相关动态，形成内容生态 |
| **使用角色** | 登录用户（游客不可） |

**动态类型**：

| 类型 | 说明 | 结构 |
|---|---|---|
| **纯文本** | 分享心情、乐评 | 文本 + 图片 |
| **分享歌曲** | 分享一首歌 | 文本 + 歌曲卡片 |
| **分享歌单** | 分享歌单 | 文本 + 歌单卡片 |
| **分享歌词** | 引用歌词片段 | 歌词片段（≤ 100 字）+ 歌曲卡片 |
| **听歌打卡** | 分享正在听 | 歌曲卡片 + 自动文案 |
| **创建歌单** | 我创建了歌单 | 自动生成 |

**发布流程**：

```
用户点击"发布动态"
   ↓
[1] 选择类型（或由入口自动带类型，如"分享歌曲"）
   ↓
[2] 编辑内容
     - 文本：≤ 500 字
     - 图片：≤ 9 张（自动压缩）
     - 关联内容：1 首歌 / 1 个歌单 / 1 段歌词
     - @ 提及：≤ 10 个用户
     - 话题：#话题#（≤ 3 个）
   ↓
[3] 前端实时检测（敏感词高亮提示）
   ↓
[4] 提交
   ↓
[5] 服务端校验：
     - 频率限制
     - 敏感词（DFA）
     - 图片机审（异步）
     - @ 用户校验（存在且未拉黑）
     - 话题校验
   ↓
[6] 入库（状态：审核中 / 已发布）
   ↓
[7] 分发到粉丝（推模式，见 FR-25-005）
   ↓
[8] 通知被 @ 用户
   ↓
[9] 返回发布成功
```

**业务规则**：

- `BR-25-023`：**文本长度 ≤ 500 字**（不含关联内容）。
- `BR-25-024`：**图片 ≤ 9 张**，单张 ≤ 5MB，自动压缩到 ≤ 500KB。
- `BR-25-025`：**必须至少有一项内容**（文本/图片/关联内容），不能全空。
- `BR-25-026`：**频率限制**：
  - 新用户（注册 < 7 天）：**3 条/天**
  - 普通用户：**20 条/天**，**5 条/小时**
  - 认证用户：**50 条/天**
  - 分钟内连续发布 **5 条**触发验证码
- `BR-25-027`：**内容审核**：文本过 DFA 敏感词 + AI 审核（见 [27 章](./27-模块18-内容安全.md)）；图片异步机审。
  - **【假设 A-33】** 动态采用**先发后审**（与 [19 章 评论一致 A-19](./19-模块10-社交基础.md)）：
    - 文本 DFA 命中**高危词** → 直接拒绝发布。
    - 文本 DFA 命中**疑似词** → 发布但仅自己可见，转人工审核。
    - 文本无命中 + 图片待审 → **立即发布**，图片审核不通过则动态降级为"图片不可见"并通知作者。
- `BR-25-028`：**@ 提及限制**：一条动态最多 @ **10 个用户**；@ 的用户必须存在且未互相拉黑。
- `BR-25-029`：**话题格式**：`#话题名#`，长度 2-20 字，最多 3 个。
- `BR-25-030`：**分享歌曲**：歌曲必须可播放（上架且有版权），下架歌曲的动态显示"歌曲已下架"。
- `BR-25-031`：**重复内容检测**：连续发布相似度 > 90% 的内容视为重复，第二次起拒绝。
- `BR-25-032`：**禁止推广**：包含外部链接、联系方式（微信号/QQ 号/手机号）的内容会被拦截或限流。
- `BR-25-033`：**发布后 5 分钟内可编辑**（编辑后重新审核），**超过 5 分钟不可编辑**，只能删除。
- `BR-25-034`：**编辑记录**：动态被编辑过则显示"已编辑"（防"钓鱼"改内容）。
- `BR-25-035`：**删除**：作者可随时删除（软删），**删除后评论/点赞一并隐藏**。
- `BR-25-036`：**动态不可恢复**（删除后不可撤销）。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-25-003-1` | 超出频率限制 | `30020`，提示配额与重置时间 |
| `EX-25-003-2` | 内容为空 | `30021`，提示"请输入内容" |
| `EX-25-003-3` | 命中高危敏感词 | `30022`，拒绝并提示违规 |
| `EX-25-003-4` | @ 的用户不存在 | 忽略该 @（不报错），或提示 |
| `EX-25-003-5` | @ 的用户已拉黑我 | 忽略该 @（静默） |
| `EX-25-003-6` | 图片上传失败 | 提示重试，其他内容保留 |
| `EX-25-003-7` | 图片审核不通过 | 动态保留，图片隐藏，通知作者 |
| `EX-25-003-8` | 关联歌曲已下架 | 拒绝发布，提示换歌曲 |
| `EX-25-003-9` | 重复内容 | `30023`，提示不要重复发布 |
| `EX-25-003-10` | 编辑超时（> 5 分钟） | `30024`，提示不可编辑 |
| `EX-25-003-11` | 审核服务不可用 | 进人工队列，内容暂时仅自己可见 |

**验收标准**：

- `AC-25-003-1`：6 种动态类型可发布
- `AC-25-003-2`：文本/图片/@/话题限制生效
- `AC-25-003-3`：频率限制按用户等级生效
- `AC-25-003-4`：敏感词分级处理（高危拒绝/疑似仅自己可见）
- `AC-25-003-5`：图片异步机审且失败可降级
- `AC-25-003-6`：@ 提及校验生效
- `AC-25-003-7`：重复内容检测生效
- `AC-25-003-8`：5 分钟内可编辑，超时不可
- `AC-25-003-9`：删除后评论点赞隐藏
- `AC-25-003-10`：发布 P95 ≤ 800ms（不含图片上传）

### FR-25-004 动态详情与互动 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 动态的详情展示与互动（点赞/评论/转发） |
| **使用角色** | 全部（游客可看不可互动） |

**互动类型**：

| 互动 | 说明 | 是否可撤销 |
|---|---|---|
| **点赞** | 类似歌曲点赞，Redis + 异步 DB | 可（再点取消） |
| **评论** | 复用 [19 章](./19-模块10-社交基础.md) 评论体系 | 可删除 |
| **转发** | 转发到自己主页（带原动态引用） | 可删除 |
| **分享** | 分享到站外（生成分享链接） | — |
| **收藏** | 收藏动态到"我的收藏" | 可取消 |
| **举报** | 复用 [19 章 举报](./19-模块10-社交基础.md) | — |

**转发（Repost）设计**：

```
原动态 A（用户 X 发布）
   ↓ 用户 Y 转发
新动态 B（用户 Y 发布）
  内容：Y 的评论（可选）+ 引用卡片（A 的摘要）
  展开 B 详情 → 显示 A 的完整内容
```

**业务规则**：

- `BR-25-037`：**转发限制**：转发时可选添加评论（≤ 200 字），也可纯转发。
- `BR-25-038`：**转发链深度**：**只保留 1 层引用**（转发转发的动态，引用最原始动态），避免无限嵌套。
  - 显示"XX 转发了 XX 的动态"，中间转发者压缩展示。
- `BR-25-039`：**原动态删除**：引用卡片显示"原动态已删除"，转发内容仍保留（用户自己写的话）。
- `BR-25-040`：**禁止转发被拉黑用户的动态**（静默失败）。
- `BR-25-041`：**点赞通知**：动态点赞**不逐条通知**（太吵），仅在**首次被点赞**与**里程碑**（10/50/100/500/1000）通知。
- `BR-25-042`：**评论通知**：动态作者收到评论通知（高频时聚合，见 FR-25-008）。
- `BR-25-043`：**转发通知**：动态作者收到转发通知（聚合）。
- `BR-25-044`：**互动计数**：点赞/评论/转发数**实时**（Redis 计数），异步落库。
- `BR-25-045`：**互动可见性**：动态设为"仅自己可见"时互动不可见。
- `BR-25-046`：**动态排序（详情页）**：评论支持按热度/时间排序（复用 [19 章](./19-模块10-社交基础.md)）。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-25-004-1` | 动态已删除 | 详情 404，列表显示"已删除" |
| `EX-25-004-2` | 动态仅作者可见，非作者访问 | 403 |
| `EX-25-004-3` | 转发原动态已删除 | 显示"原动态已删除" |
| `EX-25-004-4` | 被对方拉黑 | 不可互动（点赞/评论失败） |
| `EX-25-004-5` | 点赞频繁 | 限流 |

**验收标准**：

- `AC-25-004-1`：动态详情展示完整
- `AC-25-004-2`：点赞/评论/转发/收藏可用
- `AC-25-004-3`：转发只保留 1 层引用
- `AC-25-004-4`：原动态删除后转发仍显示
- `AC-25-004-5`：点赞通知不打扰（仅里程碑）
- `AC-25-004-6`：互动计数实时准确
- `AC-25-004-7`：被拉黑不可互动
- `AC-25-004-8`：详情页 P95 ≤ 400ms

### FR-25-005 关注流（Feed） 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 展示用户关注的人发布的动态 |
| **使用角色** | 登录用户 |

**推拉结合（Push + Pull）架构**：

| 用户类型 | 策略 | 原因 |
|---|---|---|
| **普通用户**（粉丝 < 5000） | **推模式（Push）**：发布时写入所有粉丝的收件箱 | 粉丝少，写放大可控 |
| **大 V**（粉丝 ≥ 5000） | **拉模式（Pull）**：发布时只写自己的发件箱，粉丝读时拉取 | 粉丝多，写放大不可接受 |

**收件箱（Inbox）设计**：

```
Redis ZSet（每个用户一个收件箱）：
  ml:feed:inbox:{userId}
    member = postId (带发布者的编码，避免 ID 冲突)
    score  = 时间戳（毫秒）

容量：保留最近 1000 条（超出裁剪最旧的）
```

**拉取（读取关注流）**：

```
用户打开"关注"页
   ↓
[1] 读自己的收件箱（Redis ZSet，倒序取 20 条）
   ↓
[2] 读自己关注的**大 V**的发件箱（Pull，取最近 20 条）
     ml:feed:outbox:{bigVUserId}
   ↓
[3] 合并两个来源，按时间排序
   ↓
[4] 取 Top 20（分页）
   ↓
[5] 批量查动态详情（含作者、图片、歌曲卡片）
   ↓
[6] 过滤：黑名单、已删除、不可见
   ↓
[7] 返回
```

**收件箱未初始化（新用户 / 长期未登录）**：

```
用户从没收过 Feed（inbox 不存在或有 TTL 过期）
   ↓
异步构建：拉取关注的所有人的最近动态，组装收件箱
   ↓
构建期间：同步降级为**全拉模式**（直接查关注人的动态，按时间排序）
```

**分页**：

```
游标分页（Cursor-based）：
  首次：GET /api/v1/feed/following?limit=20
  下一页：GET /api/v1/feed/following?cursor={lastScore}_{lastPostId}&limit=20

不使用 pageNum（Feed 流会因新内容插入导致翻页重复/漏数据）
```

**业务规则**：

- `BR-25-047`：**推模式阈值：粉丝 5000**（可配置）。超过则转拉模式。
- `BR-25-048`：**收件箱容量 1000 条**（`ZREMRANGEBYRANK` 裁剪），TTL 30 天（不活跃用户自动回收）。
- `BR-25-049`：**收件箱写入异步**：发布动态后通过 MQ 异步写入粉丝收件箱（不阻塞发布）。
  - 大 V 转拉模式是**发布时判断**，不是历史数据迁移（历史已推送的内容保留）。
- `BR-25-050`：**推模式写放大控制**：
  - 单次发布的粉丝数上限 **5000**（超过即转拉模式）。
  - 批量写入使用 Redis Pipeline（每批 500 个 key）。
  - 发送耗时 > 5 秒则降级为拉模式（记录并告警）。
- `BR-25-051`：**Feed 流不缓存动态内容**（只缓存 ID），内容实时查（保证删除/审核状态实时）。
- `BR-25-052`：**Feed 流必须先过滤再分页**：先取更多（如 60 条），过滤后取 20 条，不足则继续取，最多取 200 条。
  - **理由**：若先分页再过滤，会出现"一页只有 5 条"的问题。
- `BR-25-053`：**已读状态**：记录用户上次查看 Feed 的时间，之后的新动态标记"新"。
- `BR-25-054`：**游客不可用**（关注流需要登录）。
- `BR-25-055`：**空态**：未关注任何人时展示"推荐关注"（见 FR-25-009）。
- `BR-25-056`：**Feed 流不得包含自己发的动态**（自己发的在"我的动态"里看）。
- `BR-25-057`：**Feed 流支持筛选**：全部 / 只看关注的人 / 只看认证用户（可选）。
- `BR-25-058`：**Feed 流刷新**：下拉刷新获取新内容，**不自动轮询**（省流量），但**顶部提示"N 条新动态"**（WebSocket 推送通知）。

**Feed 流性能要求**：

| 操作 | 目标 |
|---|---|
| 读 Feed | P95 ≤ 300ms |
| 发布动态写收件箱 | 异步，P95 ≤ 3s（5000 粉丝） |
| 收件箱单次读取（Redis ZRange） | ≤ 5ms |

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-25-005-1` | 收件箱不存在 | 异步构建 + 同步全拉降级 |
| `EX-25-005-2` | Redis 不可用 | 全拉模式（直接查 DB，性能下降） |
| `EX-25-005-3` | 推模式超时（> 5s） | 降级拉模式，告警 |
| `EX-25-005-4` | 过滤后不足 20 条 | 继续取（最多 200 条） |
| `EX-25-005-5` | 关注的人全部注销 | 空态 + 推荐关注 |
| `EX-25-005-6` | 动态内容失效（歌曲下架） | 显示"歌曲已下架"占位 |

**验收标准**：

- `AC-25-005-1`：关注流按时间倒序展示
- `AC-25-005-2`：推模式（粉丝 < 5000）写入收件箱
- `AC-25-005-3`：拉模式（粉丝 ≥ 5000）不写收件箱
- `AC-25-005-4`：推拉结合，结果正确合并
- `AC-25-005-5`：游标分页无重复/遗漏
- `AC-25-005-6`：先过滤再分页
- `AC-25-005-7`：收件箱裁剪与 TTL 生效
- `AC-25-005-8`：不包含自己的动态
- `AC-25-005-9`：读 Feed P95 ≤ 300ms
- `AC-25-005-10`：Redis 故障降级全拉

### FR-25-006 动态推荐（发现页） 【P1】

| 项 | 内容 |
|---|---|
| **功能目标** | 关注流之外，推荐可能感兴趣的动态 |
| **使用角色** | 登录用户 |

**推荐来源**：

| 来源 | 说明 | 权重 |
|---|---|---|
| 关注的人的互动 | 关注的人点赞/评论的动态 | 高 |
| 相似用户 | 品味相近的人的动态 | 高 |
| 话题热度 | 热门话题下的优质动态 | 中 |
| 歌曲关联 | 用户常听歌曲的讨论动态 | 中 |
| 认证用户 | 音乐人发布的内容 | 中 |
| 同城 | 同城用户的动态 | 低 |
| 新用户 | 扶持新用户的内容 | 低 |

**排序（简版）**：

```
score = 0.35 × 社交相关性（关注关系链）
      + 0.25 × 内容质量（互动率、完成观看率）
      + 0.15 × 时效性（时间衰减 e^(-λt)，λ = 0.1/小时）
      + 0.15 × 兴趣匹配（用户与动态内容的标签相似度）
      + 0.10 × 作者质量（作者历史互动率）
```

**业务规则**：

- `BR-25-059`：**发现页与关注流分离**（两个 Tab），不混合。
- `BR-25-060`：**质量门槛**：推荐池中的动态必须满足（互动率 > 2% 或 作者为认证用户）。
- `BR-25-061`：**时间窗口**：只推荐 7 天内的动态（避免老内容反复推荐）。
- `BR-25-062`：**去重**：用户已看过 3 次的动态不再推荐。
- `BR-25-063`：**多样性**：同一作者最多 1 条（首屏）。
- `BR-25-064`：**负反馈**：动态支持"不感兴趣"，生效 30 天。
- `BR-25-065`：**推荐位标注**：推荐内容需可选标注"你可能感兴趣"（合规要求，见 [27 章](./27-模块18-内容安全.md)）。
- `BR-25-066`：**冷启动**：新用户发现页展示"热门动态"（全站热度）。

**验收标准**：

- `AC-25-006-1`：发现页与关注流分离
- `AC-25-006-2`：推荐来源多样化
- `AC-25-006-3`：质量门槛生效
- `AC-25-006-4`：7 天窗口限制
- `AC-25-006-5`：同作者首屏 ≤ 1 条
- `AC-25-006-6`：不感兴趣生效
- `AC-25-006-7`：新用户有热门动态兜底
- `AC-25-006-8`：发现页 P95 ≤ 500ms

## 6. @ 提及与消息

### FR-25-007 @ 提及 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 在动态/评论中提及他人，形成对话 |
| **使用角色** | 登录用户 |

**触发方式**：

```
用户在输入框中输入 "@"
   ↓
[1] 弹出候选列表（搜索框 + 推荐）
     优先：关注的用户、最近互动过的用户
   ↓
[2] 用户继续输入 → 实时搜索（300ms 防抖）
   ↓
[3] 选中（点击/回车/Tab）→ 插入 @昵称 + 隐藏 userId
   ↓
[4] 提交时解析出 userId 列表
```

**存储格式**：

```
用户输入：@小明 @阿华 你们也听听

存储文本："@小明 @阿华 你们也听听"
提及关系：t_mention（sourceType, sourceId, mentionedUserId, offset）
  - offset 用于高亮与跳转定位
```

> **为什么存偏移量**：文本中可能有多个人昵称相同，用 offset 精确定位每个 @ 的位置，前端据此渲染为可点击的用户链接。

**渲染**：

```
解析文本中的 @ 位置（依据 t_mention 的 offset 与 length）
   ↓
渲染为 <a href="/user/{userId}">@昵称</a>
   ↓
验证：@ 的用户是否已注销/改名/拉黑
  - 已注销 → 显示 @已注销用户（灰色，不可点）
  - 已改名 → 显示**当前**昵称（不显示旧昵称）
  - 已拉黑我 → 显示为纯文本（不可点）
  - 我拉黑了对方 → 显示为纯文本
```

**业务规则**：

- `BR-25-067`：**@ 数量限制**：单条内容最多 @ **10 人**。
- `BR-25-068`：**@ 频率限制**：单用户 @ 他人的总量限制 **50 次/天**（防骚扰）。
- `BR-25-069`：**被 @ 通知**：被 @ 用户收到通知（见 FR-25-008）。
- `BR-25-070`：**@ 不可绕过黑名单**：如果对方拉黑了我，@ 不生效（不通知，显示为纯文本）。
- `BR-25-071`：**@ 自己**：不允许（忽略）。
- `BR-25-072`：**@ 不存在的用户**：提交时校验，忽略无效的 @（转为纯文本）。
- `BR-25-073`：**@ 全体**：不允许（不存在 @所有人）。
- `BR-25-074`：**@ 官方账号**：允许，但官方账号可设置"仅接收关注者的 @ 通知"。
- `BR-25-075`：**渲染必须二次校验**：文本存储的昵称可能已过期，渲染时**以 userId 为准**查最新昵称。
- `BR-25-076`：**@ 敏感用户**（被限制/封禁）：不通知，显示为纯文本。
- `BR-25-077`：**@ 提及支持自动补全**：输入 @ 后按拼音/首字母搜索。
- `BR-25-078`：**防滥用**：同一用户被同一人 @ 超过 3 次/天，第 4 次起不通知（但内容正常显示）。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-25-007-1` | @ 用户不存在 | 转为纯文本 |
| `EX-25-007-2` | @ 自己 | 忽略 |
| `EX-25-007-3` | @ 超过 10 人 | 拒绝提交，提示 |
| `EX-25-007-4` | @ 被拉黑 | 不通知，纯文本显示 |
| `EX-25-007-5` | @ 频率超限 | `30030`，提示当日配额 |
| `EX-25-007-6` | 用户已改名 | 渲染显示最新昵称 |
| `EX-25-007-7` | 用户已注销 | 显示"@已注销用户"（灰色） |
| `EX-25-007-8` | 搜索补全服务不可用 | 降级为纯文本输入 |

**验收标准**：

- `AC-25-007-1`：输入 @ 弹出候选
- `AC-25-007-2`：选中后插入格式正确
- `AC-25-007-3`：被 @ 用户收到通知
- `AC-25-007-4`：黑名单不绕过
- `AC-25-007-5`：渲染以 userId 为准显示最新昵称
- `AC-25-007-6`：已注销用户显示正确
- `AC-25-007-7`：@ 数量与频率限制生效
- `AC-25-007-8`：补全搜索 P95 ≤ 150ms

### FR-25-008 消息中心升级 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 统一的、可聚合的、可管理的信息中心 |
| **使用角色** | 登录用户 |

**消息分类（升级为 5 大类）**：

| 大类 | 包含 | 聚合规则 |
|---|---|---|
| **互动消息** | 点赞、评论、@提及、转发、收藏 | 按"类型 + 对象 + 时间窗"聚合 |
| **新增粉丝** | 关注 | 聚合（"小明等 5 人关注了你"） |
| **私信** | 一对一会话 | 按会话（不过度聚合） |
| **系统通知** | 官方公告、账号安全、审核结果、功能更新 | 不聚合（重要） |
| **音乐提醒** | 关注歌手新歌、关注的歌单更新、房间开播 | 聚合 |

**聚合规则（关键设计）**：

```
聚合键：aggregateKey = {type}:{targetType}:{targetId}:{timeBucket}

时间桶（timeBucket）：
  - 互动消息：1 小时（同一小时内对同一对象的同类型互动聚合）
  - 新增粉丝：24 小时
  - 音乐提醒：24 小时

示例：
  10:00 小明 赞了你的动态 A
  10:15 小红 赞了你的动态 A
  10:30 小刚 赞了你的动态 A
  → 聚合成 1 条："小明、小红等 3 人赞了你的动态"

  11:05 小美 赞了你的动态 A（跨时间桶）
  → 新的一条："小美 赞了你的动态"
```

**聚合实现**：

```
用户 A 的动态被点赞
   ↓
[1] 计算 aggregateKey
   ↓
[2] 查 Redis：ml:notify:agg:{userId}:{aggregateKey}
     - 存在（未过期）→ 更新计数与参与者列表，**不新建通知**
     - 不存在 → 创建新通知，写入 Redis（TTL = 时间桶时长）
   ↓
[3] 更新未读数
   ↓
[4] 推送（WebSocket）
```

**未读数设计**：

```
ml:notify:unread:{userId}          → Hash（各大类的未读数）
  { "interaction": "5", "follow": "2", "message": "3", "system": "1", "music": "0" }
ml:notify:unread:total:{userId}    → String（总未读数）
```

**消息列表排序**：

```
按"大类"倒序：（互动 > 私信 > 新增粉丝 > 音乐提醒 > 系统通知）
   ↓
每类内按时间倒序
   ↓
同一聚合消息显示"参与者头像堆叠 + 文案 + 时间 + 关联内容预览"
```

**业务规则**：

- `BR-25-079`：**5 大类固定**，不再细分（细分在类内展示）。
- `BR-25-080`：**聚合时间桶**：互动 1 小时，粉丝/音乐提醒 24 小时。
- `BR-25-081`：**聚合上限**：一条聚合消息最多展示 3 个参与者头像 + "等 N 人"。
- `BR-25-082`：**聚合消息点击**：进入"消息详情"列表（展示该聚合下的所有原始消息）。
- `BR-25-083`：**已读**：
  - 点击进入消息中心 → 该类未读清零（或仅点击的那条已读，可配置）。
  - **默认：进入列表即标记该类已读**（符合用户预期）。
- `BR-25-084`：**未读数上限**：显示"99+"（超过 99）。
- `BR-25-085`：**免打扰**：用户可关闭某类通知（除系统通知中的安全类）。
- `BR-25-086`：**系统通知不聚合**（重要内容逐条展示）。
- `BR-25-087`：**消息保留**：互动/粉丝/音乐提醒 **90 天**；私信 **1 年**（见 [19 章](./19-模块10-社交基础.md)）；系统通知**永久**。
- `BR-25-088`：**一键已读**：消息中心支持"全部标记已读"。
- `BR-25-089`：**深链**：每条通知可跳转到对应内容（动态/评论/用户/歌曲/房间）。
- `BR-25-090`：**WebSocket 实时推送**：在线用户实时收到新消息通知（见 [13 章](./13-模块04-WebSocket.md)）。
- `BR-25-091`：**离线补偿**：离线用户再次上线时拉取未读消息（拉取增量）。
- `BR-25-092`：**必须尊重用户的通知设置**（见 [19 章](./19-模块10-社交基础.md)），关闭则不推送但**仍在消息中心可查**（除用户明确"不接收"）。
- `BR-25-093`：**防打扰**：同一用户的非私信类通知，**每分钟最多推送 1 条**（超出合并）。

### FR-25-009 社交关系链推荐 【P1】

| 项 | 内容 |
|---|---|
| **功能目标** | 推荐可能认识/感兴趣的人，加速关系链建立 |
| **使用角色** | 登录用户 |

**推荐来源**：

| 来源 | 说明 | 权重 |
|---|---|---|
| **共同关注** | 我关注的人也关注了 TA | 高 |
| **二度关系** | 关注的人关注的人 | 高 |
| **共同群/房间** | 在同一音乐房呆过 | 中 |
| **听歌相似** | 听歌重合度高 | 中 |
| **同城** | 同一城市 | 中 |
| **互相关注的桥梁** | 有共同好友 | 高 |
| **热门用户** | 粉丝增长快的新用户 | 低 |
| **通讯录匹配**（可选） | 上传通讯录匹配（需显式授权） | 高（但涉及隐私） |

**推荐生成**：

```
离线任务（每日）：
  对于每个活跃用户：
    - 取"共同关注"候选（关注的人的关注列表 - 已关注）
    - 取"听歌相似"候选（向量近邻用户，从用户向量库检索）
    - 取"同城"候选（同城市活跃用户，取 Top N）
    - 合并去重，按共同好友数排序
    - 过滤：已关注、已拉黑、被封禁、已注销
    - 取 Top 20 存 Redis
   ↓
在线读取（Redis）+ 实时补充（如"XX 关注了你"）
```

**"XX 关注了你"优先展示**：

```
推荐列表中，优先展示**关注了我但我没关注**的用户（回关率最高）
  显示文案："小明 关注了你"
  按钮：[回关]
```

**业务规则**：

- `BR-25-095`：**推荐数量**：每次展示 **10-20 人**。
- `BR-25-096`：**必须排除**：已关注、已拉黑、被封禁、已注销、自己。
- `BR-25-097`：**回关优先**：关注了我的人优先推荐（回关率高）。
- `BR-25-098`：**推荐理由**：展示推荐原因（"你们有 5 个共同关注"），提升可信度。
- `BR-25-099`：**可忽略**：用户可点 × 移除推荐（30 天内不再推荐该用户）。
- `BR-25-100`：**通讯录匹配必须显式授权**：用户主动上传 → 哈希手机号 → 匹配（**不上传明文**）。
  - **【假设 A-34】** 通讯录匹配**本期不做**（隐私合规风险高，需单独评估）。列表中的"通讯录匹配"为远期规划。
- `BR-25-101`：**隐私**：不暴露"谁看过你的主页"（可选功能，需双方互相同意，本期不做）。
- `BR-25-102`：**推荐必须每日更新**（避免长期推荐同一批人）。
- `BR-25-103`：**冷启动**：新用户推荐"热门用户" + "同城用户"。
- `BR-25-104`：**运营可干预**：运营可配置推荐位（如推荐官方账号）。

**异常情况**：

| 编号 | 场景 | 处理 |

| `EX-25-009-4` | Redis 不可用 | 实时计算（性能下降）或展示热门用户 |

**验收标准**：

- `AC-25-009-1`：推荐列表生成

### FR-25-011 亲密度与粉丝榜 【P1】

| 项 | 内容 |
|---|---|
| **功能目标** | 量化社交关系强度，激励互动 |
| **使用角色** | 登录用户 |

**亲密度（用户 ↔ 用户）**：

```
亲密度 = 互动次数加权求和（近 90 天，时间衰减）

互动权重：
  私信消息 × 1
  评论对方动态 × 3
  点赞对方动态 × 1
  转发对方动态 × 2
  @ 提及对方 × 3
  一起在音乐房 × 2（每次会话）
  互相关注 × 10（一次性基础分）

时间衰减：score × e^(-λ × days)，λ = 0.0077（90 天衰减到 50%）
```

**亲密度等级**：

| 等级 | 分数 | 展示 |
|---|---|---|
| 陌生 | 0-9 | 无标识 |
| 认识 | 10-49 | — |
| 熟悉 | 50-199 | 🔹 |
| 好友 | 200-999 | 🔸 |
| 密友 | ≥ 1000 | 💎 |

**粉丝榜（创作者侧）**：

| 榜单 | 说明 | 更新 |
|---|---|---|
| **铁粉榜** | 与该用户亲密度 Top 20 | 每日 |
| **互动榜** | 近 30 天互动最多的粉丝 Top 20 | 每日 |
| **打赏榜**（若有） | 送出礼物最多（见 [22 章](./22-模块13-音乐房升级.md)） | 实时 |

**业务规则**：

- `BR-25-119`：**亲密度对用户可见**（双方可见自己的亲密度，**不公开他人**）。
- `BR-25-120`：**粉丝榜公开**（认证用户默认开启，普通用户默认关闭，可主动开启）。
- `BR-25-121`：**榜单只展示 Top 20**（不展示完整排序）。
- `BR-25-122`：**榜单不上榜拉黑用户**。
- `BR-25-123`：**亲密度计算离线**（每日凌晨），不影响在线性能。
- `BR-25-124`：**亲密度不可购买**（防止刷分）。
- `BR-25-125`：**防刷**：同一用户对同一对象的互动**每天最多计 10 次**（防止刷亲密度）。
- `BR-25-126`：**隐私**：用户可关闭"展示我的亲密度"（则只显示等级，不显示分数）。
- `BR-25-127`：**榜单更新频率**：粉丝榜每日更新；礼物榜实时（见 [22 章](./22-模块13-音乐房升级.md)）。

## 12. 容量与性能

**数据量估算（10 万 DAU）**：

| 数据 | 规模 | 存储 |
|---|---|---|
| 动态 | 5000 条/天 × 365 = 180 万/年 | MySQL ~2GB/年 |
| 动态图片 | 平均 2 张/条 → 1 万张/天 | OSS ~10GB/年 |
| Feed 收件箱 | 10 万用户 × 1000 条 | Redis ~2GB |
| 通知 | 50 万/天 | MySQL ~5GB/年 |
| 私信消息 | 20 万/天 | MySQL ~10GB/年 |
| 亲密度关系 | 10 万 × 平均 20 = 200 万行 | MySQL ~200MB |
| 话题 | 少量 | MySQL |

**性能要求**：

| 操作 | P95 | P99 |
|---|---|---|
| 读 Feed 流 | ≤ 300ms | ≤ 500ms |
| 发布动态（不含图片） | ≤ 800ms | ≤ 1.5s |
| 动态详情 | ≤ 400ms | ≤ 700ms |
| 用户主页 | ≤ 500ms | ≤ 800ms |
| 会话列表 | ≤ 300ms | ≤ 500ms |
| 消息列表 | ≤ 300ms | ≤ 500ms |
| 未读数查询 | ≤ 50ms | ≤ 100ms |
| 推送消息到达 | ≤ 2s | ≤ 5s |

**并发能力**：

| 指标 | 值 |
|---|---|
| Feed 读 QPS 峰值 | 2000 |
| 发布 QPS 峰值 | 50 |
| 推送消息 QPS 峰值 | 5000 |
| 消息发送 QPS 峰值 | 500 |
| WebSocket 连接数 | 10 万（集群） |

**写放大控制**：

```
发布动态 → 粉丝数 < 5000 → 写收件箱（Pipeline 批量）
  5000 粉丝 = 1 次 Pipeline（500 个 key/批，10 批）
  耗时预估：~200ms（Redis 集群）
  若 > 5s → 降级拉模式

大 V （粉丝 ≥ 5000）→ 不写收件箱，只写发件箱（1 次写入）
  → 粉丝读取时拉取（每人 1 次读取，QPS = 粉丝活跃数）
```

## 13. 降级策略

| 依赖 | 故障 | 降级 |
|---|---|---|
| Redis（收件箱） | 不可用 | 全拉模式（查 DB，性能下降但可用） |
| 收件箱未构建 | — | 异步构建 + 同步全拉 |
| 通知聚合 Redis | 不可用 | 不聚合，逐条展示 |
| WebSocket | 不可用 | 前端轮询（30s 间隔） |
| 图片审核 | 不可用 | 进人工队列，图片暂不可见 |
| 内容审核（文本） | 不可用 | DFA 敏感词兜底 + 进人工队列 |
| 对象存储 | 不可用 | 禁止上传图片，纯文本动态可用 |
| 亲密度计算任务 | 失败 | 使用上次结果 |
| 推荐关注 | 不可用 | 展示"热门用户" |
| 消息发送 | 失败 | 前端标记"发送失败"，支持重试 |
| 大 V 发件箱读取 | 超时 | 跳过该大 V 的内容（不影响其他） |
