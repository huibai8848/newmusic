## 1. 模块目标

1. 让中文搜索**准确切词**，正确处理歌名、歌手名、缩写、谐音。
2. 让搜索**理解同义词**（"周董" = "周杰伦"，"rap" = "说唱"）。
3. 让搜索**支持拼音**（全拼、首字母）。
4. 让搜索**不受简繁体影响**（"陳奕迅" = "陈奕迅"）。
5. 让运营能够**自助维护**词典，无需重启 ES。

**衡量指标**：

| 指标 | 目标 |
|---|---|
| 分词准确率（人工抽检 Top 500 歌曲名） | ≥ 95% |
| 词典热更新生效时间 | ≤ 60s |
| 同义词覆盖常见别名 | ≥ 200 组 |
| 拼音搜索召回率 | ≥ 90% |
| 简繁转换准确率 | ≥ 99% |
| 索引更新时间（词典变更后） | 全量重建 ≤ 2h，增量 ≥ 1min 内 |

| 系统 | 自动从歌曲库同步歌手名/歌曲名到词典 |

## 3. 前置条件

- ES 7.17.10 已安装 `elasticsearch-analysis-ik` 7.17.10 插件。
- ES 配置目录可写（`$ES_HOME/config/analysis-ik/`）或有可访问的远程词典 HTTP 服务。
- ES 集群可热更新词典（`updateable: true` 或远程词典）。

> **重要说明**：IK 插件的词典**默认放在 ES 的 config 目录**（`IKAnalyzer.cfg.xml` 中配置）。在**容器化**部署下，需要：
> 1. **方案 A（推荐）**：IK 配置**远程词典 URL**（指向本项目的词典服务 `GET /api/v1/internal/dict/ik?type=main`），ES 每 60 秒自动拉取。**无需重启 ES**，运营改完词后 60 秒生效。
> 2. **方案 B**：把词典文件挂载为 **ConfigMap/Volume**，变更后用 ES API 触发热重载（`POST /_reload_search_analyzers`）——**注意**：IK 词典变更支持热更新，但**已索引的文档不会自动重新分词**，需重建索引才能对**新词**生效于已有文档。
>
> **【假设 A-21】** 本项目采用**方案 A（远程词典）**，因为运营需要频繁调整且不能重启 ES。

### FR-20-001 主词典（业务词）【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 让业务专有名词被正确切分 |
| **使用角色** | 运营 |

**词典内容**：

| 类型 | 示例 | 说明 |
|---|---|---|
| **歌手名** | 周杰伦、林俊杰、陈奕迅、邓紫棋、五月天 | 必须整体成词，不能拆为"周杰/伦" |
| **乐队/组合名** | 五月天、Beyond、S.H.E、Twins、动力火车 | — |
| **歌曲名中的特殊词** | 晴天、稻香、青花瓷、七里香 | 避免被拆 |
| **音乐术语** | 电音、说唱、民谣、古风、摇滚、R&B、City Pop | 流派词 |
| **专辑名** | 叶惠美、范特西、十一月的萧邦 | — |
| **平台词** | 音乐房、歌单、收藏夹、私人电台 | 产品功能词 |
| **网络流行语/谐音** | 绝绝子、yyds、破防了、社会摇 | 搜索可能输入 |

**格式**（IK 主词典格式，一行一个词，可选词频与词性）：

```
周杰伦 100 n
林俊杰 100 n
陈奕迅 100 n
五月天 100 n
邓紫棋 100 n
稻香 80 n
青花瓷 80 n
七里香 80 n
城市流行 50 n
说唱 90 n
电音 90 n
```

**业务规则**：

- `BR-20-001`：词典**必须**包含**所有歌手名与别名**（自动从 `t_artist` 同步 + 人工补充）。
- `BR-20-002`：词典**必须**每行一个词，UTF-8 编码（**无 BOM**）。
- `BR-20-003`：词条长度 **2~15 个字符**（单字词与超长词无效）。
- `BR-20-004`：词条**不允许**包含换行、Tab、逗号（IK 的分隔符）。
- `BR-20-005`：词典**必须**支持词频标记（`词 词频 词性`），词频越高优先级越高。
- `BR-20-006`：词典**必须**有**版本号**（用于 ES 拉取时的 ETag 判断）。
- `BR-20-007`：**自动同步**：歌手表变更时**自动**追加到词典（定时任务每小时 + MQ 实时触发）。
- `BR-20-008`：词典**上限 10 万词条**（IK 加载词典有内存开销）。
- `BR-20-009`：词典变更后**必须**在 60 秒内被 ES 拉取（远程词典轮询间隔）。
- `BR-20-010`：**新增词条**对**已索引文档**不生效（需重建索引），此限制**必须**在后台界面上向运营说明。
  - **优化**：对**高频搜索词**，可在**查询时**用 `synonym` 或 `query-time` 处理，避免重建索引。

**词典同步实现**：

```java
/**
 * IK 远程词典服务
 * ES 配置：<entry key="remote_ext_dict">http://ml-app:8080/api/v1/internal/dict/ik?type=main</entry>
 * ES 每 60 秒请求一次，通过 Last-Modified / ETag 判断是否更新
 */
@RestController
@RequestMapping("/api/v1/internal/dict")
public class IkDictController {

    @Autowired private IkDictService ikDictService;

    @GetMapping("/ik")
    public ResponseEntity<String> getIkDict(
            @RequestParam(defaultValue = "main") String type,
            @RequestHeader(value = "If-Modified-Since", required = false) String ifModifiedSince) {

        DictSnapshot snapshot = ikDictService.getSnapshot(type);  // 缓存 30 秒

        if (ifModifiedSince != null && snapshot.getLastModified().equals(ifModifiedSince)) {
            return ResponseEntity.status(HttpStatus.NOT_MODIFIED).build();
        }

        return ResponseEntity.ok()
            .header("Last-Modified", snapshot.getLastModified())
            .header("ETag", "\"" + snapshot.getVersion() + "\"")
            .contentType(MediaType.TEXT_PLAIN)
            .body(snapshot.getContent());
    }
}
```

> **注意**：ES 的 IK 远程词典要求 `Last-Modified` 与 `ETag` **同时**返回，任一变化即触发更新。

**分词效果验证工具**：

```
GET /api/v1/admin/dict/analyze?text=周杰伦的稻香&analyzer=ik_smart
```

```json

  "code": 0,
  "data": {
    "text": "周杰伦的稻香",
    "analyzer": "ik_smart",
    "tokens": [
      { "token": "周杰伦", "startOffset": 0, "endOffset": 3, "type": "CN_WORD" },
```

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-20-001-1` | 词典文件格式错误（含非法字符） | 后台校验拦截，提示具体行号 |
| `EX-20-001-2` | 词典服务不可用 | ES 使用**上次拉取的缓存**，不中断搜索；告警 |
| `EX-20-001-3` | 词典含超长词（> 15 字） | 后台拒绝并提示 |
| `EX-20-001-4` | 词典含重复词 | 去重（保留词频高的） |
| `EX-20-001-5` | 词典过大（> 10 万条） | 后台告警，拒绝新增 |
| `EX-20-001-6` | ES 未拉取到新词典 | 后台显示"生效中"，60 秒后自动重试；超 5 分钟告警 |

**验收标准**：

- `AC-20-001-1`：歌手名不被拆分（"周杰伦" 是 1 个 token）
- `AC-20-001-2`：词典更新后 60 秒内生效
- `AC-20-001-3`：词典格式校验正确
- `AC-20-001-4`：分词工具可验证效果
- `AC-20-001-5`：歌手新增自动同步到词典
- `AC-20-001-6`：词典服务不可用时搜索不中断

### FR-20-002 停用词【P1】

| 项 | 内容 |
|---|---|
| **功能目标** | 移除无意义词，减少噪音召回 |
| **使用角色** | 运营 |

**停用词分类**：

| 分类 | 示例 | 说明 |
|---|---|---|
| **中文虚词** | 的、了、和、与、及、或、在、是、就、也、都 | 语法词 |
| **搜索意图词** | 我想听、帮我找、有没有、请、来个、推荐 | 用户口语中的意图词 |
| **通用名词** | 歌、歌曲、音乐、一首、歌单 | 除非在歌曲名中，否则无区分度 |
| **英文虚词** | a、an、the、of、and、or、to、in | — |
| **标点与符号** | 、。，！？；：""''（）【】 | — |
| **纯数字** | 单独的数字（非年份/年代） | 保留 1980-2029（避免误删年代） |

**格式**（IK 停用词，一行一个词）：

```
的
了
和
与
我想听
帮我找
有没有
来个
推荐
歌
歌曲
音乐
一首
the
a
an
of
```

**业务规则**：

- `BR-20-011`：停用词**仅用于查询分析**（`search_analyzer`），**不用于索引分析**。
  - **理由**：若索引时也移除"歌"，则歌曲名《一首歌的时间》会被破坏。查询时移除则用户搜"歌"不会召回全部歌曲（这本就是噪音）。
  - **【假设 A-22】** 本项目**索引用 `ik_max_word`（不带停用词），查询用 `ik_smart` + 停用词**。这是 ES 中文搜索的常见最佳实践。
- `BR-20-012`：停用词**必须**包含常见搜索引擎噪音词。
- `BR-20-013`：**年份与年代不列为停用词**（1980-2029、"80s"、"90年代"）。
- `BR-20-014`：停用词**必须**支持热更新（同上，远程词典）。
- `BR-20-015`：停用词**上限 5000 条**。
- `BR-20-016`：停用词变更**仅影响查询**，**无需重建索引**（重大优势）。
- `BR-20-017`：**歌曲名中恰好包含停用词**时，用户**完整搜索歌名**应能命中——通过 `match_phrase` 或 `keyword` 子字段兜底。

**验收标准**：

- `AC-20-002-1`：搜索"我想听周杰伦的歌"能命中周杰伦（移除意图词）
- `AC-20-002-2`：停用词不影响索引（《一首歌的时间》仍可搜到）
- `AC-20-002-3`：停用词热更新生效
- `AC-20-002-4`：歌曲名含停用词时完整搜索可命中

| **使用角色** | 运营 |

**同义词分组**：

| 类别 | 示例 |
|---|---|

| **语种同义** | 国语,华语,中文,普通话 / 粤语,广东话,Cantonese / 纯音乐,轻音乐,器乐,无人声,instrumental |

**格式**（IK `synonym` filter，Solr 格式，逗号分隔）：

```
周杰伦,周董,杰伦,Jay
陈奕迅,Eason,医生
林俊杰,JJ
说唱,rap,嘻哈,hiphop,hip-hop
电子,EDM,电音
民谣,folk
摇滚,rock,摇滚乐
国语,华语,中文,普通话
粤语,广东话
纯音乐,轻音乐,器乐,无人声
运动,健身,跑步
睡眠,睡前,助眠
伤感,悲伤,难过
治愈,暖心
```

**同义词类型**：

| 类型 | 语法 | 说明 |
|---|---|---|
| **等价同义** | `A,B,C` | A/B/C 互相等价 |
| **单向扩展** | `A => B,C` | 搜索 A 时扩展为 B、C，但搜索 B 不扩展为 A |

**使用场景选择**：

| 场景 | 配置 |
|---|---|
| **索引时同义** | 会把同义词写入倒排索引（索引膨胀） |
| **查询时同义** | 查询时扩展（灵活，但性能略差） |
| **【假设 A-23】** | 本项目**采用查询时同义**（`search_analyzer` 使用 synonym filter），因为运营需要频繁调整且避免索引膨胀与重建。"周董"在**索引时**若不同义，则歌曲名含"周董"的歌需要通过"周杰伦"搜到——用**查询时扩展**即可（搜"周杰伦"→ 扩展为"周杰伦,周董"→ 命中）。 |

**同义词过滤器的可更新配置**：

```json
{
  "filter": {
    "music_synonym": {
      "type": "synonym",
      "synonyms_path": "analysis/music_synonyms.txt",
      "updateable": true,          // 关键：支持热更新
      "lenient": true              // 忽略格式错误的行（不阻断）
    }
  }
}
```

> **重要**：`updateable: true` 允许通过 `POST /_reload_search_analyzers` **热重载**同义词，**无需重启、无需重建索引**（因为是查询时同义）。
>
> 远程同义词文件需 ES 7.x 支持 `synonyms_path` 为 URL（**7.17 不支持**，需用文件路径 + ConfigMap 挂载 + 热重载 API）。
>
> **【假设 A-24】** 同义词文件通过 **ConfigMap 挂载**到 ES config 目录，运营修改后：
> 1. 后台写入同义词内容到 MySQL + 生成文件到挂载卷（通过 Sidecar 或 initContainer 同步）
> 2. 调用 `POST /_reload_search_analyzers`
> 3. 若无法写挂载卷，则降级为"应用层同义词扩展"（见下）

**降级方案：应用层同义词扩展**

若无法写 ES 挂载卷，可在应用层做同义词扩展：

```java
@Component
public class SynonymExpander {
    @Autowired private SynonymService synonymService;   // 从 t_synonym 表读取（带缓存）

    /** 把用户查询扩展为同义词的 OR 查询 */
    public String expand(String query) {
        Set<String> terms = new HashSet<>();
        terms.add(query);
        terms.addAll(synonymService.getSynonyms(query));
        return String.join(" ", terms);
    }
}
// 然后 multi_match 的 query 用扩展后的串
// 优点：完全可控、热更新、无需 ES 配合
// 缺点：丢失词位置信息（phrase 查询受影响）
```

**业务规则**：

- `BR-20-018`：同义词**采用查询时扩展**（避免索引膨胀与重建）。
- `BR-20-019`：同义词**必须**单向扩展 vs 等价同义**明确区分**（歌手别名用等价，风格用单向更合适）。
- `BR-20-020`：同义词组**上限 5000 组**，单组**上限 20 个词**。
- `BR-20-021`：同义词**不允许**出现循环（`A=>B` 且 `B=>A`）。
- `BR-20-022`：同义词**不允许**与停用词冲突（同义词中的词不能是停用词）。
- `BR-20-023`：同义词**热更新**：`POST /_reload_search_analyzers`，**无需重建索引**。
- `BR-20-024`：同义词**必须**支持**运营后台管理**（CRUD + 批量导入 + 生效状态显示）。
- `BR-20-025`：同义词**必须**记录**变更历史**。
- `BR-20-026`：**歌手别名**从 `t_artist.alias` **自动同步**到同义词。
- `BR-20-027`：同义词扩展后**必须**保持**原始词的高权重**（原词 `boost` 更高，避免同义词结果淹没原词结果）。

**原词权重保持实现**：

```json
{
  "query": {
    "bool": {
      "should": [
        { "multi_match": { "query": "周杰伦", "fields": ["artist_name^3"], "boost": 2.0 } },
        { "multi_match": { "query": "周董",   "fields": ["artist_name^3"], "boost": 1.0 } },
        { "multi_match": { "query": "杰伦",   "fields": ["artist_name^3"], "boost": 1.0 } }
      ]
    }
  }
}
```

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-20-003-1` | 同义词文件格式错误 | `lenient: true` 忽略错误行 + 告警 |
| `EX-20-003-2` | 热重载失败 | 保留旧同义词，告警；提供后台"重试" |
| `EX-20-003-3` | 同义词组过大（> 20） | 后台拒绝并提示 |
| `EX-20-003-4` | 同义词循环 | 后台校验拒绝 |
| `EX-20-003-5` | ES 集群不支持热重载 | 降级为应用层同义词扩展 |
| `EX-20-003-6` | 同义词与停用词冲突 | 后台警告，提示移除 |

**验收标准**：

- `AC-20-003-1`：搜索"周董"能命中周杰伦的歌曲
- `AC-20-003-2`：搜索"rap"能命中说唱风格歌曲
- `AC-20-003-3`：同义词热更新 60 秒内生效
- `AC-20-003-4`：原词结果排名高于同义词结果
- `AC-20-003-5`：运营可在后台管理同义词
- `AC-20-003-6`：歌手别名自动同步

### FR-20-004 扩展词典与停用词（二级词典）【P2】

**查询策略**：

```java
/**
 * 智能判断输入是否为拼音，选择合适的查询字段
 */
public class PinyinQueryStrategy {

    private static final Pattern PINYIN_PATTERN = Pattern.compile("^[a-zA-Z]{2,}$");
    private static final Pattern CHINESE_PATTERN = Pattern.compile(".*[\\u4e00-\\u9fa5].*");

    public Query buildQuery(String keyword, String field) {
        boolean hasChinese = CHINESE_PATTERN.matcher(keyword).matches();
        boolean isPurePinyin = PINYIN_PATTERN.matcher(keyword).matches();

        if (hasChinese) {
            // 含中文：只搜原文（省性能）
            return QueryBuilders.multiMatchQuery(keyword, field + "^5", field + ".pinyin^2");
        }

        if (isPurePinyin) {
            // 纯拼音/字母：搜拼音字段为主，原文字段兜底
            return new BoolQueryBuilder()
                .should(QueryBuilders.multiMatchQuery(keyword, field + ".pinyin^4"))
                .should(QueryBuilders.multiMatchQuery(keyword, field + "^2"))
                .minimumShouldMatch(1);
        }

        // 混合（如 "周jl"）：两者都搜
        return new BoolQueryBuilder()
            .should(QueryBuilders.multiMatchQuery(keyword, field + "^4"))
            .should(QueryBuilders.multiMatchQuery(keyword, field + ".pinyin^3"))
            .minimumShouldMatch(1);
    }
}
```

**业务规则**：

- `BR-20-034`：拼音字段**必须**支持：全拼（`zhoujielun`）、分字全拼（`zhou jie lun`）、首字母（`zjl`）、原始词（`周杰伦`）。
- `BR-20-035`：拼音**必须** `lowercase`（大小写不敏感）。
- `BR-20-036`：**中文输入**只搜原文字段（拼音权重低，避免噪音召回）。
- `BR-20-037`：**纯拼音输入**搜拼音字段为主、原文兜底。
- `BR-20-038`：拼音搜索**仅对**歌曲名、歌手名、专辑名、歌单名生效，**不**对歌词生效（歌词拼音无意义且索引膨胀严重）。
- `BR-20-039`：**索引体积**：开启拼音后索引体积约增大 **1.5~2 倍**，需在容量规划中考虑。
- `BR-20-040`：**多音字**处理：pinyin 插件默认取常见读音，对多音字词（如"曾毅" zeng/yi）需加入自定义词典固定读音。
- `BR-20-041`：**首字母搜索**要求：**至少 2 个字母**（单字母召回过多）。
- `BR-20-042`：**首字母匹配**必须**完整匹配**（`zjl` 匹配"周杰伦"，`zj` 也可匹配前缀，`z` 不匹配）。
- `BR-20-043`：拼音搜索**必须**记录埋点（判断使用率，决定是否保留）。

**多音字处理**：

## 6. 简繁体转换

### FR-20-006 简繁互通 【P1】

| 项 | 内容 |
|---|---|
| **功能目标** | 简繁体搜索互不影响（"陳奕迅" = "陈奕迅"） |
| **使用角色** | 全部（尤其港台用户） |

**实现方案对比**：

| 方案 | 说明 | 优点 | 缺点 |
|---|---|---|---|
| **A. ES `stconvert` 插件** | 索引与查询都转简体 | 索引小 | 需额外插件；索引时转换损失原文 |
| **B. 查询时转换** | 查询时把繁体转简体，再查简体索引 | 无需重建索引；灵活 | 若数据本身是繁体则查不到 |
| **C. 双向索引** | 同时索引简体与繁体字段 | 最全 | 索引体积翻倍 |
| **D. 应用层转换** | 查询时转换 + 分词前处理 | 简单可控 | 需维护转换表 |

**选型**：**方案 B + D 组合**——**索引时同时存储简体与原文字段**，**查询时把输入统一转简体**。

**【假设 A-25】** 采用 `elasticsearch-analysis-stconvert` 插件 + 应用层兜底转换。

**实现**：


**应用层兜底（不依赖插件）**：

```java
/**
 * 简繁转换工具（基于 OpenCC 的 Java 实现或自建映射表）
 * 依赖：com.github.houbb:opencc4j:1.8.0
 */
@Component
public class ChineseConverter {

    /** 繁体 → 简体（查询预处理） */
    public String toSimplified(String text) {
        if (StringUtils.isBlank(text)) return text;
        return OpenccUtil.convert(text, "t2s");   // Traditional to Simplified
    }

    /** 简体 → 繁体（可选，用于展示） */
    public String toTraditional(String text) {
        if (StringUtils.isBlank(text)) return text;
        return OpenccUtil.convert(text, "s2t");
    }
}

// 在搜索入口统一预处理
public SearchResult search(String keyword) {
    String normalized = chineseConverter.toSimplified(keyword);
    // 用 normalized 查询
}
```

> **注意**：`opencc4j` 依赖 **JDK 8 兼容**（1.8.0 版本支持）。**必须**验证依赖不引入高版本 JDK 需求。

**业务规则**：

- `BR-20-044`：**查询时**把繁体统一转为简体（`t2s`）。
- `BR-20-045`：**索引时**对歌曲名/歌手名/专辑名存储**转换后的版本**（索引字段用转换后的）。
- `BR-20-046`：**展示时**保持**原文**（如台湾歌手用繁体艺名，展示用繁体）。
- `BR-20-047`：简繁转换**必须**覆盖常见异体字（如"裡"→"里"、"後"→"后"）。
- `BR-20-048`：**不改变**专有名词的语义（"范特西"不转、"葉惠美"→"叶惠美" 是正确的）。
- `BR-20-049`：转换表**必须**可更新（新增异体字）。
- `BR-20-050`：**性能**：转换开销 ≤ 0.5ms（单次查询）。
- `BR-20-051`：**地区化**：可根据用户地区（IP/语言设置）决定**展示**用简/繁，但**索引**统一简体。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-20-006-1` | stconvert 插件不可用 | 应用层 opencc4j 兜底 |
| `EX-20-006-2` | opencc4j 也不可用 | 仅原文搜索（功能降级），告警 |
| `EX-20-006-3` | 转换错误（罕见字） | 记录日志，保留原文 |

**分析器使用矩阵**：

| 字段 | 索引分析器 | 查询分析器 | 说明 |
|---|---|---|---|
| `name`（歌曲名） | `index_analyzer` | `search_analyzer_music` | 索引细分，查询粗分 + 同义 |

**为什么索引用 `ik_max_word`、查询用 `ik_smart`？**

| 分析器 | 行为 | 示例（"周杰伦的稻香"） |
|---|---|---|
| `ik_max_word` | **最细粒度**：穷尽所有可能的分词 | 周杰伦 / 周杰 / 杰伦 / 的 / 稻香 / 稻 |
| `ik_smart` | **最粗粒度**：最少的分词 | 周杰伦 / 的 / 稻香 |

- **索引时**用 `ik_max_word`：让**更多词**进入倒排索引，提高**召回率**（用户搜"杰伦"也能命中）。
- **查询时**用 `ik_smart`：减少查询词数量，提高**准确率**与**性能**。
- 这是 ES 中文搜索的**标准最佳实践**。

**业务规则**：

- `BR-20-052`：索引分析器**必须**用 `ik_max_word`（召优先）。
- `BR-20-053`：查询分析器**必须**用 `ik_smart` + 同义词（准确 + 灵活）。
- `BR-20-054`：**必须**配置 `char_filter` 统一全角/半角与特殊符号。
- `BR-20-055`：**同义词仅用于查询**（`search_analyzer`），避免索引膨胀。
- `BR-20-056`：**繁简转换**用于索引与查询**双向**（保证互搜）。
- `BR-20-057`：**拼音**独立子字段，不污染主字段。
- `BR-20-058`：**分析器配置变更必须**重建索引（用别名切换，见 [15 章](./15-模块06-搜索与AI搜索.md)）。
- `BR-20-059`：分析器配置**必须**纳入版本管理（Git），禁止直接在 ES 上手工修改生产配置。
- `BR-20-060`：**必须**提供分析器测试接口（后台可输入文本查看分词结果）。

**验收标准**：

- `AC-20-007-1`：索引分析器为 `ik_max_word`，查询为 `ik_smart`
- `AC-20-007-2`：搜"杰伦"能命中周杰伦（max_word 索引优势）

| 搜索量关联 | 展示词条的历史搜索量（辅助判断重要性） |

**分词测试界面**：

```
┌──────────────────────────────────────────────────────┐
│  文本输入: [周杰伦的稻香                          ]   │
│  ┌─ 修改前 (当前生产配置) ──────────────────────┐    │
│  │  周杰伦 | 的 | 稻香                            │    │
│  └───────────────────────────────────────────────┘    │
│  ┌─ 修改后 (含本次编辑的词典) ─────────────────┐    │
│  │  周杰伦 | 的 | 稻香 | 香                      │    │
│  └───────────────────────────────────────────────┘    │
│  [保存并生效]  [放弃]                                 │
└──────────────────────────────────────────────────────┘
```

**业务规则**：

- `BR-20-061`：词条**必须**有来源标记（人工/自动），**自动词条不可手工删除**。
- `BR-20-062`：**批量导入**必须**逐行校验**并返回错误报告。
- `BR-20-063`：**分词测试**必须**对比**修改前后效果。
- `BR-20-064`：**生效状态**必须展示 ES 上次拉取时间（运营可判断是否生效）。
- `BR-20-065`：**变更必须先预览**（分词测试）**再保存**。
- `BR-20-066`：**保存后自动触发** ES 重载（同义词/停用词）或**提示需重建索引**（主词典新词）。
- `BR-20-067`：词条删除**必须**二次确认（可能影响线上搜索）。
- `BR-20-068`：词典操作**必须**记录变更历史（可回滚）。
- `BR-20-069`：**搜索量关联**：展示词条近 7 天被搜索的次数（辅助决策）。
- `BR-20-070`：**同义词**管理界面与**主词典**分开（语义不同）。

**验收标准**：

- `AC-20-008-1`：词典 CRUD 完整
- `AC-20-008-2`：批量导入有错误报告
- `AC-20-008-3`：分词测试对比修改前后
- `AC-20-008-4`：生效状态可见
- `AC-20-008-5`：变更历史可查
- `AC-20-008-6`：自动词条不可手工删除
- `AC-20-008-7`：一键重载可用

## 10. 运维要求

| 项 | 要求 |
|---|---|
| 词典服务可用性 | ≥ 99.9%（ES 强依赖） |
| 词典服务响应时间 | ≤ 100ms（ES 每 60s 拉取） |
| 词典内容大小 | 主词典 ≤ 10 万条（约 2MB）；同义词 ≤ 5000 组（约 200KB） |
| 索引体积预算 | 拼音字段使索引增大 1.5~2 倍 |
| 重建索引时长 | 100 万歌曲 ≈ 1.5~2 小时（3 分片） |
| 别名切换 | 零停机（`music_song_v{N}` → `music_song`） |
| 词典版本 | 每次变更生成新版本号（时间戳），ES 拉取时用 ETag 判断 |
| 监控 | 词典服务可用性、拉取成功率、词典大小、索引体积、分词耗时 |

**重建索引流程（SOP）**：

```
[1] 创建新索引 music_song_v{N+1}（带新分析器配置）
[2] 设置 refresh_interval = -1, number_of_replicas = 0（加速写入）
[3] 全量数据写入（从 MySQL 分批读取，bulk 写入，每批 1000）
[4] 对比新旧索引文档数（必须一致）
[5] 抽样对比新旧索引的搜索结果（10 个典型查询，人工校验）
[6] 恢复 refresh_interval = 1s, number_of_replicas = 1
[7] 别名原子切换：POST /_aliases { "actions": [ {"remove": {"index": "music_song_v{N}", "alias": "music_song"}}, {"add": {"index": "music_song_v{N+1}", "alias": "music_song"}} ] }
[8] 验证线上搜索正常
[9] 观察 24 小时后删除旧索引
```

**回滚**：别名切回旧索引（秒级）。

## 11. 降级策略

| 依赖 | 故障 | 降级 |
|---|---|---|
| 词典服务 | 不可用 | ES 使用上次拉取的词典缓存，搜索不中断 |
| pinyin 插件 | 未安装/损坏 | 拼音搜索降级为原文搜索 |
| stconvert 插件 | 未安装/损坏 | 应用层 opencc4j 兜底；再失败则仅原文搜索 |
| synonym filter | 文件缺失 | `lenient: true` 不阻断；同义词失效功能降级 |
| ES 热重载失败 | 支持问题 | 降级为应用层同义词/停用词处理 |
| ES 整体 | 不可用 | 搜索降级 MySQL LIKE（见 [15 章](./15-模块06-搜索与AI搜索.md)） |
