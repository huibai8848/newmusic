## 1. 性能需求

### 1.1 响应时间

**定义**：服务端处理时间（不含网络传输与客户端渲染），单位 ms。

| 接口类型 | 示例 | P50 | P95 | **P99** | 超时 |
|---|---|---|---|---|---|
| **极快（缓存直读）** | 点赞状态、关注状态 | ≤ 20 | ≤ 50 | **≤ 80** | 1s |
| **快（简单查询）** | 用户信息、歌曲详情 | ≤ 50 | ≤ 120 | **≤ 200** | 2s |
| **普通（列表）** | 歌曲列表、评论列表、我的歌单 | ≤ 100 | ≤ 250 | **≤ 300** | 3s |
| **较慢（复杂查询）** | 搜索、推荐、Feed | ≤ 150 | ≤ 350 | **≤ 500** | 3s |
| **慢（写 + 多步）** | 发布动态、创建歌单、上传歌曲 | ≤ 200 | ≤ 400 | **≤ 600** | 5s |
| **很慢（外部依赖）** | AI 生成歌单、AI 搜索 | ≤ 1.5s | ≤ 3s | **≤ 5s** | 10s |
| **异步任务** | 批量标注、报表生成 | — | — | — | 后台任务 |

### 1.2 吞吐量

| 指标 | 目标 | 说明 |
|---|---|---|
| **全站 QPS**（正常） | 5,000 | 支持限流上限 |
| **全站 QPS**（峰值） | 10,000 | 需扩容支持 |

| **推荐 QPS** | 1,000 | 含多路召回 |
| **MQ 消息吞吐** | 50,000 条/秒 | 峰值 |
| **埋点上报** | 100,000 条/秒 | 峰值 |
| **AI 调用** | 50 QPS | 受成本与限流约束 |

**并发用户模型**（10 万 DAU 基准）：

```
10 万 DAU
  ↓ 日活中 30% 同时在线 → 3 万在线
  ↓ 同时在线中 10% 正在操作 → 3,000 并发操作
  ↓ 每个操作平均 3 个请求 → 9,000 请求/10 秒 → 900 QPS（均值）
  ↓ 峰值系数 3 → 2,700 QPS
  ↓ 加埋点（每用户每分钟 5 条）→ 3 万 × 5 / 60 = 2,500 QPS
  ↓ 合计约 5,000 QPS（峰值 10,000）
```

### 1.4 性能设计原则

| 编号 | 要求 |
|---|---|
| `NFR-P-001` | **所有读接口必须优先走缓存**（除非明确实时性要求） |
| `NFR-P-002` | **所有列表接口必须分页**（禁止全量返回） |
| `NFR-P-003` | **单接口返回体 ≤ 200KB**（超过必须分页或裁剪） |
| `NFR-P-004` | **禁止 N+1 查询**（批量查询代替循环查询） |
| `NFR-P-005` | **禁止大事务**（单事务 < 1000 行 / < 1 秒） |
| `NFR-P-006` | **禁止全表扫描**（必须有索引支撑） |
| `NFR-P-007` | **禁止在循环内调用远程服务/AI** |
| `NFR-P-008` | **批量操作必须用批量接口**（Redis Pipeline、批量 SQL） |
| `NFR-P-009` | **耗时的非必要操作必须异步**（MQ / 线程池） |
| `NFR-P-010` | **外部调用必须有超时**（HTTP/DB/Redis/AI 全部设置超时） |
| `NFR-P-011` | **多路并行调用必须并行执行**（CompletableFuture） |
| `NFR-P-012` | **热点数据必须本地缓存 + 分布式缓存双层** |
| `NFR-P-013` | **大列表必须虚拟滚动**（前端） |
| `NFR-P-014` | **静态资源必须 CDN + 强缓存 + 版本化**（hash 文件名） |
| `NFR-P-015` | **任意接口必须有超时与降级**（不无限等待） |
| `NFR-P-016` | **性能必须可测量**（关键路径有耗时打点与监控） |
| `NFR-P-017` | **性能必须回归验证**（每版本压测核心场景） |
| `NFR-P-018` | **禁止在请求链路中做大数据量计算**（移到离线/异步） |
| `NFR-P-019` | **数据库连接必须在事务提交后释放**（避免长连接占用） |
| `NFR-P-020` | **Redis 必须避免大 key 与热 key** |

## 2. 安全需求

### 2.1 认证与授权

| 编号 | 要求 |
|---|---|
| `NFR-S-001` | **必须使用 JWT 无状态认证**（access + refresh 双 token） |
| `NFR-S-002` | **access token 有效期 ≤ 2 小时**，refresh token ≤ 7 天且**旋转（一次性）** |
| `NFR-S-003` | **签名算法必须 RS256**（非对称，便于验证方不持有私钥） |
| `NFR-S-004` | **必须使用 BCrypt（cost ≥ 10）存储密码**，禁止明文/MD5/SHA1 |
| `NFR-S-005` | **管理后台必须使用独立 token 体系**（不同签名密钥、`iss=ml-admin`，见 [18 章](./18-模块09-管理后台.md)） |
| `NFR-S-006` | **必须实现 RBAC**，且**全局角色与房间角色两套独立不继承**（见 [02 章](./02-用户角色与权限矩阵.md)） |
| `NFR-S-007` | **接口必须校验权限**（注解式 `@PreAuthorize` / 自定义 `@RequirePermission`） |
| `NFR-S-008` | **越权必须防护**：水平越权（IDOR，校验资源归属）、垂直越权（校验角色） |
| `NFR-S-009` | **超级管理员必须启用 2FA**（TOTP），敏感操作二次验证 |
| `NFR-S-010` | **敏感操作必须二次确认**（删除、封禁、导出、配置变更） |
| `NFR-S-011` | **必须支持强制下线**（token 黑名单 / 版本号机制） |
| `NFR-S-012` | **登录必须防爆破**（失败计数 + 锁定 + 验证码 + 限流） |
| `NFR-S-013` | **必须支持会话管理**（查看登录设备、踢出其他设备） |
| `NFR-S-014` | **刷新 token 必须绑定设备指纹**（可选，防 token 盗用） |

### 2.2 数据安全

| 编号 | 要求 |
|---|---|
| `NFR-S-015` | **所有传输必须 HTTPS（TLS 1.2+）**，禁用 HTTP/弱加密套件 |
| `NFR-S-016` | **敏感字段必须加密存储**：手机号、邮箱（AES-256）、身份证（若采集） |
| `NFR-S-017` | **密码必须单向哈希**（BCrypt），**不可逆** |
| `NFR-S-018` | **敏感字段必须脱敏展示**（手机号 `138****8888`、邮箱 `a***@b.com`） |
| `NFR-S-019` | **日志禁止打印敏感信息**（密码、token、完整手机号、身份证） |
| `NFR-S-020` | **密钥必须集中管理**（KMS / 环境变量 / 加密配置），**禁止硬编码**、禁止提交到 Git |
| `NFR-S-021` | **密钥必须定期轮换**（至少每年，泄露时立即轮换） |
| `NFR-S-022` | **数据库备份必须加密** |
| `NFR-S-023` | **数据必须分级**（公开/内部/敏感/机密），按级授权访问 |
| `NFR-S-024` | **用户注销后必须按合规处理数据**（删除或匿名化，见 [04 章](./04-数据模型与数据库设计.md)） |
| `NFR-S-025` | **导出数据必须有权限 + 审计 + 水印**（管理后台导出） |
| `NFR-S-026` | **必须防止批量爬取**（限流 + 行为识别 + 异常告警） |

### 2.3 Web 安全

| 编号 | 要求 |
|---|---|
| `NFR-S-027` | **必须防 SQL 注入**（MyBatis 使用 `#{}`，禁止 `${}` 拼接；动态排序字段必须白名单校验） |
| `NFR-S-028` | **必须防 XSS**：输出转义（前端 React 默认转义，**禁止滥用 `dangerouslySetInnerHTML`**）、富文本必须服务端净化（白名单标签） |
| `NFR-S-029` | **必须防 CSRF**（token 放 Header 而非 Cookie + `SameSite=Lax`；若用 Cookie 则必须 CSRF Token） |
| `NFR-S-030` | **必须防 SSRF**（用户可控 URL 必须校验白名单/禁止内网地址，如头像 URL、音频 URL） |
| `NFR-S-031` | **必须防 XXE**（禁用外部实体，XML 解析安全配置） |
| `NFR-S-032` | **必须防反序列化漏洞**（不使用 Java 原生反序列化接收外部数据；FastJSON 必须升级到安全版本或改用 Jackson） |
| `NFR-S-033` | **必须防路径穿越**（文件上传/下载路径必须规范化校验） |
| `NFR-S-034` | **必须防命令注入**（禁止拼接 shell 命令） |
| `NFR-S-035` | **必须设置安全响应头**：`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Content-Security-Policy`、`Referrer-Policy`、`Strict-Transport-Security` |
| `NFR-S-036` | **CORS 必须白名单**（禁止 `*` 配合 `credentials`） |
| `NFR-S-037` | **Cookie 必须 `HttpOnly` + `Secure` + `SameSite`** |
| `NFR-S-038` | **文件上传必须校验**：类型（白名单魔数校验，非仅扩展名）、大小、数量、内容（图片二次渲染去 EXIF） |
| `NFR-S-039` | **上传文件必须重命名**（UUID，不用原始文件名）且**存于对象存储独立域名**（防 XSS） |
| `NFR-S-040` | **必须防重放攻击**（关键接口加时间戳 + nonce，或幂等键） |
| `NFR-S-041` | **必须防越权访问静态资源**（音频 URL 必须签名，有效期 ≤ 4 小时，防盗链） |
| `NFR-S-042` | **前端不得硬编码任何密钥**（AK/SK、私钥） |

### 2.4 业务安全

| 编号 | 要求 |
|---|---|

| `NFR-S-044` | **必须防薅羊毛**（如无经济体系则暂缓，但预留风控接入点） |

| `NFR-S-046` | **必须防内容注入**（敏感词、外链、广告、联系方式，见 [27 章](./27-模块18-内容安全.md)） |

| `NFR-S-049` | **用户手机号/邮箱默认不公开**，仅在用户主动公开时可见 |
| `NFR-S-050` | **必须防止枚举攻击**（用户 ID 用不可预测的雪花 ID；短码不连续） |

## 3. 可用性需求

### 3.1 可用性指标

| 服务等级 | 可用性 | 月停机 | 适用 |
|---|---|---|---|
| **核心** | **99.95%** | ≤ 21.6 分钟 | 登录、播放、搜索、推荐 |
| **重要** | 99.9% | ≤ 43 分钟 | 社交、房间、歌单 |
| **一般** | 99.5% | ≤ 3.6 小时 | 数据看板、运营工具 |

**RTO / RPO**：

| 场景 | RTO | RPO |
|---|---|---|
| 单实例故障 | ≤ 1 分钟 | 0 |

## 4. 数据一致性需求

### 4.1 一致性分级

**不同数据对一致性的要求不同，必须分级对待**（全部强一致会牺牲性能，全部最终一致会导致业务错误）。

| 级别 | 说明 | 数据示例 | 实现 |
|---|---|---|---|
| **强一致（L1）** | 任何时刻读到的都是最新 | 用户余额（若有）、麦克风座位占用、房间播放状态版本、密码、权限、库存类 | 数据库事务 + 乐观锁/悲观锁 + 分布式锁 |
| **会话一致（L2）** | 同一用户会话内一致 | 用户修改资料后立即刷新 | 写后读主 + 主键查询 |
| **准实时（L3）** | 秒级最终一致 | 点赞数、关注数、评论数、播放数 | 异步更新 + 缓存 |
| **最终一致（L4）** | 分钟级最终一致 | 推荐特征、统计报表、搜索索引、Feed 推送、埋点数据 | MQ + 离线任务 |

### 4.2 一致性保障机制

| 编号 | 要求 |
|---|---|
| `NFR-C-001` | **强一致数据必须用数据库事务**（`@Transactional`，注意传播与隔离级别） |
| `NFR-C-002` | **并发更新必须用乐观锁（`version`）或悲观锁**（`SELECT ... FOR UPDATE`） |
| `NFR-C-003` | **跨实例的临界区必须用分布式锁**（Redisson），且**必须有 DB 兜底** |
| `NFR-C-004` | **缓存与 DB 一致性必须用 Cache-Aside + 延迟双删**（见 [12 章](./12-模块03-Redis缓存.md)） |
| `NFR-C-005` | **缓存更新必须先更新 DB 再删缓存**（不是更新缓存） |
| `NFR-C-006` | **跨服务的写操作必须考虑分布式事务**：优先用**最终一致（本地消息表 + MQ）**，避免 2PC |
| `NFR-C-007` | **MQ 消费必须幂等**（重复消费不产生副作用） |
| `NFR-C-008` | **接口必须幂等**（关键写操作支持幂等键，如点赞、下单类） |
| `NFR-C-009` | **计数类数据必须可对账**（缓存计数与 DB 实际值定期校验，偏差告警） |
| `NFR-C-010` | **搜索索引必须与 DB 最终一致**（MQ 驱动同步 + 定期全量重建） |
| `NFR-C-011` | **推荐特征必须与离线特征一致**（同源计算 + 一致性校验，见 [24 章](./24-模块15-推荐升级.md)） |
| `NFR-C-012` | **Feed 收件箱必须可重建**（丢失时可从 outbox 重建） |
| `NFR-C-013` | **写后读必须保证一致**（关键场景强制读主库） |
| `NFR-C-014` | **必须处理并发冲突**（同一歌单并发编辑、同一房间并发点歌、同一用户并发操作） |
| `NFR-C-015` | **必须防止重复提交**（前端防抖 + 后端幂等键 + 唯一索引兜底） |
| `NFR-C-016` | **必须有唯一约束兜底**（如 `t_like (user_id, song_id)` 唯一索引），防止并发产生脏数据 |
| `NFR-C-017` | **删除必须用逻辑删除**（`deleted` 字段），且查询自动过滤（MP 配置） |
| `NFR-C-018` | **数据变更必须有审计**（关键表记录变更日志或使用 binlog 订阅） |
| `NFR-C-019` | **必须定期对账**（见 [26 章 数据质量](./26-模块17-数据平台.md)）：缓存 vs DB、搜索 vs DB、统计 vs 明细 |
| `NFR-C-020` | **对账偏差超阈值必须告警并自动修复**（如点赞数偏差 > 1% 自动重算） |

### 4.3 典型一致性问题与对策

| 问题 | 场景 | 对策 |
|---|---|---|
| **缓存与 DB 不一致** | 更新 DB 后删缓存失败 | 延迟双删 + 缓存过期兜底 + 对账 |
| **计数不准** | 并发点赞导致计数错误 | Redis 原子计数 + 定期对账重算 |
| **重复数据** | 并发提交产生重复 | 唯一索引 + 幂等键 |
| **丢失更新** | 并发编辑覆盖 | 乐观锁 `version` |
| **主从延迟读到旧数据** | 修改后立即读 | 写后读主 |
| **搜索与 DB 不一致** | 歌曲下架但搜索还能搜到 | MQ 同步 + 定期比对 + 下架时双写删除 |
| **Feed 重复** | 同一条动态多次入收件箱 | ZSet 天然去重（member = postId） |
| **消息重复消费** | MQ 重试导致重复通知 | 幂等键 + 通知去重 |
| **分布式锁失效** | Redis 淘汰锁 key | 锁超时 + DB 兜底 |
| **跨库事务** | 用户服务与房间服务 | 本地消息表 + MQ 最终一致 |
| **AI 生成与事实不符** | LLM 编造歌曲 | 候选集校验（见 [23 章](./23-模块14-AI增强.md)） |
| **时钟不一致** | 多实例时间偏差 | NTP 同步 + 用服务端时间 + 逻辑时钟（版本号） |

### 4.4 一致性验收

- `AC-NFR-C-001`：强一致数据无并发错误（并发测试）
- `AC-NFR-C-002`：缓存与 DB 一致性校验通过
- `AC-NFR-C-003`：计数类数据对账偏差 < 0.1%
- `AC-NFR-C-004`：MQ 消费幂等验证
- `AC-NFR-C-005`：接口幂等验证（重复提交）
- `AC-NFR-C-006`：搜索与 DB 一致性校验
- `AC-NFR-C-007`：推荐特征在线离线一致性
- `AC-NFR-C-008`：Feed 可重建验证
- `AC-NFR-C-009`：写后读一致验证
- `AC-NFR-C-010`：唯一约束兜底生效

| `NFR-O-006` | **CDN 必须优化**：音频格式分级（默认 128k）、强缓存、预热、防盗链、比价 |
| `NFR-O-007` | **AI 必须成本控制**（分级模型、缓存、批处理、预算熔断，见 [23 章](./23-模块14-AI增强.md)） |
| `NFR-O-008` | **存储必须有生命周期**（冷热分离、归档、定期清理） |
| `NFR-O-009` | **日志/监控必须有采样与保留期**（避免存储成本失控） |
| `NFR-O-010` | **数据库必须有优化**（索引优化、慢 SQL 治理、只读实例按需） |
| `NFR-O-011` | **Redis 必须有内存优化**（大 key 治理、合理过期、避免无用数据） |
| `NFR-O-012` | **必须定期清理无用资源**（实例、卷、IP、快照） |
| `NFR-O-013` | **成本优化必须量化**（优化前后对比） |
| `NFR-O-014` | **成本优化不得损害可用性与性能** |
| `NFR-O-015` | **必须月度成本报告**（含趋势、异常、优化建议） |
| `NFR-O-016` | **必须成本归因**（哪个功能/团队花了多少钱） |

### 7.3 成本验收

## 8. 合规需求

### 8.1 法律法规遵循

| 法规 | 要求 | 对应实现 |
|---|---|---|
| **《网络安全法》** | 实名制、日志留存 ≥ 6 个月、安全防护 | 手机号注册；审计日志 2 年；见 [18 章](./18-模块09-管理后台.md) |
| **《个人信息保护法》** | 告知同意、最小必要、可撤回、可删除 | 隐私政策、同意管理、注销删除 |
| **《数据安全法》** | 数据分级、跨境限制 | 数据分级（见 NFR-S-023） |
| **《生成式人工智能服务管理暂行办法》** | AI 生成内容标识、审核 | AI 内容标注（见 [27 章](./27-模块18-内容安全.md)） |
| **《互联网信息服务管理办法》** | 内容审核、违法信息处置 | 内容安全体系（见 [27 章](./27-模块18-内容安全.md)） |
| **《未成年人保护法》** | 未成年人保护 | 青少年模式（见 [27 章](./27-模块18-内容安全.md)） |
| **《著作权法》** | 版权授权、侵权处置 | 版权管理 + 投诉下架（见 [27 章](./27-模块18-内容安全.md)） |
| **《互联网用户账号信息管理规定》** | 账号信息管理、IP 属地 | 昵称审核、IP 属地（**【假设 A-42】**：IP 属地展示按监管要求评估后决定是否上线） |
| **《App 违法违规收集使用个人信息行为认定方法》** | 权限最小化 | 见 8.2 |
| **等保 2.0** | 安全等级保护 | 见 8.3 |

> **免责声明**：本章为**产品与技术层面的合规设计**，不构成法律意见。上线前必须由**法务合规团队**审核，并根据实际运营主体、业务范围、目标市场（是否出海）确定适用法规。

### 8.2 个人信息保护

| 编号 | 要求 |
|---|---|
| `NFR-L-001` | **必须有隐私政策与服务协议**，注册时明示同意（默认不勾选，独立勾选） |
| `NFR-L-002` | **必须遵循最小必要原则**（仅收集必要信息，不收集与功能无关的信息） |

| `NFR-L-004` | **必须支持撤回同意**（用户可关闭个性化推荐、可拒绝对话） |
| `NFR-L-005` | **必须支持数据可携带**（用户可导出自己的数据） |
| `NFR-L-006` | **必须支持账号注销**（且注销后数据按合规处理：删除或匿名化） |

### 8.3 安全等级保护（等保 2.0）

**若运营主体需要等保备案（通常"互联网音乐平台"需要二级或三级）**：

| 层面 | 要求 | 对应实现 |
|---|---|---|
| **安全物理环境** | 机房安全 | 云服务商保障 |
| **安全通信网络** | 网络隔离、加密传输 | VPC、HTTPS、网络隔离 |
| **安全区域边界** | 访问控制、入侵防范 | WAF、防火墙、限流 |
| **安全计算环境** | 身份鉴别、访问控制、数据保护、审计 | JWT、RBAC、加密、审计日志 |
| **安全管理中心** | 集中管控、集中审计 | 日志中心、监控中心 |

## 10. 非功能需求汇总验收

| 类别 | 关键指标 | 验收方式 |
|---|---|---|
| **性能** | 核心接口 P99 达标、5000 QPS 通过 | 压测 + APM |
| **安全** | 无高危漏洞、渗透测试通过 | 扫描 + 渗透测试 |
| **可用性** | 99.95%、MTTR ≤ 15min | 监控统计 + 演练 |
| **一致性** | 对账偏差 < 0.1%、无并发错误 | 对账 + 并发测试 |
| **可扩展性** | 无状态、可水平扩展、模块化 | 架构评审 + 扩容验证 |
| **兼容性** | 4 浏览器 + 移动端、JDK 8 兼容 | 兼容性测试 |
| **成本** | ≤ ¥0.5/DAU/月 | 成本监控 |
| **合规** | 隐私政策、注销、青少年模式 | 合规审查 |
| **可维护性** | 覆盖率 ≥ 60%、CI/CD | 代码统计 |

**非功能需求的整体验收原则**：

1. **非功能需求与功能需求同等重要**，未达标不得上线。
2. **每个版本必须做非功能回归**（性能、安全扫描、兼容性）。
3. **非功能问题优先级**：安全 > 可用性 > 性能 > 成本 > 其他。
4. **非功能需求必须可测量**，不可测量的需求必须转化为可测量的指标。
5. **例外必须有记录与审批**（明确不做的原因与风险接受人）。
