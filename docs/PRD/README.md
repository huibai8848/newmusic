# MusicLive 在线音乐社交平台 — 产品需求文档（PRD）

> **文档版本**：v1.0.0
> **文档状态**：评审稿（Ready for Dev Review）
> **编制日期**：2026-10-12
> **适用工程**：`newmusic`（Spring Boot 2.6.13 / JDK 1.8，Maven `com.example:newmusic`）
> **产品代号**：MusicLive
> **一句话定位**：一个支持在线听歌、AI 搜索与推荐、音乐房实时互动、用户社交互动、内容安全与数据运营的 Web 音乐平台。

---

## 0. 如何阅读本文档

本文档为**开发评审级**需求文档，面向：产品经理、后端工程师、前端工程师、测试工程师、运维/DBA、算法工程师。

### 0.1 文档组织方式

全文按"**总—分—纵**"三层组织：

| 层 | 章节 | 读者 |
|---|---|---|
| **总** | 01 产品概述、02 角色与权限、03 系统架构、04 数据模型、05 通用设计规范 | 全员必读 |
| **分** | 10~28 功能模块规格（19 个模块） | 按模块分工精读 |
| **纵** | 29 非功能需求、30 测试与验收、31 里程碑与排期 | 全员必读 |

### 0.2 需求编号规则

所有需求条目使用全局唯一编号，格式：`{类型}-{模块号}-{序号}`。

| 前缀 | 含义 | 示例 |
|---|---|---|
| `FR` | 功能需求（Functional Requirement） | `FR-14-003` 音乐房禁言 |
| `NFR` | 非功能需求 | `NFR-P-002` 接口 P99 ≤ 300ms（P 性能 / S 安全 / A 可用性 / C 一致性 / E 扩展 / B 兼容 / O 成本 / L 合规 / M 可维护） |
| `BR` | 业务规则（Business Rule） | `BR-14-007` 房主不可被禁言 |
| `AC` | 验收标准（Acceptance Criteria） | `AC-14-003-1` |
| `EX` | 异常场景（Exception） | `EX-14-003-1` |

编号一经分配**不得复用、不得重排**，需求废弃时标记 `[已废弃]` 并保留占位。

### 0.3 优先级定义

| 优先级 | 定义 | 排期要求 | 占比目标 |
|---|---|---|---|
| **P0** | 不做产品无法上线；核心主链路，缺失即阻断 | 必须进入 MVP 版本 | 约 45% |
| **P1** | 强烈影响体验/留存/商业化，可在 MVP 后第一个迭代补齐 | 上线后 1~2 个迭代内 | 约 35% |
| **P2** | 增强型、锦上添花、探索性 | 视资源投入，可延后 | 约 20% |

### 0.4 假设标注约定

凡未经确认的技术选型、第三方依赖、容量参数，均以引用块标注：

> **【假设 A-xx】** 内容……
> **可选方案**：方案一 / 方案二
> **验证方式**：……

假设清单统一登记在 [01-产品概述.md](./01-产品概述.md) 第 9 节，评审时逐条确认。

### 0.5 需求条目标准结构

每个功能点（FR）按以下 **8 要素**展开，缺一不可：

1. **功能目标** — 解决什么问题，衡量什么
2. **使用角色** — 谁能操作
3. **前置条件** — 入口、状态、依赖
4. **操作流程** — 分步骤主流程（Happy Path）
5. **业务规则** — 校验、计算、约束（BR 编号）
6. **异常情况** — 失败分支与兜底（EX 编号）
7. **验收标准** — 可测试的判定条件（AC 编号，Given/When/Then）
8. **优先级** — P0 / P1 / P2

## 2. 版本规划速览（详细见 31 章）

| 版本 | 主题 | 目标 | 预计周期 |
|---|---|---|---|
| **V0.1 骨架** | 工程基建 | 工程分层、统一响应、鉴权、CI、DB 初始化 | 2 周 |

## 3. 关键风险提示（详见 31 章风险登记册）

| 风险 | 影响 | 缓解 |
|---|---|---|
| 音乐**版权**与音频源合法性 | 产品无法对外发布 | 上线前完成版权合规评审；MVP 使用授权曲库/自有素材；预留 `copyright_status` 字段 |
| 大模型 API **成本不可控** | 毛利为负 | 全链路缓存 + 分级模型路由 + 每日预算熔断（见 23 章成本控制） |
| WebSocket **集群一致性** | 房间状态错乱 | Redis 存权威状态 + MQ 广播 + 版本号向量时钟（见 13/14 章） |
| JDK 1.8 / Boot 2.6 **版本天花板** | 部分新库不可用 | 明确依赖白名单（见 03 章技术选型表），预留 Boot 3 升级路径 |
| 搜索/推荐**冷启动** | 新用户首日体验差 | 热门兜底 + 编辑精选 + 新用户问卷（见 24 章冷启动） |
