## 1. 模块目标

1. 提供**稳定、低延迟、跨页面不中断**的音频播放体验。
2. 提供**与音频精确同步**的歌词展示（含逐行与逐字）。
3. 完整记录播放行为，为推荐与运营提供数据基础。

**衡量指标**：

| 指标 | 目标 |
|---|---|
| 播放起播时间（点击→出声） | ≤ 1.5s（P95，缓存命中 ≤ 500ms） |
| 播放中断率（异常停止/总播放） | ≤ 0.5% |
| 歌词同步偏差 | ≤ 200ms（P95） |
| 播放失败率 | ≤ 0.3% |
| 切歌响应时间 | ≤ 300ms |
| 播放状态上报成功率 | ≥ 99.9% |

## 4. 播放核心

### FR-16-001 播放/暂停/切歌 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 基础播放控制，操作响应 < 300ms |
| **使用角色** | 全部（游客受限） |
| **前置条件** | 歌曲有可播放音源且版权状态允许 |

**操作流程**：

```
用户点击歌曲（列表/详情/搜索/歌单/房间）
   ↓
[1] 前置校验
     - 歌曲存在且 status=1
     - copyright_status=1（否则提示"该歌曲暂无版权"）
     - 游客试听配额未耗尽（BR-16-002）
   ↓
[2] 更新播放器状态（Zustand，乐观更新，立即 UI 反馈）
     - 立即渲染歌曲信息、封面、歌词占位
     - audio.src 设置为音频 URL
   ↓
[3] 获取播放地址
     - 请求 GET /api/v1/play/url?songId=xxx&quality=standard
     - 返回带签名的 CDN URL（防盗链，见 BR-16-010）
   ↓
[4] 加载音频
     - audio.load() → canplay 事件 → audio.play()
     - 加载中显示 loading 状态（封面旋转 / 进度环）
   ↓
[5] 播放开始（timeupdate / playing 事件）
     - 上报播放开始（异步，不阻塞）
     - 开始歌词滚动
   ↓
用户点击暂停 → audio.pause() → 状态变 paused
用户点击下一首 → 计算下一首（依播放模式）→ 回到 [1]
用户点击上一首 → 计算上一首（依播放模式）→ 回到 [1]
```

**播放控制接口清单**：

| 操作 | 触发 | 前端行为 |
|---|---|---|
| 播放 | 点击/双击歌曲 | 加载并播放 |
| 暂停 | 点击播放按钮 | `audio.pause()` |
| 继续 | 再次点击 | `audio.play()` |
| 上一首 | 点击/MediaSession | 按模式计算上一首 |
| 下一首 | 点击/MediaSession | 按模式计算下一首 |
| 拖动进度 | 拖进度条 | 设置 `currentTime` |
| 音量 | 滑块 | 设置 `volume`（0~1） |
| 静音 | 点击喇叭 | `muted` 切换 |

**业务规则**：

- `BR-16-001`：播放器状态**必须**由 Zustand 单一数据源管理，组件通过 selector 订阅，避免重复渲染。
- `BR-16-002`：**游客试听限制**：每首 30 秒，每日 10 首。播放到 30 秒时暂停并提示"试听结束，登录后可听完整版"。配额存 `ml:guest:preview:{deviceId}:{yyyyMMdd}`（Hash: songId → 已播放秒数，TTL 到次日 0 点）。
- `BR-16-003`：**无版权歌曲**（`copyright_status=2`）不返回播放地址，提示"该歌曲暂无版权，为你推荐相似歌曲"。
- `BR-16-004`：**下架歌曲**（`status=0`）不可播放。
- `BR-16-005`：切歌时**必须**先 `pause()` 再换 `src` 再 `play()`，避免音轨重叠。
- `BR-16-006`：播放请求**必须**带 `traceId`，便于链路追踪。
- `BR-16-007`：**跨页面不中断**：`<audio>` 挂在 `MainLayout`，路由切换不销毁（见 [11 章](./11-模块02-前端界面.md)）。
- `BR-16-008`：同一时刻**只能**有一首歌曲在播放（全局单实例 audio）。
- `BR-16-009`：切歌时**立即**更新 UI（乐观），音源加载失败再回滚并提示。
- `BR-16-010`：**播放地址签名**：URL 带 `expires` 与 `sign`（HMAC-SHA256），有效期 **2 小时**，防盗链。签名在服务端生成：
  ```
  sign = HMAC_SHA256(secret, path + "|" + expires + "|" + userId)
  url  = https://cdn.example.com/audio/xxx.mp3?expires=1730000000&sign=abc...
  ```
- `BR-16-011`：**并发限制**：同一用户最多同时 3 个播放会话（防共享账号），超出则踢掉最早的会话。会话存 `ml:play:session:{userId}`（Set: sessionId，TTL 2h）。
- `BR-16-012`：**播放上报去重**：同一歌曲 5 秒内重复上报只计一次。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-16-001-1` | 音频加载失败（404/超时） | 重试 2 次（换备用 CDN）→ 仍失败提示"播放失败，请稍后重试"，自动切下一首 |
| `EX-16-001-2` | 浏览器自动播放策略阻止 | 首次播放需用户交互；若被阻止提示"点击播放" |
| `EX-16-001-3` | 版权校验失败 | `80006`，提示"该歌曲暂无版权" |
| `EX-16-001-4` | 游客试听额度用尽 | `80007`，提示登录 |
| `EX-16-001-5` | 网络中断 | 暂停播放，显示"网络异常"，网络恢复后提示"是否继续播放" |
| `EX-16-001-6` | 音频解码错误 | 记录错误日志（含歌曲 ID、编码格式），跳过该曲 |
| `EX-16-001-7` | 并发会话超限 | 踢掉最早会话，提示"你的账号在其他设备播放" |
| `EX-16-001-8` | 签名过期（播放中） | 提前 5 分钟预刷新 URL（仅在切歌时生效，播放中不中断） |
| `EX-16-001-9` | 歌曲在播放中被下架 | 允许播完当前曲，下一首不再播放该曲 |

**验收标准**：

- `AC-16-001-1`：点击歌曲后 1.5s 内出声（缓存命中 ≤ 500ms）
- `AC-16-001-2`：切歌响应 ≤ 300ms（UI 反馈）
- `AC-16-001-3`：路由切换播放不中断
- `AC-16-001-4`：无版权歌曲不可播放且有提示
- `AC-16-001-5`：游客播放 30 秒后暂停并提示登录
- `AC-16-001-6`：音频 404 时自动切下一首
- `AC-16-001-7`：播放地址超过 2 小时失效
- `AC-16-001-8`：同账号第 4 个会话踢掉第 1 个

### FR-16-002 播放模式 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 提供多种播放顺序策略 |
| **使用角色** | 全部 |

**模式定义**：

| 模式 | 常量 | 行为 |
|---|---|---|
| 列表循环 | `LIST_LOOP`（默认） | 顺序播放，最后一首后回到第一首 |
| 单曲循环 | `SINGLE_LOOP` | 当前曲播完重播 |
| 随机播放 | `SHUFFLE` | 随机顺序，**不重复**直到全播完（洗牌算法） |
| 顺序播放 | `ORDER` | 顺序播放，最后一首后**停止** |

**下一首计算算法**：

```typescript
function getNextSong(state: PlayerState): Song | null {
  const { playlist, currentIndex, mode, shuffleOrder } = state;
  if (playlist.length === 0) return null;

  switch (mode) {
    case 'SINGLE_LOOP':
      return playlist[currentIndex];               // 重播当前

    case 'LIST_LOOP':
      return playlist[(currentIndex + 1) % playlist.length];

    case 'ORDER':
      return currentIndex + 1 < playlist.length
        ? playlist[currentIndex + 1]
        : null;                                    // 到底停止

    case 'SHUFFLE': {
      // shuffleOrder 是播放列表索引的洗牌数组
      const pos = shuffleOrder.indexOf(currentIndex);
      const nextPos = (pos + 1) % shuffleOrder.length;
      if (nextPos === 0 && !state.shuffleReplay) {
        // 一轮播完，重新洗牌并继续
        state.shuffleOrder = shuffle([...Array(playlist.length).keys()]);
        state.shuffleReplay = true;
      }
      return playlist[shuffleOrder[nextPos]];
    }
  }
}
```

**洗牌算法（Fisher-Yates）**：

```typescript
function shuffle<T>(arr: T[]): T[] {
  const a = [...arr];
  for (let i = a.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1));
    [a[i], a[j]] = [a[j], a[i]];
  }
  return a;
}
```

**业务规则**：

- `BR-16-013`：播放模式**持久化**到 `localStorage`（Key: `ml_player_mode`），刷新后保持。
- `BR-16-014`：随机播放**必须**使用洗牌数组而非每次随机索引，避免同一首重复出现。
- `BR-16-015`：切换播放列表时**重新洗牌**（`shuffleOrder` 重建）。
- `BR-16-016`：单曲循环时点击"下一首"仍**切换**到下一首（不重播当前）。
- `BR-16-017`：顺序播放到底后**停止**，不自动循环。
- `BR-16-018`：模式切换**立即生效**于下一次切歌，不打断当前播放。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-16-002-1` | 播放列表为空 | 切歌无操作 |
| `EX-16-002-2` | 列表仅 1 首 + 顺序播放 | "下一首"按钮置灰 |
| `EX-16-002-3` | `shuffleOrder` 与列表长度不符（列表变更） | 重建 `shuffleOrder` |
| `EX-16-002-4` | localStorage 不可用 | 使用内存默认值 LIST_LOOP |

**验收标准**：

- `AC-16-002-1`：4 种模式行为正确
- `AC-16-002-2`：随机播放一轮内不重复
- `AC-16-002-3`：刷新页面后播放模式保持
- `AC-16-002-4`：单曲循环时点下一首会切歌

### FR-16-003 播放列表与队列 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 管理当前播放队列 |
| **使用角色** | 全部 |

**队列模型**：

```typescript
interface PlayerState {
  // 当前播放列表（用户"设为播放列表"的结果）
  playlist: Song[];
  currentIndex: number;
  // 播放模式
  mode: PlayMode;
  shuffleOrder: number[];
  shuffleReplay: boolean;
  // 播放状态
  isPlaying: boolean;
  currentTime: number;
  duration: number;
  volume: number;
  muted: boolean;
  // 加载状态
  loadState: 'idle' | 'loading' | 'ready' | 'error';
  // 当前歌曲
  currentSong: Song | null;
  // 房间模式（房间内播放由服务端权威控制）
  roomMode: boolean;
  roomId: string | null;
  roomVersion: number;
}
```

**队列操作**：

| 操作 | 说明 | 影响 currentIndex |
|---|---|---|
| 播放歌曲（单击） | **替换**整个队列为当前上下文列表 | 重置为点击项 |
| 下一首播放（加入队列） | **插入**到当前歌曲之后 | 若插入位置 ≤ currentIndex 则 +1 |
| 添加到队列末尾 | 追加到 `playlist` 末尾 | 不变 |
| 从队列移除 | 移除指定项 | 若移除项 < currentIndex 则 -1；若 = currentIndex 则播下一首 |
| 清空队列 | 清空 `playlist` | 停止播放 |
| 上移/下移 | 调整队列顺序 | 跟随调整 |

**业务规则**：

- `BR-16-019`：**单击播放**的上下文列表来自**当前页面**（搜索结果列表、歌单列表、专辑歌曲列表等），点击哪首就以哪首为起点。
- `BR-16-020`：**双击/点"+"** 表示"下一首播放"，插入队列。
- `BR-16-021`：队列**不持久化**到 localStorage（每次刷新重置），但**当前歌曲与进度**持久化（见 FR-16-008）。
  - **理由**：队列可能含大量数据且与页面上下文强相关，持久化意义不大；但"上次听到哪"体验重要。
- `BR-16-022`：队列**上限 500 首**，超出提示"播放列表已满"。
- `BR-16-023`：从队列移除**当前播放**的歌曲时，自动播放下一首。
- `BR-16-024`：队列中的歌曲**不重复校验**（允许同一首歌多次出现，用户可能故意添加）。
- `BR-16-025`：播放队列**UI 面板**为抽屉（Drawer），从底部滑出，展示封面缩略图 + 歌名 + 歌手 + 时长 + 操作按钮。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-16-003-1` | 队列为空时播放 | 无操作 |
| `EX-16-003-2` | 队列超 500 首 | `80008`，提示已满 |
| `EX-16-003-3` | 移除当前播放曲 | 自动播下一首 |
| `EX-16-003-4` | 队列中歌曲已下架 | 播放时跳过并提示，自动切下一首 |

**验收标准**：

- `AC-16-003-1`：单击歌曲替换队列并以该曲为起点
- `AC-16-003-2`："下一首播放"正确插入
- `AC-16-003-3`：队列面板操作实时反映
- `AC-16-003-4`：移除当前播放曲后自动播下一首
- `AC-16-003-5`：队列上限 500 生效

### FR-16-004 播放历史 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 记录并展示用户听歌历史 |
| **使用角色** | 登录用户（游客本地记录） |

**记录策略**：

```
播放开始时上报（异步，不阻塞播放）
   ↓
POST /api/v1/play/record
{ "songId": "1857...", "quality": "standard", "source": "search", "roomId": null, "playId": "uuid" }
   ↓
服务端：
  1. 写 t_play_history（异步 MQ，批量刷盘）
  2. ZINCRBY ml:play:user:{userId}:recent（ZSet，score=时间戳，member=songId）
  3. 播放计数：INCR ml:play:count:{songId}
  4. 上报埋点（见第 10 节）
```

**有效播放判定**：

```
有效播放（计入统计）= 播放时长 ≥ 30 秒 或 播放比例 ≥ 60%
```

**业务规则**：

- `BR-16-026`：历史**保留最近 500 条**（Redis ZSet 只保留 500 个 member，`ZREMRANGEBYRANK`）。
- `BR-16-027`：历史按**时间倒序**展示，同一首歌多次播放**只显示最近一次**（去重），但 `t_play_history` 保留全部记录。
- `BR-16-028`：历史**分页加载**（每页 30 条）。
- `BR-16-029`：用户可**删除单条**或**清空全部**历史。清空为**软删除**（`is_deleted=1`），实际数据保留用于推荐（匿名字段）。
- `BR-16-030`：`t_play_history` **按月分表**（`t_play_history_202610`），历史数据保留 **6 个月**，之后归档到 ClickHouse（见 [26 章](./26-模块17-数据平台.md)）。
- `BR-16-031`：播放上报**批量写入**：客户端每 30 秒或切歌时上报一次，服务端用 MQ 聚合批量入库（每 500 条或 1 秒 flush 一次）。
- `BR-16-032`：**游客**播放历史存 `localStorage`（最多 100 条）。
- `BR-16-033`：历史中的歌曲若已下架，展示但标记"已下架"且不可播放。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-16-004-1` | 上报接口失败 | 前端重试 2 次（指数退避），仍失败则丢弃（不阻塞播放） |
| `EX-16-004-2` | 网络离线 | 缓存到 localStorage，网络恢复后批量补报（最多 200 条） |
| `EX-16-004-3` | Redis 不可用 | 直接写 MySQL（降级，性能下降） |
| `EX-16-004-4` | 分表不存在（跨月首日） | 自动建表（定时任务提前 1 天建下月表） |

**验收标准**：

- `AC-16-004-1`：播放后 5 秒内历史可查
- `AC-16-004-2`：历史同一首歌去重显示最近一次
- `AC-16-004-3`：历史最多 500 条（Redis）/ 分页可查全部（MySQL）
- `AC-16-004-4`：清空历史后列表为空
- `AC-16-004-5`：播放上报失败不影响播放

### FR-16-005 进度控制与记忆 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 精确进度控制 + 断点续播 |
| **使用角色** | 全部（登录用户跨设备） |

**进度条交互**：

| 交互 | 行为 |
|---|---|
| 拖动进度条（pointerdown → pointermove） | 实时更新**显示**进度，不改变播放位置；显示预览时间气泡 |
| 释放（pointerup） | 设置 `audio.currentTime`，**立即**同步 |
| 键盘 ← / → | 后退/前进 5 秒 |
| 键盘 Shift + ← / → | 后退/前进 30 秒 |
| 点击进度条 | 跳转到点击位置 |

**拖动期间的处理**：

```typescript
// 关键：拖动时暂停 timeupdate 驱动 UI，避免跳动
const [isDragging, setIsDragging] = useState(false);
const [dragValue, setDragValue] = useState(0);

// 拖动中不更新 currentTime 显示
const displayTime = isDragging ? dragValue : player.currentTime;

function onPointerUp() {
  audio.currentTime = dragValue;
  setIsDragging(false);
  // 拖动结束后强制同步一次
}
```

**断点续播**：

```typescript
// 持久化（localStorage）
{
  "ml_last_play": {
    "songId": "1857...",
    "position": 62.5,
    "playlistSource": "playlist:123456",
    "updatedAt": 1730000000000,
    "userId": "1857..."      // 用于区分账号

}

//   POST /api/v1/play/progress  { songId, position, quality }
```

**业务规则**：

- `BR-16-034`：进度条**必须**支持**拖动预览**（不改变实际播放位置直到释放）。

### FR-16-007 LRC 歌词解析与展示 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 精确解析 LRC 并在正确时间展示与滚动 |
| **使用角色** | 全部 |

**LRC 格式支持**：

```
[ti:晴天]
[ar:周杰伦]
[al:叶惠美]
[by:某某]
[offset:0]
[00:00.00]<前奏>
[00:12.50]故事的小黄花
[00:15.80]从出生那年就飘着
[00:19.20]童年的荡秋千
[01:02.00][02:15.00]随记忆一直晃到现在     ← 多时间标签（重复段落）
```

**解析实现**：

```typescript
interface LyricLine {
  time: number;       // 秒
  text: string;
  translation?: string;   // 翻译（如有）
  romaji?: string;        // 罗马音（如有）
}

interface ParsedLyric {
  meta: {
    title?: string; artist?: string; album?: string; by?: string; offset: number;
  };
  lines: LyricLine[];
  hasTranslation: boolean;
  hasWordLevel: boolean;
}

const TIME_TAG = /\[(\d{1,3}):(\d{1,2})(?:[.:](\d{1,3}))?\]/g;
const META_TAG = /^\[(ti|ar|al|by|offset|length):(.*)\]$/;

function parseLrc(raw: string): ParsedLyric {
  const lines: LyricLine[] = [];
  const meta: any = { offset: 0 };

  for (const rawLine of raw.split(/\r?\n/)) {
    const line = rawLine.trim();
    if (!line) continue;

    const metaMatch = line.match(META_TAG);
    if (metaMatch) {
      const key = metaMatch[1];
      const value = metaMatch[2].trim();
      if (key === 'offset') meta.offset = parseInt(value, 10) || 0;
      else meta[key] = value;
      continue;
    }

    // 一行可能有多个时间标签
    const tags = [...line.matchAll(TIME_TAG)];
    if (tags.length === 0) continue;

    const text = line.replace(TIME_TAG, '').trim();
    if (!text) continue;

    for (const tag of tags) {
      const min = parseInt(tag[1], 10);
      const sec = parseInt(tag[2], 10);
      const ms  = tag[3] ? parseInt(tag[3].padEnd(3, '0'), 10) : 0;
      lines.push({ time: min * 60 + sec + ms / 1000, text });
    }
  }

  lines.sort((a, b) => a.time - b.time);
  return { meta, lines, hasTranslation: false, hasWordLevel: false };
}
```

**时间补偿**：

```
实际展示时间 = 歌词时间 - offset/1000 + 用户偏移校准
其中 offset 来自 LRC 的 [offset:] 标签（毫秒，正值表示歌词提前）
```

**当前行定位（二分查找）**：

```typescript
function findCurrentLine(lines: LyricLine[], currentTime: number): number {
  let lo = 0, hi = lines.length - 1, ans = -1;
  while (lo <= hi) {
    const mid = (lo + hi) >> 1;
    if (lines[mid].time <= currentTime) { ans = mid; lo = mid + 1; }
    else hi = mid - 1;
  }
  return ans;   // -1 表示前奏
}
```

**业务规则**：

- `BR-16-051`：歌词解析在**前端**进行（减少服务端压力），后端 `t_lyric` 存原始 LRC 文本。
- `BR-16-052`：歌词**必须**支持**多时间标签**（`[01:02.00][02:15.00]同一句`）。
- `BR-16-053`：歌词**必须**支持 `[offset:]` 补偿。
- `BR-16-054`：歌词查找**必须**用**二分查找**（O(log n)），禁止线性扫描（每帧调用）。
- `BR-16-055`：当前行**居中高亮**，`transform: translateY()` 平滑滚动（不用 `scrollTop` 逐帧设置，避免抖动）。
- `BR-16-056`：无歌词时显示"暂无歌词"，并尝试展示歌曲信息（歌手、专辑、发行时间）。

**解析实现（方案 C）**：

```typescript
interface WordSegment {
  text: string;
  startTime: number;   // 秒
  endTime: number;     // 秒
}

interface LyricLine {
  time: number;
  text: string;
  words?: WordSegment[];   // 逐字信息
  translation?: string;
}

const WORD_TAG = /<(\d{1,3}):(\d{1,2})(?:[.:](\d{1,3}))?>/g;

function parseWordLevel(text: string, lineTime: number): WordSegment[] | undefined {
  const tags = [...text.matchAll(WORD_TAG)];
  if (tags.length === 0) return undefined;

  const segments: WordSegment[] = [];
  for (let i = 0; i < tags.length; i++) {
    const tag = tags[i];
    const start = toSeconds(tag);
    const end = i + 1 < tags.length ? toSeconds(tags[i + 1]) : lineTime + 5; // 末字默认 5 秒
    const textStart = tag.index! + tag[0].length;
    const textEnd = i + 1 < tags.length ? tags[i + 1].index! : text.length;
    const wordText = text.slice(textStart, textEnd);
    if (wordText) segments.push({ text: wordText, startTime: start, endTime: end });
  }
  return segments.length > 0 ? segments : undefined;
}
```

**业务规则**：

- `BR-16-068`：用户校准偏移**范围限制** `[-30s, +30s]`（超出视为误操作）。
- `BR-16-069`：用户偏移**叠加在** LRC 内建 offset 之上：`最终 = LRC offset + 用户 offset`。
- `BR-16-070`：用户偏移**仅对自己生效**，不影响其他用户。
- `BR-16-071`：本地偏移**立即生效**，服务端同步**异步**（失败不影响本地）。
- `BR-16-072`：提供"重置"按钮恢复为 0。
- `BR-16-073`：运营后台可**全局**修正某首歌的歌词偏移（写回 `t_lyric.offset`，影响所有用户）。若某首歌的用户校准率 > 30% 且方向一致，**提示运营**修正。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-16-009-1` | 偏移值非法（NaN/超范围） | 拒绝，重置为 0 |
| `EX-16-009-2` | 服务端同步失败 | 静默失败，保留本地偏移 |
| `EX-16-009-3` | 未登录用户 | 仅本地保存 |

**验收标准**：

- `AC-16-009-1`：调整偏移后歌词立即跟随
- `AC-16-009-2`：刷新页面后偏移保持
- `AC-16-009-3`：偏移范围被限制在 ±30s
- `AC-16-009-4`：重置按钮生效

### FR-16-012 播放失败重试与容错 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 音频加载失败时自动恢复，不中断体验 |
| **使用角色** | 全部 |

**错误类型与处理**：

| `audio.error.code` | 含义 | 处理 |
|---|---|---|
| `1 ABORTED` | 用户中止 | 不处理（正常） |
| `2 NETWORK` | 网络错误 | 重试 2 次（间隔 1s、3s）→ 换备用 CDN 重试 1 次 → 仍失败切下一首 |
| `3 DECODE` | 解码失败 | 不重试（源文件问题），切下一首 + 上报错误 |
| `4 SRC_NOT_SUPPORTED` | 格式不支持 | 尝试降级音质（如从无损降为标准）→ 仍失败切下一首 |

**重试实现**：

```typescript
class PlaybackRecovery {
  private retryCount = 0;
  private readonly MAX_RETRY = 2;
  private readonly BACKOFF = [1000, 3000];
  private readonly CDN_FALLBACKS = ['https://cdn1.example.com', 'https://cdn2.example.com'];

  async onError(err: MediaError): Promise<void> {
    metrics.playErrorTotal.labels({ code: String(err.code) }).inc();

    if (err.code === MediaError.MEDIA_ERR_ABORTED) return;

    if (err.code === MediaError.MEDIA_ERR_DECODE) {
      // 解码错误：不重试，跳过
      log.error('Audio decode error, skipping: songId={}', this.currentSongId);
      this.next();
      return;
    }

    if (this.retryCount < this.MAX_RETRY) {
      const delay = this.BACKOFF[this.retryCount];
      this.retryCount++;
      log.warn('Playback failed, retry {}/{} after {}ms', this.retryCount, this.MAX_RETRY, delay);
      await sleep(delay);
      this.reload();     // 保持 currentTime
      return;
    }

    // 换备用 CDN
    if (this.cdnIndex < this.CDN_FALLBACKS.length - 1) {
      this.cdnIndex++;
      log.warn('Switching to fallback CDN: {}', this.CDN_FALLBACKS[this.cdnIndex]);
      this.switchCdn();
      this.retryCount = 0;
      return;
    }

    // 全部失败
    toast.error('播放失败，已为你切换下一首');
    metrics.playSkipTotal.inc();
    this.next();
  }

  private async reload(): Promise<void> {
    const position = this.audio.currentTime;   // 保留进度
    this.audio.load();
    await once(this.audio, 'canplay');
    this.audio.currentTime = position;
    await this.audio.play().catch(() => { /* 自动播放策略阻止，等待用户交互 */ });
  }
}
```

**业务规则**：

- `BR-16-086`：重试**必须**保留**播放进度**（`currentTime`），不从头开始。
- `BR-16-087`：**解码错误不重试**（源文件问题，重试无意义）。
- `BR-16-088`：重试**必须**有退避（1s、3s），避免雪崩。
- `BR-16-089`：连续 **3 首**歌曲播放失败 → 停止自动切歌，提示"网络异常，请检查网络"（避免无限循环）。
- `BR-16-090`：播放错误**必须**上报监控（`songId`、`error code`、`cdn`、`quality`、`network type`）。
- `BR-16-091`：CDN 切换**必须**通过重新请求播放地址（带新 CDN 域名）实现。
- `BR-16-092`：**卡顿检测**：若 `waiting` 事件持续 > 5s，显示"缓冲中..."，> 15s 则自动降质（P1）。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-16-012-1` | 所有重试与 CDN 都失败 | 切下一首 + 提示 |
| `EX-16-012-2` | 连续 3 首失败 | 停止自动切歌，提示检查网络 |
| `EX-16-012-3` | 播放地址签名过期 | 重新请求播放地址（一次） |
| `EX-16-012-4` | 网络恢复 | 提示"网络已恢复，是否继续播放" |
| `EX-16-012-5` | 缓冲超时 | 降质重试（P1） |

**验收标准**：

- `AC-16-012-1`：网络错误自动重试并保留进度
- `AC-16-012-2`：解码错误直接切下一首（不重试）
- `AC-16-012-3`：连续 3 首失败后停止自动切歌
- `AC-16-012-4`：播放错误上报到监控
- `AC-16-012-5`：CDN 切换后播放恢复

## 9. 前端性能要求

| 项 | 要求 |
|---|---|
| 播放条渲染 | 不引起整页重渲染（`React.memo` + Zustand selector 精确订阅） |

| 音频预加载 | 下一首 `preload="auto"`（播放列表模式下预加载下一首元数据） |
| 内存 | 及时 `revokeObjectURL`（若有本地 blob），释放 audio.src |
| 长列表 | 播放队列用 `react-window` 虚拟滚动（> 100 首时） |

**Zustand 精确订阅示例**：

```typescript
// ❌ 差：整对象订阅，任何字段变化都重渲染
const player = usePlayerStore();

// ✅ 好：仅订阅需要的字段
const currentSong = usePlayerStore(s => s.currentSong);
const isPlaying    = usePlayerStore(s => s.isPlaying);

// ✅ 好：多字段用 shallow 比较
const { isPlaying, volume } = usePlayerStore(
  useShallow(s => ({ isPlaying: s.isPlaying, volume: s.volume }))
);
```
