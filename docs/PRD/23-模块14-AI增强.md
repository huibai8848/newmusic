## 1. 模块目标

用 AI 增强内容理解与用户创作能力，**同时严格控制成本**（AI 是本项目最大的可变成本）。

**衡量指标**：

| 指标 | 目标 |
|---|---|
| AI 日成本 | ≤ 预算（可配置，默认 100 元/天） |
| AI 调用缓存命中率 | ≥ 60% |
| 歌词翻译可用率 | ≥ 95% |
| 情绪识别准确率（人工抽检） | ≥ 80% |
| AI 歌单生成成功率 | ≥ 95% |
| AI 功能降级可用率 | 100%（任一 AI 不可用不影响主流程） |
| AI 调用 P95 延迟 | ≤ 3s（在线） / 无要求（离线批处理） |

## 4. AI 统一框架

### FR-23-001 AI 调用网关 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 统一所有 AI 调用的入口，实现路由、缓存、限流、成本、降级 |
| **使用角色** | 系统内部 |

**统一网关架构**：

```
业务方调用 AiGateway.chat(request)
   ↓
[1] 请求指纹计算：fingerprint = sha256(model + prompt + params)
   ↓
[2] 缓存查询：ml:ai:cache:{fingerprint}
     命中 → 返回缓存内容（记 fromCache = true，成本 0）
   ↓
[3] 预算检查：AiBudgetGuard.checkBudget()
     超预算 → 抛 AI_QUOTA_EXCEEDED → 业务降级
   ↓
[4] 限流检查：用户级 + 全局级（见下）
   ↓
[5] 模型路由：根据 scene + 用户等级 + 成本策略选择模型
   ↓
[6] 调用 LLM（带超时、重试）
   ↓
[7] 结果校验（JSON Schema / 长度 / 安全）
   ↓
[8] 写缓存（TTL 按 scene 配置）
   ↓
[9] 记录成本：t_ai_call_log（场景、模型、token、成本、耗时、用户、结果）
   ↓
[10] 埋点上报
```

**`AiGateway` 核心接口**：

```java
public interface AiGateway {

    /** 纯文本生成 */
    AiResponse<String> chat(AiRequest request);

    /** 结构化输出（JSON Schema 校验） */
    <T> AiResponse<T> chatStructured(AiRequest request, Class<T> clazz);

    /** 批量（一次调用处理多条，降本） */
    <T> AiResponse<List<T>> chatBatch(AiRequest request, Class<T> clazz);

    /** 文本向量 */
    AiResponse<float[]> embed(String text, String scene);
}

@Data
@Builder
public class AiRequest {
    private String scene;              // 场景：LYRIC_TRANS / EMOTION / PLAYLIST_GEN / SEARCH_PARSE ...
    private String systemPrompt;
    private String userPrompt;
    private List<ChatMessage> history; // 多轮对话（可选）
    private Double temperature;        // 默认 0.7
    private Integer maxTokens;         // 默认 1024
    private Long timeoutMs;            // 默认 3000
    private Boolean jsonMode;          // 是否要求 JSON 输出
    private String cacheKey;           // 自定义缓存键（覆盖默认指纹）
    private Duration cacheTtl;         // 缓存时长（null = 不缓存）
    private String userId;             // 用于限流与成本归因
    private String modelLevel;         // SMALL / MEDIUM / LARGE（模型档位）
}
```

**模型路由策略**：

| 档位 | 模型（示例） | 成本 | 适用场景 |
|---|---|---|---|
| `SMALL` | qwen-turbo / gpt-4o-mini 级 | 低 | 意图识别、关键词抽取、简单分类 |
| `MEDIUM` | qwen-plus / gpt-4o 级 | 中 | 歌词翻译、情绪识别、摘要 |
| `LARGE` | qwen-max / claude-sonnet 级 | 高 | 推荐精排、复杂创作（歌单生成） |

**场景 → 档位映射（`t_sys_config` 可配）**：

| 场景 | 档位 | 缓存 TTL | 超时 | 最大 Token |
|---|---|---|---|---|
| `SEARCH_PARSE` | SMALL | 1h | 2s | 512 |
| `SEARCH_EXPLAIN` | SMALL | 1h | 2s | 256 |
| `LYRIC_TRANS` | MEDIUM | 永久 | 5s | 2048 |
| `LYRIC_SUMMARY` | MEDIUM | 永久 | 5s | 512 |
| `EMOTION_TAG` | SMALL | 永久 | 3s | 256 |
| `PLAYLIST_GEN` | LARGE | 24h | 10s | 2048 |
| `REC_RERANK` | LARGE | 不缓存 | 5s | 1024 |
| `HUM_DETECT` | 专用服务 | 不缓存 | 10s | — |
| `AUDIT` | SMALL/MEDIUM | 不缓存 | 3s | 512 |

**限流策略**：

| 层级 | 限制 | 说明 |
|---|---|---|
| 用户级 | 见各功能（如 AI 搜索 20 次/小时） | 防单用户滥用 |
| 全局级 | 全局 QPS 上限（如 50 QPS） | 保护 LLM 与成本 |
| 场景级 | 各场景独立 QPS | 防单场景挤占 |
| 预算级 | 日成本上限 | 最终熔断 |

**业务规则**：

- `BR-23-001`：**所有 AI 调用必须**经过 `AiGateway`（禁止业务代码直接调 LLM SDK）。
- `BR-23-002`：**必须**有缓存（除明确不缓存的场景如推荐精排）。
- `BR-23-003`：**必须**记录成本（每次调用记录 input/output token 与折算成本）。
- `BR-23-004`：**必须**有超时（默认 3s，可配）。
- `BR-23-005`：**必须**有降级路径（每个 AI 功能定义降级行为）。
- `BR-23-006`：**必须**支持**多模型可插拔**（通过配置切换，不硬编码）。
- `BR-23-007`：**必须**支持**批量调用**（一次处理多条，降低调用次数）。
- `BR-23-008`：**Prompt 版本化**：每个场景的 Prompt 有版本号，记录到调用日志。
- `BR-23-009`：**AI 输出必须校验**（JSON Schema、长度、敏感词）。
- `BR-23-010`：**AI 输出必须过内容审核**（AI 也可能生成违规内容）。
- `BR-23-011`：**成本记录精确到分**，按场景/模型/用户维度可聚合。
- `BR-23-012`：**必须**有实时成本监控与告警（80% 预算告警，100% 熔断）。
- `BR-23-013`：**模型降级**：LARGE 模型失败/超时 → 降级到 MEDIUM → SMALL → 规则兜底。
- `BR-23-014`：**缓存 Key 必须**包含模型与 Prompt 版本（模型升级后缓存自动失效）。
- `BR-23-015`：**离线任务优先**：可离线的 AI 任务（歌词翻译、情绪识别）**走离线批处理**，成本更低（可用更便宜的批处理 API）且不影响在线延迟。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-23-001-1` | LLM 超时 | 重试 1 次（换模型档位降级），仍失败走降级 |
| `EX-23-001-2` | 预算超限 | 熔断全站 AI（除安全审核），业务降级 |
| `EX-23-001-3` | 缓存不可用 | 仍调用 LLM（成本上升），告警 |
| `EX-23-001-4` | 输出校验失败 | 重试 1 次，仍失败走降级 |
| `EX-23-001-5` | 输出含敏感词 | 拦截，记录，返回降级内容 |
| `EX-23-001-6` | 成本记录写入失败 | 记本地日志，不阻断业务，异步补写 |
| `EX-23-001-7` | 主模型不可用 | 自动切备用模型（配置多个） |
| `EX-23-001-8` | 全局 QPS 超限 | 排队（带超时）或降级 |

**验收标准**：

- `AC-23-001-1`：所有 AI 调用经网关（代码审查 + 埋点验证）
- `AC-23-001-2`：缓存命中率 ≥ 60%
- `AC-23-001-3`：成本记录完整准确
- `AC-23-001-4`：模型可配置切换
- `AC-23-001-5`：超时可控且降级正常
- `AC-23-001-6`：批量调用降低调用次数
- `AC-23-001-7`：预算熔断生效
- `AC-23-001-8`：输出经审核

## 5. 歌词翻译

### FR-23-002 歌词翻译与音译 【P1】

| 项 | 内容 |
|---|---|
| **功能目标** | 为外币歌曲生成中文翻译与罗马音 |
| **使用角色** | 全部 |

**处理流程**：

```
用户点击"翻译"（或系统预生成热门歌曲）
   ↓
[1] 检查缓存：ml:ai:lyric:trans:{songId}:{targetLang}
     命中 → 直接返回
   ↓
[2] 获取歌词（t_lyric.lrc）
   ↓
[3] 解析歌词行（去除时间标签，保留结构）
   ↓
[4] 批量翻译（一次请求翻译多行，降低调用次数与成本）
     Prompt 设计（关键）：
     - 输入：JSON 数组的歌词行（带索引）
     - 输出：JSON 数组的翻译（带相同索引，保证对齐）
     - 要求：保持语序自然、保留情感、不添加解释
   ↓
[5] 校验：返回行数必须与输入一致（否则视为失败）
   ↓
[6] 重新组装为 LRC（相同时间标签 + 翻译文本）
   ↓
[7] 保存到 t_lyric.translation
   ↓
[8] 返回
```

**翻译 Prompt（关键设计）**：

```
System:
你是一位专业的歌词翻译。请将以下歌词翻译为{目标语言}，要求：
1. 保持原文的情感与意境，译文自然流畅
2. 不要添加任何解释、注释或括号内容
3. 保持每行的对应关系：输入 N 行，输出必须恰好 N 行
4. 输出 JSON 数组格式：[{"i":0,"t":"译文"},{"i":1,"t":"译文"},...]
5. 不要翻译拟声词、人名（如"La La La"、"Hey Jude"保持原样）
6. 只输出 JSON，不要任何其他文字

User:
{"lines": [
  {"i": 0, "t": "You are my sunshine"},
  {"i": 1, "t": "My only sunshine"},
  {"i": 2, "t": "You make me happy"},
  {"i": 3, "t": "When skies are grey"}
]}
```

**期望输出**：

```json
[
  {"i": 0, "t": "你是我的阳光"},
  {"i": 1, "t": "我唯一的阳光"},
  {"i": 2, "t": "你让我快乐"},
  {"i": 3, "t": "当天空灰暗时"}
]
```

**罗马音（音译）Prompt**：

```
System:
请为以下日语歌词生成罗马音（Romaji）。要求：
1. 使用标准 Hepburn 罗马字转写
2. 保持每行对应：输入 N 行输出 N 行
3. 输出 JSON 数组：[{"i":0,"t":"romaji"},...]
4. 只输出 JSON

User:
{"lines": [{"i":0,"t":"君の名前を呼んでいる"}, ...]}
```

**业务规则**：

- `BR-23-016`：**批量翻译**：一次请求翻译**完整歌词**（而非逐行），大幅降低调用次数。
  - **权衡**：整首歌词约 30-60 行，一次请求 token 较多（约 500-1500 input tokens），但**调用次数从 60 次降为 1 次**，总成本低得多。
  - **限制**：若歌词 > 100 行，分批（每批 50 行）。
- `BR-23-017`：**行数校验**：输出行数必须与输入一致，否则**重试**或**降级**（不展示错位翻译）。
- `BR-23-018`：**时间戳对齐**：翻译与原歌词共享时间标签，**逐行对应**。
- `BR-23-019`：**缓存永久**（`ml:ai:lyric:trans:{songId}:{lang}`），随歌曲下架清除。
- `BR-23-020`：**预生成**：热门歌曲（播放量 Top 1000）**离线预生成**翻译，用户点击时秒出。
- `BR-23-021`：**按需生成**：冷门歌曲用户点击时才生成（约 3-5 秒，显示 loading）。
- `BR-23-022`：**目标语言**本期仅支持**中文**（英/日/韩 → 中）。
- `BR-23-023`：**中文歌曲不翻译**（无意义）。
- `BR-23-024`：**翻译质量**：用户可**反馈**（"翻译有误"），累积反馈后运营人工修正。
- `BR-23-025`：**翻译过内容审核**（AI 可能生成不当内容）。
- `BR-23-026`：**展示模式**：原文 / 原文+翻译 / 仅翻译（见 [16 章](./16-模块07-播放与歌词.md)）。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-23-002-1` | 输出行数不匹配 | 重试 1 次；仍失败则**不展示翻译**，提示"翻译服务暂时不可用" |
| `EX-23-002-2` | LLM 超时（> 5s） | 返回"翻译生成中，请稍后再试" + 异步生成 |
| `EX-23-002-3` | 预算是超限 | 提示"翻译服务繁忙"，不生成 |
| `EX-23-002-4` | 歌词为空 | 提示"暂无歌词" |
| `EX-23-002-5` | 翻译含违规内容 | 拦截该行，显示原文 |
| `EX-23-002-6` | 中文歌曲请求翻译 | 提示"中文歌曲无需翻译" |

**验收标准**：

- `AC-23-002-1`：外币歌曲翻译可生成且逐行对齐
- `AC-23-002-2`：翻译行数与原文一致
- `AC-23-002-3`：缓存命中率 ≥ 80%（热门歌曲）
- `AC-23-002-4`：热门歌曲预生成，秒出
- `AC-23-002-5`：行数不匹配时不展示错位翻译
- `AC-23-002-6`：三种展示模式可用
- `AC-23-002-7`：翻译经内容审核
- `AC-23-002-8`：用户可反馈翻译问题

## 6. 情绪与场景识别

### FR-23-004 歌曲情绪识别 【P1】

| 项 | 内容 |
|---|---|
| **功能目标** | 自动为歌曲打上情绪与场景标签，支撑推荐与搜索 |
| **使用角色** | 系统内部（运营可校正） |

**识别维度**：

| 维度 | 取值 | 用途 |
|---|---|---|
| **情绪（valence-arousal）** | valence 0~1（负面-正面）、arousal 0~1（平静-激动） | 精准推荐 |
| **情绪标签** | 开心/伤感/治愈/活力/平静/孤独/激昂/怀旧 | 搜索与歌单 |
| **场景标签** | 运动/睡眠/通勤/学习/工作/聚会/驾车/深夜 | 场景歌单 |
| **能量（energy）** | 0~1 | 推荐排序 |
| **BPM** | 数值 | 场景匹配 |

**识别输入**：

```
输入信息（多源融合）：
1. 歌词全文（主要信号）
2. 歌曲名（辅助）
3. 已有标签（辅助）
4. BPM（若有，来自音频分析）
5. 用户行为（播放场景，如夜间播放多 → 可能适合助眠）
```

**Prompt 设计**：

```
System:
你是一位音乐情绪分析专家。请分析这首歌曲的情绪与适用场景。

输出严格符合以下 JSON Schema，不要输出其他内容：
{
  "valence": 0.0~1.0,        // 情绪正负：0 极度负面，1 极度正面
  "arousal": 0.0~1.0,        // 唤醒度：0 极度平静，1 极度激动
  "energy": 0.0~1.0,         // 能量：0 极低，1 极高
  "emotion": ["伤感", "治愈"],  // 情绪标签（从以下选择 1-3 个）
  "scene": ["深夜", "睡眠"],    // 场景标签（从以下选择 0-3 个）
  "confidence": 0.0~1.0,     // 置信度
  "reason": "简短理由，不超过 30 字"
}

可选情绪标签：开心,伤感,治愈,活力,平静,孤独,激昂,怀旧,浪漫,思念
可选场景标签：运动,睡眠,通勤,学习,工作,聚会,驾车,深夜,清晨,雨天

User:
歌曲名：{name}
歌手：{artist}
标签：{tags}
歌词：
{lyric}
```

**业务规则**：

- `BR-23-034`：情绪识别**离线批处理**（每日处理新歌 + 未标注歌曲），**不占用在线额度**。
- `BR-23-035`：**批量处理**：每小时处理 **500 首**（受 LLM 限流与成本约束）。
- `BR-23-036`：**置信度阈值**：`confidence < 0.6` 的**不自动采用**，进**人工审核队列**。
- `BR-23-037`：情绪标签**必须**从**白名单**中选择（不允许 LLM 自创标签）。
- `BR-23-038`：**数值边界校验**：valence/arousal/energy 必须在 0~1。
- `BR-23-039`：结果存入 `t_song_emotion`（`song_id`、`valence`、`arousal`、`energy`、`emotion_tags`、`scene_tags`、`confidence`、`source`、`version`）。
- `BR-23-040`：**运营可校正**：后台可修改歌曲情绪标签，`source` 标记为 `MANUAL`，**后续 AI 重跑不覆盖人工标注**。
- `BR-23-041`：**重新识别触发**：歌词变更时自动重跑。
- `BR-23-042`：**同步到 ES**：情绪/场景标签写入 ES（用于搜索筛选）。
- `BR-23-043`：**BPM 来自音频分析**（非 LLM）：使用音频处理库（如 `tarsosdsp` 或专用服务）分析，**不消耗 AI 成本**。
  - **【假设 A-30】** BPM 通过**离线音频分析服务**（Python + librosa）计算，作为独立任务写入 `t_song.bpm`。若该服务不可用，BPM 留空（场景匹配时跳过该条件）。
- `BR-23-044`：**质量抽检**：每周抽样 100 首人工核对，准确率 < 80% 时调整 Prompt。
- `BR-23-045`：**成本控制**：单首约 500-1500 tokens，100 万首歌全量约 ¥500-1500（一次性），可接受。

**异常情况**：

**验收标准**：

| 项 | 内容 |

| **使用角色** | 登录用户 |

> **重要说明**：哼唱识曲需要**音频指纹（Audio Fingerprint）**技术（如 **Shazam 算法** 或 **Chromaprint/AcoustID**），**不是 LLM 能力**，需要独立服务。

**实现方案**：

| 方案 | 说明 | 可行性 |
|---|---|---|
| **A. AcoustID（Chromaprint）** | 开源音频指纹库，已有服务端实现 | **推荐**（成熟开源） |
| **B. 自建 Shazam 算法** | 实现频谱峰值提取 + 哈希匹配 | 成本高，工作量大 |
| **C. 第三方 API** | 如 ACRCloud（付费） | 需付费，且需版权库 |
| **D. 自建简化版** | 旋律轮廓匹配（把哼唱转为音高序列，匹配曲库） | 准确率低 |

**选型**：**方案 A（Chromaprint + 自建索引）**【假设 A-31】

**流程**：

```
用户点击"哼唱识曲" → 录音 10 秒（麦克风权限）
   ↓
[1] 音频预处理：转单声道、16kHz、降噪、归一化
   ↓
[2] 生成音频指纹（Chromaprint）
   ↓
[3] 在指纹库（基于曲库全量音频预生成）中检索
   ↓
[4] 返回 Top 3 候选（含相似度）
   ↓
[5] 用户确认 → 跳转播放
```

**业务规则**：

- `BR-23-065`：**录音时长 10 秒**（可配 5-15 秒）。

- `BR-23-069`：**指纹库**需**全量曲库预生成**（100 万首 × 约 1 分钟音频，预处理耗时长，需离线批量）。
- `BR-23-070`：**识别率预期**：哼唱（非原唱）识别率较低（**30-50%**），**必须**在 UI 上提示"哼唱识别率有限，可尝试更清晰的旋律"。

- `BR-23-072`：**移动端优先**（桌面端麦克风体验差）。
- `BR-23-073`：**失败**时提示"没识别出来，试试其他方式搜索"。
- `BR-23-074`：**不作为核心功能**（准确率有限），作为**补充入口**。

## 8. AI 标注批处理

### FR-23-008 离线 AI 标注任务 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 批量完成 AI 标注，不占用在线额度 |
| **使用角色** | 系统内部 |

**任务清单**：

| 任务 | 频率 | 批量 | 说明 |
|---|---|---|---|
| 歌词翻译预生成 | 每日 | 500 首 | 热门歌曲优先 |
| 歌词摘要生成 | 每日 | 1000 首 | — |
| 情绪场景识别 | 每小时 | 500 首 | 新歌优先 |
| 向量生成 | 每日 | 全量增量 | 新歌 + 变更歌曲 |
| BPM 分析 | 每日 | 1000 首 | 音频分析（非 AI） |
| 翻译质量抽检 | 每周 | 100 首 | 人工 |

**任务编排（XXL-Job）**：

```java
@XxlJob("aiAnnotationJob")
public void execute() {
    // 1. 获取待处理歌曲（按优先级：新歌 > 热门 > 其他）
    List<Long> songIds = songService.findSongsNeedingAnnotation(
        AnnotationType.EMOTION, 500);

    // 2. 分批处理，每批 20 首（一次 LLM 调用处理多首，降本）
    List<List<Long>> batches = Lists.partition(songIds, 20);

    for (List<Long> batch : batches) {
        // 预算检查
        if (!budgetGuard.hasBudget()) {
            log.warn("AI budget exhausted, pausing annotation job");
            break;
        }

        try {
            processBatch(batch);
            // 每批间隔 1 秒，避免触发 LLM 限流
            Thread.sleep(1000);
        } catch (Exception e) {
            log.error("Batch annotation failed: {}", batch, e);
            // 记录失败，下轮重试
        }
    }
}
```

**批量标注 Prompt（降本关键）**：

```
System:
你是音乐分析专家。请分析以下 {N} 首歌曲，为每首输出情绪与场景分析。
输出 JSON 数组，每首一个对象，顺序与输入一致：
[{"id":"...","valence":0.5,"arousal":0.3,"energy":0.4,"emotion":["平静"],"scene":["深夜"],"confidence":0.8}, ...]
只输出 JSON。

User:
[
  {"id":"1001","name":"晴天","artist":"周杰伦","tags":["流行","青春"],"lyric":"故事的小黄花..."},
  {"id":"1002","name":"...","artist":"...","tags":[...],"lyric":"..."},
  ...
]
```

> **降本效果**：单次调用处理 20 首，Prompt 开销（System 部分）只计一次，相比逐首调用可节省 **40-60%** 的 token 成本。

**业务规则**：

- `BR-23-076`：**必须批量处理**（一次调用多首），降低 System Prompt 重复开销。
- `BR-23-077`：**批量大小 10-20 首**（太大则单次输出过长易截断，太小则降本效果差）。
- `BR-23-078`：**批内顺序**必须与输入一致（校验 ID 匹配）。
- `BR-23-079`：**预算检查**每批前执行，超预算立即停止。
- `BR-23-080`：**限流**：每批间隔 ≥ 1 秒（避免触发 LLM 限流）。
- `BR-23-081`：**失败重试**：单批失败重试 2 次，仍失败记录到 `t_ai_annotation_fail` 下轮重试。
- `BR-23-082`：**进度记录**：任务进度存 Redis（`ml:ai:job:{jobName}:progress`），支持断点续跑。
- `BR-23-083`：**优先级**：新歌（7 天内）> 热门（播放 Top 10000）> 其他。
- `BR-23-084`：**幂等**：已有标注的歌曲跳过（除非歌词变更）。
- `BR-23-085`：**离线时段**：批处理在低峰时段执行（凌晨 2:00 - 6:00），避免与在线请求争抢 LLM 配额。
- `BR-23-086`：**成本监控**：任务完成后记录当次成本，累计到日报。
- `BR-23-087`：**人工覆盖保护**：`source = MANUAL` 的标注**不被**批处理覆盖。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-23-008-1` | 预算耗尽 | 停止任务，记录进度，次日续跑 |
| `EX-23-008-2` | LLM 限流（429） | 退避重试（指数退避，最长 60s） |
| `EX-23-008-3` | 批内部分失败 | 成功的入库，失败的记录重试 |
| `EX-23-008-4` | 输出数量不匹配 | 整批视为失败，重试（或降为逐首处理） |
| `EX-23-008-5` | 任务超时 | XXL-Job 分片 + 断点续跑 |
| `EX-23-008-6` | 与在线请求争抢配额 | 在线优先：批处理检测到在线 QPS 高时暂停 |

**验收标准**：

- `AC-23-008-1`：批处理任务按计划执行
- `AC-23-008-2`：批量调用降低 token 成本（对比逐首处理）
- `AC-23-008-3`：预算耗尽自动停止并可续跑
- `AC-23-008-4`：失败重试机制有效
- `AC-23-008-5`：新歌优先处理
- `AC-23-008-6`：人工标注不被覆盖
- `AC-23-008-7`：成本记录完整

## 12. 成本模型与预算

**单次调用成本估算（以人民币计，示例价格）**：

| 场景 | 模型档 | 输入 tokens | 输出 tokens | 单价（元/千 tokens） | 单次成本 |
|---|---|---|---|---|---|
| 搜索意图解析 | SMALL | 800 | 200 | 0.001 / 0.002 | ¥0.0012 |
| 搜索解释 | SMALL | 300 | 100 | 0.001 / 0.002 | ¥0.0005 |
| 歌词翻译（整首） | MEDIUM | 1500 | 1500 | 0.004 / 0.012 | ¥0.024 |
| 歌词摘要 | MEDIUM | 1500 | 50 | 0.004 / 0.012 | ¥0.0066 |
| 情绪识别（批量 20 首） | SMALL | 8000 | 2000 | 0.001 / 0.002 | ¥0.012（单首 ¥0.0006） |
| AI 歌单生成 | LARGE | 5000 | 1500 | 0.02 / 0.06 | ¥0.19 |
| 推荐精排（每用户） | LARGE | 4000 | 500 | 0.02 / 0.06 | ¥0.11 |

**日成本估算（10 万 DAU 场景）**：

| 场景 | 日调用量 | 单次成本 | 日成本 | 备注 |
|---|---|---|---|---|
| 搜索意图解析 | 20000 | ¥0.0012 | ¥24 | 假设 20% 搜索用 AI，缓存命中 40% → 实际 12000 次 |
| 歌词翻译（按需） | 2000 | ¥0.024 | ¥48 | 大部分热门预生成 |
| 歌词翻译（预生成） | 500（离线） | ¥0.024 | ¥12 | 批处理更便宜 |
| 歌词摘要（预生成） | 1000（离线） | ¥0.0066 | ¥6.6 | 低峰批处理 |
| 情绪识别（预生成） | 500（离线） | ¥0.0006 | ¥0.3 | 批量摊销 |
| AI 歌单生成 | 1000 | ¥0.19 | ¥190 | **最大成本项**，需严控 |
| 推荐精排 | 不启用（本期用规则） | — | ¥0 | P2 再评估 |
| **合计** | — | — | **约 ¥280/天** | 约 **¥8400/月** |

**成本优化措施**：

| 措施 | 节省 |
|---|---|
| 结果缓存（40-60% 命中） | 40%+ |
| 分级模型（小模型做简单任务） | 50%+ |
| 批量调用（离线任务） | 40-60% |
| 候选列表精简字段 | 20% |
| 离线低峰批处理（批处理 API 折扣） | 30-50% |
| AI 歌单生成严格限流（5 次/小时/人） | 控制峰值 |
| 每日预算熔断 | 硬上限 |

## 13. 降级策略

| 依赖 | 故障 | 降级 |
|---|---|---|
| LLM 服务 | 不可用 | 所有在线 AI 功能降级（搜索→关键词，翻译→不展示，歌单→提示） |
| LLM 主模型 | 不可用 | 切换备用模型 |
| 预算耗尽 | — | 熔断（除内容安全审核） |
| 缓存 Redis | 不可用 | 直连 LLM（成本上升） + 告警 |
| 向量服务 | 不可用 | 跳过语义召回 |
| 离线批处理 | 失败 | 次日续跑，不影响在线 |
| 音频分析（BPM） | 不可用 | BPM 留空，场景匹配跳过该条件 |
| 哼唱识别服务 | 不可用 | 隐藏入口 |
| 麦克风权限 | 拒绝 | 隐藏功能 |
