---

## 1. 模块目标

1. 让用户能对内容**表达态度**（点赞、收藏、评论、分享）。
2. 让用户能**建立关系**（关注、私信）。
3. 让用户能**及时收到反馈**（通知）。
4. 让用户能**举报不良内容**（举报，配合内容安全）。

**衡量指标**：

| 指标 | 目标 |
|---|---|
| 评论接口 P95 | ≤ 300ms |
| 点赞接口 P95 | ≤ 150ms |
| 收藏数/DAU | ≥ 0.8 |
| 评论数/DAU | ≥ 0.3 |
| 通知到达延迟 | ≤ 5s |
| 点赞重复率（脏数据） | 0 |
| 评论成功率 | ≥ 99.9% |

---

## 2. 使用角色

| 角色 | 能力 |
|---|---|
| 游客 | 只读（可看评论、收藏数），**不可**写 |
| 普通用户 | 全部社交能力 |
| 房主 | 房间内管理评论（见 [14 章](./14-模块05-音乐房.md)） |
| 管理员 | 删除评论、处理举报（见 [18 章](./18-模块09-管理后台.md)） |

## 3. 前置条件

- 用户已登录（写操作）。
- 内容审核服务可用（见 [27 章](./27-模块18-内容安全.md)）。
- Redis 可用（计数、通知队列）。
- WebSocket 可用（实时通知）。

## 4. 评论

### FR-19-001 发表评论 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 用户对歌曲/歌单/房间发表评论 |
| **使用角色** | 登录用户 |
| **前置条件** | 用户未禁言 |

**评论对象类型**：

| 类型 | `target_type` | 说明 |
|---|---|---|
| 歌曲 | `SONG` | 歌曲详情页评论区 |
| 歌单 | `PLAYLIST` | 歌单页 |
| 专辑 | `ALBUM` | 专辑页 |
| 房间 | `ROOM` | 房间内（实时，见 [14 章](./14-模块05-音乐房.md)） |
| 评论 | `COMMENT` | 回复评论 |

**操作流程**：

```
用户输入评论内容 → 点击"发送"
   ↓
[1] 前端预校验
     - 非空（trim 后）
     - 长度 1~500 字
     - 频率限制（UI 禁用 5 秒）
   ↓
[2] 提交 POST /api/v1/comments
     {
       "targetType": "SONG",
       "targetId": "1857...",
       "content": "这首歌太好听了",
       "parentId": null,          // 回复时填写
       "rootId": null             // 二级回复时填写顶层评论 ID
     }
   ↓
[3] 服务端校验
     - 登录校验
     - 禁言校验（40016）
     - 目标存在性校验
     - 目标状态校验（歌曲未下架）
     - 长度校验
     - 频率限制（Redis 滑动窗口：用户 1 分钟 5 条，1 小时 30 条）
     - 敏感词检测（DFA）
     - 内容重复检测（同一用户同一内容 5 分钟内拒绝）
   ↓
[4] 敏感词判定分流
     ├─ 命中拦截词 → 拒绝，返回 50002
     ├─ 命中疑似词 → 状态设为"待审核"（status=0），用户可见"审核中"
     └─ 无命中 → 机审（AI 审核，异步）
                 ├─ 通过 → 状态"已通过"（status=1）
                 └─ 不通过 → 状态"待审核"（转人工）
   ↓
[5] 保存评论（t_comment）
   ↓
[6] 更新计数：
     INCR ml:count:comment:{targetType}:{targetId}
     INCR ml:count:user:comment:{userId}
   ↓
[7] 发送通知（目标作者 / 被回复人）
   ↓
[8] 返回评论（含用户信息、时间、状态）
```

**业务规则**：

- `BR-19-001`：评论长度 **1~500 字**（含表情符号，按字符计）。
- `BR-19-002`：**禁止**纯表情评论（防止刷屏）——要求至少 1 个非表情字符。
- `BR-19-003`：**频率限制**：单用户 1 分钟 **5 条**，1 小时 **30 条**，1 天 **200 条**。
- `BR-19-004`：**内容重复**：同一用户 5 分钟内相同内容**拒绝**。
- `BR-19-005`：**敏感词**分级处理（拦截/疑似），见 [27 章](./27-模块18-内容安全.md)。
- `BR-19-006`：**先发后审**（普通用户）：评论立即可见（乐观），机审异步，若判定违规则**撤回**并通知用户。
  - **【假设 A-19】** 采用"先发后审"以保障体验；若平台合规要求严格，可切换为"先审后发"（配置项 `comment.audit.mode`）。
- `BR-19-007`：**新用户保护期**（注册 ≤ 7 天）：评论**先审后发**（防广告号）。
- `BR-19-008**：**禁言用户**返回 `40016`，并显示解禁时间。
- `BR-19-009`：评论**必须**支持**表情**（Emoji 直接存储，自定义表情用 `[表情名]` 占位）。
- `BR-19-010`：评论**必须**支持 **@提及**（见 [25 章](./25-模块16-社交升级.md)）。
- `BR-19-011`：评论**必须**记录 **IP 与 UA**（用于风控与取证）。
- `BR-19-012`：**评论内容**必须**转义**存储（防 XSS），前端渲染时**不允许** `dangerouslySetInnerHTML`（除高亮片段）。
- `BR-19-013`：评论**禁止**包含外部链接（除白名单域名），含链接则降级为纯文本并提示。
- `BR-19-014`：**被评论内容下架**后，其评论**不删除**但不可见（随内容一起隐藏）。
- `BR-19-015`：**评论数计数**：Redis 计数 + 5 分钟定时刷盘（同 [12 章](./12-模块03-Redis缓存.md) 计数策略）。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-19-001-1` | 内容为空 | `70001`，前端拦截 |
| `EX-19-001-2` | 长度超限 | `70002`，提示最大 500 字 |
| `EX-19-001-3` | 命中拦截敏感词 | `50002`，提示"内容包含违规词汇" |
| `EX-19-001-4` | 频率超限 | `40017`，提示"评论过于频繁，请稍后再试" |
| `EX-19-001-5` | 内容重复 | `40018`，提示"请勿重复评论" |
| `EX-19-001-6` | 用户被禁言 | `40016`，显示解禁时间 |
| `EX-19-001-7` | 目标不存在 | `70004`，提示"内容不存在" |
| `EX-19-001-8` | 目标已下架 | `70005`，提示"该内容已下架" |
| `EX-19-001-9` | 审核服务不可用 | **降级**：敏感词通过的评论直接发布，标记"待补审"（异步重试） |
| `EX-19-001-10` | 数据库写入失败 | 返回失败，前端保留内容允许重试 |

**验收标准**：

- `AC-19-001-1`：发表评论成功并立即显示
- `AC-19-001-2`：长度与频率限制生效
- `AC-19-001-3`：敏感词被拦截
- `AC-19-001-4`：重复评论被拒绝
- `AC-19-001-5`：禁言用户无法评论
- `AC-19-001-6`：新用户评论先审后发
- `AC-19-001-7`：评论内容 XSS 转义
- `AC-19-001-8`：审核服务不可用时降级可用
- `AC-19-001-9`：评论 P95 ≤ 300ms

### FR-19-002 评论列表与回复 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 展示评论并支持二级回复 |
| **使用角色** | 全部 |

**评论结构（二级）**：

```
顶层评论（rootId = null, parentId = null）
  ├─ 回复 1（rootId = 顶层 ID, parentId = 顶层 ID）
  ├─ 回复 2（rootId = 顶层 ID, parentId = 顶层 ID）
  └─ 回复 3 对回复 1（rootId = 顶层 ID, parentId = 回复 1 ID）
```

**列表展示**：

| 排序 | 说明 |
|---|---|
| 最热（默认） | 点赞数 DESC，时间 DESC |
| 最新 | 创建时间 DESC |

**分页规则**：

- 顶层评论：分页（每页 20 条）
- 每条顶层评论：默认展示 **2 条**回复，点击"展开更多回复"加载全部（最多展示 50 条，超出提示"查看更多"进入二级页）

**业务规则**：

- `BR-19-016`：评论**必须**支持**二级回复**（不做无限嵌套，超过二级统一挂到 root 下）。
- `BR-19-017`：回复**必须**显示"回复 @某人"。
- `BR-19-018`：顶层评论按**热度**排序（点赞数 × 0.7 + 回复数 × 0.3），热度相同时按时间倒序。
- `BR-19-019`：**评论内容中的 @提及**渲染为可点击链接。
- `BR-19-020`：**已删除评论**显示为"该评论已删除"占位（保留结构），其下回复仍可见。
- `BR-19-021`：**待审核评论**：对作者自己显示（带"审核中"标记），对其他人**不可见**。
- `BR-19-022`：**评论列表缓存**：热门前 20 条缓存 1 分钟（`ml:comment:hot:{targetType}:{targetId}`）。
- `BR-19-023`：**分页深分页**：超过 100 页切换游标分页（复用 [05 章](./05-通用设计规范.md) 规范）。
- `BR-19-024`：评论列表**必须**返回当前用户是否已点赞该评论（`liked` 字段）。
- `BR-19-025`：评论列表**必须**返回作者的**当前昵称与头像**（若作者已注销，显示"已注销用户"）。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-19-002-1` | 目标不存在 | 返回空列表 + `70004` |
| `EX-19-002-2` | 评论数 > 10000 | 限制最多可翻 100 页，提示切换"最热" |
| `EX-19-002-3` | 作者已注销 | 显示"已注销用户"，头像为默认 |
| `EX-19-002-4` | 评论内容含已删评论 @ | 显示"已删除用户" |

**验收标准**：

- `AC-19-002-1`：评论列表正确展示二级结构
- `AC-19-002-2`：默认 2 条回复，可展开
- `AC-19-002-3`：最热/最新排序正确
- `AC-19-002-4`：已删除评论占位显示
- `AC-19-002-5`：待审核评论仅作者可见
- `AC-19-002-6`：`liked` 字段正确

### FR-19-003 删除评论 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 用户删除自己的评论；管理员删除违规评论 |
| **使用角色** | 评论作者、管理员 |

**删除类型**：

| 类型 | 触发 | 效果 |
|---|---|---|
| 用户自删 | 作者点击"删除" | 软删除，内容置空 |
| 管理员删除 | 后台操作 | 软删除 + 记录原因 + 通知作者 |
| 系统删除 | 机审/人审判定违规 | 软删除 + 通知作者 + 计入违规次数 |

**业务规则**：

- `BR-19-026`：删除为**软删除**（`is_deleted=1`），内容字段**置空**（隐私）。
- `BR-19-027`：删除**顶层评论**时，其**回复一并不可见**（级联隐藏，但数据保留）。
- `BR-19-028`：**管理员删除必须**填写原因并**通知作者**。
- `BR-19-029`：**用户自删**不通知。
- `BR-19-030**：删除后**计数递减**（`DECR`）。
- `BR-19-031`：**删除操作幂等**（重复删除返回成功）。
- `BR-19-032`：**系统删除**计入用户**违规次数**，累计达阈值触发禁言（见 [27 章](./27-模块18-内容安全.md)）。
- `BR-19-033`：删除**不影响**已发出的通知（通知仍保留，但点击时显示"内容已删除"）。
- `BR-19-034`：用户删除自己的评论**无次数限制**，但**频繁删除**（1 小时 > 50 次）触发风控检查。

**验收标准**：

- `AC-19-003-1`：用户可删除自己的评论
- `AC-19-003-2`：删除顶层评论后回复不可见
- `AC-19-003-3`：管理员删除需填原因并通知
- `AC-19-003-4`：删除后计数正确
- `AC-19-003-5`：不能删除他人评论（非管理员）

### FR-19-004 评论点赞 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 对评论表达认同 |
| **使用角色** | 登录用户 |

**业务规则**：

- `BR-19-035`：评论点赞**存 Redis Set**（`ml:like:comment:{commentId}`，member = userId），**异步落库** `t_like`。
- `BR-19-036`：**幂等**：重复点赞不重复计数。
- `BR-19-037`：**取消点赞**：从 Set 移除，计数递减。
- `BR-19-038`：点赞数**批量获取**（列表接口一次性返回所有评论的 `liked` 与 `likeCount`，用 `SMISMEMBER` 或 Pipeline）。
- `BR-19-039`：点赞**限流**：单用户 1 分钟 **100 次**（防脚本）。
- `BR-19-040`：点赞**必须**支持**乐观更新**（前端立即 +1，失败回滚）。
- `BR-19-041`：点赞数**必须**防刷（同一用户对同一评论只能一次；同一 IP 短时间大量点赞触发风控）。
- `BR-19-042`：**点赞通知**：评论点赞数达到 **10/50/100/500/1000** 时通知作者（不必每次点赞都通知）。
- `BR-19-043`：点赞数据**必须**支持对账（定时比对 Redis Set 与 `t_like` 表）。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-19-004-1` | 评论已删除 | `70004`，不可点赞 |
| `EX-19-004-2` | Redis 不可用 | 直接写 MySQL（降级） |
| `EX-19-004-3` | 并发点赞/取消 | Redis 原子操作保证一致 |
| `EX-19-004-4` | 点赞数不一致（对账发现） | 以 MySQL 为准修正 |

**验收标准**：

- `AC-19-004-1`：点赞/取消正确且幂等
- `AC-19-004-2`：列表接口返回 `liked` 状态
- `AC-19-004-3`：点赞乐观更新
- `AC-19-004-4`：里程碑点赞发通知
- `AC-19-004-5`：点赞 P95 ≤ 150ms

## 5. 点赞与收藏

### FR-19-005 歌曲/歌单点赞 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 表达对内容的喜欢 |
| **使用角色** | 登录用户 |

**点赞对象**：歌曲（`SONG`）、歌单（`PLAYLIST`）、专辑（`ALBUM`）、评论（`COMMENT`）、房间消息（`ROOM_MESSAGE`）。

> **说明**：**歌曲点赞**在业务语义上等同于"喜欢"，会**写入推荐特征库**（见 [17 章](./17-模块08-AI推荐.md)）。

**数据结构**：

```
Redis:
  ml:like:song:{songId}          Set<userId>     # 点赞用户集合（用于"哪些人点赞"与去重）
  ml:like:user:{userId}:song     Set<songId>     # 用户点赞的歌曲（用于"我喜欢"列表）
  ml:count:like:song:{songId}    String          # 点赞计数（待刷盘）

MySQL:
  t_like (user_id, target_type, target_id, create_time)  UNIQUE(user_id, target_type, target_id)
```

> **权衡**：同时维护 `ml:like:song:{songId}` 与 `ml:like:user:{userId}:song` 两个 Set 会占用双倍内存，但能同时支持"歌曲的点赞列表"与"用户的点赞列表"两个方向的查询。对于 100 万用户 × 平均 200 点赞 = 2 亿 member，内存约 **5GB+**，可接受（Redis Cluster 分摊）。
> **替代方案**（内存敏感时）：只维护 `ml:like:user:{userId}:song`，歌曲维度用计数 + MySQL 查询。**本项目选择双 Set**，因为"我喜欢"与"谁点赞了"都是高频需求。

**业务规则**：

- `BR-19-044`：点赞**幂等**（Set 天然去重 + MySQL 唯一索引兜底）。
- `BR-19-045`：点赞**立即更新**前端 UI（乐观）。
- `BR-19-046**：点赞**必须**同步写推荐特征（异步 MQ）。
- `BR-19-047`：点赞数**定时刷盘**（每 5 分钟，见 [12 章](./12-模块03-Redis缓存.md)）。
- `BR-19-048`：**取消点赞**后**必须**同步移除推荐特征。
- `BR-19-049`：**点赞数**在列表接口批量返回（Pipeline `SCARD` 或读缓存计数）。
- `BR-19-050`：点赞**限流**：单用户 1 分钟 100 次。
- `BR-19-051`：**异常点赞行为**（10 秒内点赞 > 50 首）触发风控，标记为可疑，忽略其点赞对热度的贡献。
- `BR-19-052`：**不可点赞**已下架/审核不通过的歌曲。
- `BR-19-053`：用户可在"我的-喜欢"中**取消点赞**（批量取消支持）。
- `BR-19-054`：**点赞列表排序**：按点赞时间倒序（最新喜欢的在前）。

**接口**：

| 功能 | 方法 | 路径 |
|---|---|---|
| 点赞 | POST | `/api/v1/likes` |
| 取消点赞 | DELETE | `/api/v1/likes` |
| 我的喜欢（歌曲） | GET | `/api/v1/likes/songs` |
| 批量查询点赞状态 | POST | `/api/v1/likes/batch-check` |

**验收标准**：

- `AC-19-005-1`：点赞/取消正确且幂等
- `AC-19-005-2`：点赞立即反映在 UI
- `AC-19-005-3`：点赞数刷盘后与 MySQL 一致
- `AC-19-005-4`：我的喜欢列表正确且按时间倒序
- `AC-19-005-5`：点赞影响推荐特征
- `AC-19-005-6`：限流生效
- `AC-19-005-7`：不可点赞下架歌曲

### FR-19-006 收藏歌单/歌曲 【P0】

| 项 | 内容 |

### FR-19-007 分享 【P1】

| 项 | 内容 |
|---|---|
| **功能目标** | 把内容分享到站内/站外 |
| **使用角色** | 全部（游客也可分享链接） |

**分享目标**：

| 目标 | 说明 |
|---|---|
| 站内私信 | 分享给好友（见 FR-19-011） |
| 动态 | 发表到个人动态（P1，见 [25 章](./25-模块16-社交升级.md)） |
| 复制链接 | 生成短链 |
| 系统分享 | 调用 `navigator.share`（移动端） |
| 第三方（P2） | 微信/微博/QQ（需 SDK，**本期不做**） |

**短链生成**：

```
POST /api/v1/share
{ "targetType": "SONG", "targetId": "1857...", "channel": "COPY_LINK" }
   ↓
生成短码（Base62，6 位，如 aB3x9K）
存储：
  Redis  ml:short:url:{code}  →  { targetType, targetId, sharerId, expireAt }  (TTL 30 天)
  MySQL  t_share (可选落库用于统计)
返回 https://ml.ink/aB3x9K
   ↓
用户访问短链 → 重定向到 /song/1857...?from=share&sharerId=xxx
   ↓
记录分享点击数 + 归因（首次访问通过分享链接的用户，标记为"分享拉新"）
```

**业务规则**：

- `BR-19-066`：短链**有效期 30 天**（可配置）。
- `BR-19-067`：短码**必须**防碰撞（生成后检查存在性，冲突则重试）。
- `BR-19-068`：短码**必须**排除易混淆字符（`0/O`、`1/l/I`）。
- `BR-19-069`：分享**必须**记录**渠道**与**分享人**。
- `BR-19-070**：分享链接**必须**带 `from=share&sharerId=xxx` 用于归因。
- `BR-19-071`：**分享计数**：`INCR ml:count:share:{targetType}:{targetId}`。
- `BR-19-072`：分享链接**必须**在**社交平台**有良好的预览（OG 标签：标题、描述、封面）。
  - 需**服务端渲染**或**预渲染** OG 标签（爬虫 UA 检测 → 返回带 OG 的 HTML）。
- `BR-19-073`：分享**必须**记录埋点（渠道、目标、成功/取消）。
- `BR-19-074`：**不可分享**已下架内容（提示内容不可用）。
- `BR-19-075`：短链**必须**支持**统计**（点击数、独立访客数）。

private static final Pattern BOT_UA = Pattern.compile(

// <meta property="og:title" content="晴天 - 周杰伦" />

**验收标准**：

- `AC-19-007-1`：短链生成且可跳转
- `AC-19-007-2`：短链可统计点击数
- `AC-19-007-3`：分享归因正确
- `AC-19-007-4`：OG 标签正确（第三方平台预览正常）
- `AC-19-007-5`：不可分享下架内容
- `AC-19-007-6`：短链有效期 30 天

### FR-19-011 私信会话 【P1】

| 项 | 内容 |
|---|---|
| **功能目标** | 用户一对一聊天 |
| **使用角色** | 登录用户 |
| **前置条件** | 双方均未拉黑对方；接收方未关闭私信 |

**会话模型**：

```
t_conversation (会话)
  id, user_a_id, user_b_id (user_a_id < user_b_id 保证唯一), 
  last_message_id, last_message_time, unread_a, unread_b, create_time

t_private_message (消息)
  id, conversation_id, sender_id, receiver_id, content, msg_type(TEXT/IMAGE/SONG/PLAYLIST/ROOM),
  is_read, read_time, create_time, is_deleted
```

**业务流程**：

```
用户 A 打开与 B 的会话
   ↓
GET /api/v1/messages/conversation?targetUserId=B
   ↓
服务端查找或创建会话（user_a_id = min(A,B), user_b_id = max(A,B)）
   ↓
加载历史消息（分页，每次 30 条，向上滚动加载更多）
   ↓
用户 A 发送消息 → WebSocket 推送（实时）→ 服务端持久化
   ↓
若 B 在线 → WebSocket 实时推送
若 B 离线 → 写离线消息 + 站内通知
   ↓
B 打开会话 → 标记已读 → 未读数清零
```

**消息类型**：

| 类型 | 说明 | 载荷 |
|---|---|---|
| `TEXT` | 文本 | 内容（≤ 500 字） |
| `IMAGE` | 图片 | URL（已上传，≤ 5MB） |
| `SONG` | 分享歌曲 | songId（渲染为歌曲卡片） |
| `PLAYLIST` | 分享歌单 | playlistId |
| `ROOM` | 邀请进房间 | roomId（渲染为邀请卡片） |

**业务规则**：

- `BR-19-107`：私信**仅限**互相关注的用户 → **【假设 A-20】** 默认配置为"**所有人可私信**"，用户可在设置中改为"仅互相关注"或"关闭私信"。默认宽松以降低使用门槛，设置中可收紧。
- `BR-19-108`：**非互关**用户的私信**限制**：每天最多发送 **3 条**（防骚扰），对方回复后可无限沟通。
- `BR-19-109`：私信内容**必须**过敏感词与审核（同评论）。
- `BR-19-110`：**文本消息长度 ≤ 500 字**。
- `BR-19-111`：**图片消息**必须**先上传**再发送，图片**必须**过内容审核。
- `BR-19-112`：会话**唯一性**：`UNIQUE(user_a_id, user_b_id)` 保证不会重复建会话。
- `BR-19-113`：**未读数**存 Redis（`ml:msg:unread:{userId}:{conversationId}`）+ 会话表冗余。
- `BR-19-114`：**消息持久化**：`t_private_message`，保留 **1 年**，之后归档。
- `BR-19-115`：**已读回执**：对方已读时，发送者收到"已读"状态（可选功能，可在设置关闭）。
- `BR-19-116`：**消息撤回**：发送后 **2 分钟**内可撤回（撤回后双方均显示"消息已撤回"）。
- `BR-19-117`：**消息删除**：单方删除（仅自己不可见）。
- `BR-19-118`：**离线消息**：接收方离线时，消息存储并推送通知（站内 + 邮件可选）。
- `BR-19-119`：**拉黑**后**不能**发送私信（`40021`）。
- `BR-19-120`：**私信频率限制**：1 分钟 20 条，1 小时 200 条。
- `BR-19-121`：**会话列表**按 `last_message_time` 倒序，支持未读数徽标。
- `BR-19-122`：**私信举报**：用户可举报私信（**隐私敏感**，仅 ADMIN+ 可查看内容，见 [18 章](./18-模块09-管理后台.md)）。
- `BR-19-123`：**未关注用户**首次私信时，会话顶部提示"对方可能无法及时回复"。
- `BR-19-124`：**消息发送失败**（网络问题）时前端显示重试按钮，不丢失已输入内容。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-19-011-1` | 对方已拉黑我 | `40021`，提示"无法发送" |
| `EX-19-011-2` | 对方关闭私信 | `40023`，提示"对方已关闭私信" |
| `EX-19-011-3` | 非互关超过 3 条/天 | `40024`，提示"关注对方后可继续聊天" |
| `EX-19-011-4` | 发送太频繁 | `40017`，提示稍后再试 |
| `EX-19-011-5` | 内容含敏感词 | `50002`，拒绝发送 |
| `EX-19-011-6` | 撤回超时（> 2 分钟） | `40025`，提示"超过撤回时限" |
| `EX-19-011-7` | WebSocket 断开 | 消息降级为 HTTP 发送，实时推送失败时对方刷新可见 |
| `EX-19-011-8` | 接收方账号注销 | 会话标记"对方已注销"，不可发送 |
| `EX-19-011-9` | 图片审核不通过 | 消息发送成功但图片显示"内容违规"占位 |

**验收标准**：

- `AC-19-011-1`：可发送/接收私信（实时）
- `AC-19-011-2`：会话唯一不重复
- `AC-19-011-3`：未读数正确

- `AC-19-011-6`：支持 5 种消息类型
- `AC-19-011-7`：离线消息可收到
- `AC-19-011-8`：拉黑后不可发送
- `AC-19-011-9`：消息保留 1 年
- `AC-19-011-10`：私信举报可处理

**通知结构**：

```json
{
  "id": "1857...",
  "type": "COMMENT",
  "title": "小明 评论了你的歌曲",
  "content": "这首歌太好听了...",
  "sender": {
    "userId": "1857...",
    "nickname": "小明",
    "avatar": "https://..."
  },
  "target": {
    "targetType": "SONG",
    "targetId": "1857...",
    "targetName": "晴天"
  },
  "isRead": false,
  "createTime": "2026-10-12 10:30:00"
}
```

**业务规则**：

- `BR-19-131`：通知**存储**在 `t_notification`，保留 **90 天**（之后归档）。
- `BR-19-132`：**未读数**存 Redis（`ml:notify:unread:{userId}`），供徽标展示。
- `BR-19-133`：**实时推送**：用户在线时通过 WebSocket 推送（`type=NOTIFICATION`）。
- `BR-19-134`：**离线**：仅存储，用户下次登录时拉取。
- `BR-19-135`：**聚合规则**：
  - 同一内容的多个点赞 → 1 分钟内聚合为"XXX 等 5 人点赞了你"
  - 单日关注 > 50 → 聚合为"XXX 等 52 人关注了你"
  - 同一内容的多个评论 → **不聚合**（评论是有价值的独立信息）
- `BR-19-136`：**通知设置**：用户可**分类开关**（点赞/评论/关注/系统 等），见 FR-19-012。
- `BR-19-137`：**通知跳转**：点击通知跳转到对应内容（若内容已删除则提示"内容已删除"）。
- `BR-19-138`：**自己对自己的操作不通知**（如自己点赞自己的评论）。
- `BR-19-139`：**通知去重**：同一用户对同一内容的同一动作**不重复通知**。
- `BR-19-140`：**通知清理**：90 天前的通知归档；用户可手动清空全部。
- `BR-19-141`：**通知分页**：每页 20 条，按时间倒序。
- `BR-19-142`：**通知分组 Tab**：全部 / 互动（点赞评论@）/ 关注 / 私信 / 系统。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-19-013-1` | 通知发送失败 | 重试 3 次，仍失败记日志（不阻断主流程） |
| `EX-19-013-2` | 用户已注销 | 跳过，不发送 |
| `EX-19-013-3` | 内容已被删除 | 通知仍发送，点击时提示"内容已删除" |
| `EX-19-013-4` | 通知量激增 | 降级：仅推送高优先级（关注/私信/系统），其他仅存储 |
| `EX-19-013-5` | WebSocket 不可用 | 降级为仅存储 + 轮询拉取 |

**验收标准**：

- `AC-19-013-1`：各类通知正确触发
- `AC-19-013-2`：在线用户实时收到（≤ 5s）
- `AC-19-013-3`：未读数徽标正确
- `AC-19-013-4`：聚合规则生效
- `AC-19-013-5`：自己操作自己不通知

- `AC-19-013-8`：点击跳转正确

## 9. 举报

### FR-19-015 内容举报 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 让用户参与内容治理 |
| **使用角色** | 登录用户 |
| **依赖** | [27 章 内容安全](./27-模块18-内容安全.md)、[18 章 管理后台](./18-模块09-管理后台.md) |

**举报对象**：歌曲 / 评论 / 用户 / 房间 / 私信 / 歌单 / 歌词。

**举报原因（分类）**：

| 大类 | 具体原因 |
|---|---|
| 违法违规 | 涉政、涉黄、涉暴、涉恐、赌博、诈骗 |
| 侵权 | 侵犯版权、侵犯隐私、冒用他人 |
| 不良信息 | 广告垃圾、色情低俗、辱骂攻击、引战 |
| 内容质量 | 歌曲信息错误、音质问题、歌词错误、重复内容 |
| 其他 | 自由描述 |

**操作流程**：

```
用户点击"举报" → 选择原因 → （可选）上传证据截图 → （可选）补充说明 → 提交
   ↓
服务端：
  1. 校验：登录、原因必填、目标存在
  2. 去重：同一用户对同一目标同一原因 24 小时内只能举报一次
  3. 频率限制：单用户 1 小时最多 10 次举报
  4. 写入 t_report（状态=待处理）
  5. 相同目标的多条举报**合并**为一个审核任务
  6. 进入审核工作台（高优先级）
   ↓
返回"举报已提交，我们会尽快处理"
```

**业务规则**：

- `BR-19-151`：举报**原因必填**（分类选择）。
- `BR-19-152`：举报**去重**：同一用户对同一目标同一原因 **24 小时**内只能一次。
- `BR-19-153`：举报**频率限制**：单用户 **1 小时 10 次**，**1 天 30 次**。
- `BR-19-154`：**多人举报同一目标** → **合并**为一个审核任务（记录所有举报人）。
- `BR-19-155`：举报**必须**通知举报人处理结果（见 [18 章](./18-模块09-管理后台.md)）。
- `BR-19-156`：**恶意举报**（举报成立率 < 10% 且举报数 > 20）**限制**举报功能 7 天。
- `BR-19-157**：**举报处理 SLA**：普通 24 小时，严重（涉政涉黄涉暴）**2 小时**。
- `BR-19-158`：举报**必须**记录（举报人、目标、原因、证据、时间、IP）。
- `BR-19-159`：**举报人信息保密**（被举报者不可知举报人身份）。
- `BR-19-160`：**私信举报**需提供**消息 ID**（用户不能随意举报整个会话）。
- `BR-19-161`：**举报后处理**：
  - 成立 → 执行处置（删除/封禁/限流），通知举报人"已处理"
  - 不成立 → 驳回，通知举报人"未发现问题"
  - 待补充 → 联系举报人补充信息
- `BR-19-162`：**举报成立**时给举报人**信用分 +1**（鼓励举报），信用分影响审核优先级。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-19-015-1` | 24 小时内重复举报 | `40026`，提示"你已举报过" |
| `EX-19-015-2` | 举报频率超限 | `40027`，提示稍后再试 |
| `EX-19-015-3` | 目标不存在 | `70004`，提示"内容不存在" |
| `EX-19-015-4` | 举报自己 | `40028`，拒绝 |
| `EX-19-015-5` | 证据图片过大 | `40029`，提示 ≤ 5MB |
| `EX-19-015-6` | 被限制举报 | `40030`，提示限制到期时间 |

**验收标准**：

- `AC-19-015-1`：可举报各类对象
- `AC-19-015-2`：举报原因必填
- `AC-19-015-3`：24 小时内去重
- `AC-19-015-4`：频率限制生效
- `AC-19-015-5`：多人举报合并
- `AC-19-015-6`：举报人收到处理结果通知
- `AC-19-015-7`：恶意举报被限制
- `AC-19-015-8`：举报人信息保密

## 14. 性能与容量

| 项 | 预估 | 说明 |
|---|---|---|
| 评论 QPS | 峰值 500 | 写少读多 |
| 点赞 QPS | 峰值 5000 | 全部走 Redis |
| 点赞 Set 内存 | 2 亿 member × ~50B ≈ 10GB | Redis Cluster 分摊 |
| 关注关系 | 100 万用户 × 平均 50 关注 = 5000 万 | Redis Set + MySQL |
| 私信消息 | 100 万条/天 | 按月分表，保留 1 年 |
| 通知 | 500 万条/天 | 保留 90 天，按月分表 |
| 未读数 | 100 万 key | 内存 ~100MB |

**私信分表**：`t_private_message_202610`（按月），提前 1 天建下月表。

**通知分表**：`t_notification_202610`（按月）。

## 15. 降级策略

| 依赖 | 故障 | 降级 |
|---|---|---|
| 审核服务 | 不可用 | 评论/私信直接发布，标记"待补审"，异步重试 |
| WebSocket | 不可用 | 通知/私信降级为轮询（30 秒） |
| Redis | 不可用 | 点赞/收藏/关注直写 MySQL（性能下降），限流失效（改用本地 Guava RateLimiter） |
| 通知服务 | 不可用 | 仅存储不推送，用户下次登录拉取 |
| 邮件服务 | 不可用 | 重试 + 死信队列，不阻断主流程 |
| 短链服务 | 不可用 | 降级为完整 URL 分享 |
