## 1. 模块目标

在基础播放之上提供**进阶体验**：更高音质、更灵活的控制、更智能的适配、更省流量的策略。

**衡量指标**：

| 指标 | 目标 |
|---|---|
| 高音质使用率 | ≥ 20%（VIP 用户中） |
| 音质切换成功率 | ≥ 99.5% |
| 卡顿率（播放中断 > 1s） | ≤ 2% |
| 弱网自动降质准确率 | ≥ 90% |
| 跨设备同步延迟 | ≤ 10s |
| PWA 离线可用率 | ≥ 95% |

---

## 2. 使用角色

| 角色 | 能力 |
|---|---|
| 游客 | 仅标准音质，无离线，无跨设备同步 |
| 普通用户 | 标准/高音质、倍速、均衡器、跨设备同步、PWA 离线（缓存已播歌曲） |
| VIP 用户（预留） | 无损音质、无限离线缓存 |

> **说明**：本项目**本期不做**支付/会员体系（见 [01 章](./01-产品概述.md) Out of scope），音质等级通过**用户等级/运营配置**控制。`is_vip` 字段为**预留**。

## 3. 音质切换

### FR-21-001 音质等级与自动降级 【P1】

| 项 | 内容 |
|---|---|
| **功能目标** | 提供多档音质并智能适配网络 |
| **使用角色** | 登录用户 |

**音质等级**：

| 等级 | 代码 | 码率 | 格式 | 单曲大小（4 分钟） | 权限 |
|---|---|---|---|---|---|
| 标准 | `standard` | 128 kbps | MP3 | ~4 MB | 全部 |
| 高 | `high` | 320 kbps | MP3 | ~10 MB | 登录用户 |
| 无损 | `lossless` | 900~1100 kbps | FLAC | ~30 MB | VIP（预留） |

**自动降级策略**：

```
播放开始时根据网络状况选择音质
   ↓
[1] 检测网络类型（Network Information API）
     - 4G/5G/WiFi → 用户设定音质
     - 3G / 慢速 2G → 降为标准
     - 未检测到（Safari） → 默认标准，观察实际缓冲后调整
   ↓
[2] 用户设定优先（若用户明确选择某音质,则使用该音质）
   ↓
[3] 播放中监测卡顿
     - 连续 2 次缓冲超时（> 3s）→ 自动降一级，提示"已自动切换为标准音质"
     - 弹提示 "网络较慢，已切换为 {quality}，可在设置中关闭自动切换"
   ↓
[4] 网络恢复后**不自动升回**（避免反复切换），仅在下次播放时应用
```

**业务规则**：

- `BR-21-001`：**默认音质**：登录用户为 `high`，游客为 `standard`。
- `BR-21-002`：音质设置**持久化**（`ml:play:quality:{userId}` + `localStorage`）。
- `BR-21-003`：**自动降质**：连续 2 次缓冲超时（> 3s）自动降一级。
- `BR-21-004`：**自动降质可关闭**（设置项 `play.autoQuality`，默认开启）。
- `BR-21-005`：**不自动升质**（避免网络抖动导致反复切换）。
- `BR-21-006`：切换音质时**保留播放进度**（记录 `currentTime`，切换后恢复）。
- `BR-21-007`：**音质切换有心跳间隙**，前端需显示"切换音质中..."并暂停 UI 更新。
- `BR-21-008`：**无损音质**仅 VIP 可用，非 VIP 请求返回降级（返回 high）并提示。
- `BR-21-009**：**无对应音质音源**时降级（如某歌无 FLAC → 返回 high，提示"该歌曲暂无无损音质"）。
- `BR-21-010`：**音质偏好**影响 `t_play_history.quality` 统计（用于运营分析）。
- `BR-21-011`：**流量节省模式**（设置项）：强制标准音质 + 不预加载 + 图片降质。
- `BR-21-012`：**音质切换入口**：播放页"音质"按钮 + 设置页全局默认。
- `BR-21-013`：播放地址按音质**分别缓存**（`ml:play:url:{songId}:{quality}`）。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-21-001-1` | 请求的音源不存在 | 降级到下一档可用音质 + 提示 |
| `EX-21-001-2` | 非 VIP 请求无损 | 降级为 high + 提示"无损音质需要 VIP" |
| `EX-21-001-3` | 切换音质时网络中断 | 保持原音质继续播放，提示切换失败 |
| `EX-21-001-4` | 切换后加载失败 | 回滚到原音质并恢复进度 |
| `EX-21-001-5` | 网络类型检测不支持 | 默认标准音质，观察缓冲行为调整 |
| `EX-21-001-6` | 自动降质频繁触发 | 5 分钟内最多降 2 次，之后提示"网络不稳定" |

**验收标准**：

- `AC-21-001-1`：可切换三档音质（权限内）
- `AC-21-001-2`：切换保留播放进度
- `AC-21-001-3`：连续卡顿自动降质并提示
- `AC-21-001-4`：自动降质可关闭
- `AC-21-001-5`：非 VIP 请求无损被降级并提示
- `AC-21-001-6`：音源缺失时降级正常
- `AC-21-001-7`：音质偏好持久化
- `AC-21-001-8`：流量节省模式生效

## 4. 播放控制增强

### FR-21-002 倍速播放 【P1】

| 项 | 内容 |
|---|---|
| **功能目标** | 支持 0.5x~2.0x 倍速 |
| **使用角色** | 全部 |

**倍速档位**：`0.5x / 0.75x / 1.0x / 1.25x / 1.5x / 1.75x / 2.0x`

**实现（Web Audio API `preservesPitch`）**：

```typescript
// HTMLMediaElement.playbackRate + preservesPitch
audio.playbackRate = rate;

// 保持音高不变（避免"快进变尖"）
// 标准属性（Chrome 75+, Firefox 101+, Safari 15.4+）
audio.preservesPitch = true;
// 兼容旧前缀
(audio as any).webkitPreservesPitch = true;
(audio as any).mozPreservesPitch = true;
```

**业务规则**：

- `BR-21-014`：倍速范围 **0.5x ~ 2.0x**（超出可能音质严重失真）。
- `BR-21-015`：**保持音高**（`preservesPitch = true`），避免"快放变尖"。
- `BR-21-016`：**倍速不影响**播放计数与时长统计（上报的 `play_duration` 为**实际音频时长**，非墙钟时间）。
  - **实现**：`playedAudioDuration = (t2 - t1) * playbackRate`
- `BR-21-017`：倍速**持久化**（`localStorage`），下次播放沿用。
- `BR-21-018**：**歌词同步**在倍速下**仍然正确**（因为歌词基于 `currentTime` 计算，而 `currentTime` 是音频时间）。
- `BR-21-019`：倍速**不适用于**房间模式（房间内由服务端统一控制，速度必须为 1.0x）。
- `BR-21-020`：倍速**入口**：播放页"1.0x"按钮 → 弹出档位选择。
- `BR-21-021`：**无效播放判定**在倍速下**按音频时长**计算（2.0x 播 15 秒 = 30 秒音频 → 有效）。
- `BR-21-022`：**2.0x 以上**（如 2.5x）**不提供**（音质考虑），但可通过**长按**跳过 15 秒实现快速略过。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-21-002-1` | 浏览器不支持 preservesPitch | 仍设置 `playbackRate`（音高会变），提示"当前浏览器不支持保持音高" |
| `EX-21-002-2` | 房间模式尝试变速 | 拒绝，提示"房间内不支持变速" |
| `EX-21-002-3` | 倍速下歌词不同步 | 检查 `currentTime` 单位（秒），修正 |
| `EX-21-002-4` | 切歌后倍速丢失 | 每次 `load()` 后重新设置 `playbackRate`（浏览器会重置） |

**验收标准**：

- `AC-21-002-1`：7 档倍速可切换
- `AC-21-002-2`：2.0x 下音高不变（主观听感）
- `AC-21-002-3`：倍速下歌词同步正确
- `AC-21-002-4`：切歌后倍速保持
- `AC-21-002-5`：有效播放判定按音频时长
- `AC-21-002-6`：房间模式禁用变速

### FR-21-003 均衡器 【P2】

| 项 | 内容 |
|---|---|
| **功能目标** | 提供音效调节 |
| **使用角色** | 登录用户 |

**实现（Web Audio API）**：

```
<audio> → MediaElementAudioSourceNode
   ↓
GainNode（音量 / 音量平衡器）
   ↓
BiquadFilterNode × N（各频段 EQ）
   ↓
DynamicsCompressorNode（可选：压缩）
   ↓
AudioContext.destination
```

**预设音效**：

| 预设 | 说明 | 频段增益（Hz: dB） |
|---|---|---|
| 默认 | 不调整 | 全 0 |
| 流行 | 突出人声与中频 | 60:0, 230:0, 910:+2, 3600:+2, 14000:0 |
| 摇滚 | 突出低频与高频 | 60:+3, 230:+1, 910:-1, 3600:+2, 14000:+3 |
| 人声 | 突出中频 | 60:-2, 230:0, 910:+3, 3600:+3, 14000:-1 |
| 低音增强 | 强调低频 | 60:+6, 230:+3, 910:0, 3600:0, 14000:0 |
| 高音增强 | 强调高频 | 60:0, 230:0, 910:0, 3600:+3, 14000:+5 |
| 古典 | 平衡 | 60:+1, 230:0, 910:0, 3600:+1, 14000:+2 |

**自定义 EQ**：5 段滑块（60Hz / 230Hz / 910Hz / 3.6kHz / 14kHz），±12 dB。

**业务规则**：

- `BR-21-023`：均衡器**仅在有 Web Audio API 支持时提供**。
- `BR-21-024`：**开启均衡器**会**接管音频输出**（MediaElementSource），**注意**：
  - 一旦创建 `MediaElementAudioSourceNode`，音频**不再直接输出到扬声器**，必须通过 AudioContext 输出。
  - 若 AudioContext 因自动播放策略被挂起，会导致**无声**——必须处理 `AudioContext.resume()`。
- `BR-21-025`：**均衡器默认关闭**（避免引入复杂度与风险）。
- `BR-21-026`：**CORS 限制**：加载跨域音频时，若 CDN 未设置 `Access-Control-Allow-Origin`，`createMediaElementSource` 会**导致无声**（音频变成静音）。
  - **关键要求**：**CDN 必须**为音频响应设置 `Access-Control-Allow-Origin: *`（或具体域名）+ 音频元素设置 `crossorigin="anonymous"`。
  - **【假设 A-26】** 若 CDN 无法配置 CORS，则**不提供均衡器功能**（降级为仅预设的"音效增强"通过服务端转码实现，成本高，本期不做）。
- `BR-21-027`：均衡器设置**持久化**（`localStorage`），跨会话保持。
- `BR-21-028`：均衡器**不影响**音频下载/离线文件（仅影响本地播放）。
- `BR-21-029`：均衡器在**房间模式**下**仍然可用**（仅本地音效，不影响他人）。
- `BR-21-030`：**性能**：均衡器开启后 CPU 占用增加应 < 5%。
- `BR-21-031`：**移动端**默认隐藏均衡器（屏幕小 + 耗电）。
- `BR-21-032`：均衡器**必须有"重置"按钮**。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-21-003-1` | 浏览器不支持 Web Audio API | 隐藏均衡器功能 |
| `EX-21-003-2` | CORS 未配置导致无声 | 检测无声（`audio.volume > 0` 但无输出）→ 关闭均衡器并告警；**上线前必须验证 CDN CORS** |
| `EX-21-003-3` | AudioContext 挂起 | 在用户交互时 `resume()` |
| `EX-21-003-4` | 频段增益异常（> ±12dB） | 限制范围 |
| `EX-21-003-5` | 切换音质后均衡器失效 | 重新创建 MediaElementSource（注意：同一 audio 元素只能创建一次 source） |

> **重要技术陷阱**：`createMediaElementSource()` 对**同一个 `<audio>` 元素只能调用一次**，重复调用会抛 `InvalidStateError`。因为本项目**全局单例 audio 元素**，所以**只需创建一次**，切换歌曲**无需重建**（source 会跟随元素变化）。这是用单例 audio 的关键优势。

**验收标准**：

- `AC-21-003-1`：7 种预设音效可切换
- `AC-21-003-2`：自定义 EQ 可调节
- `AC-21-003-3`：设置持久化
- `AC-21-003-4`：切歌后均衡器仍生效
- `AC-21-003-5`：CORS 配置正确时无静音问题
- `AC-21-003-6`：重置按钮生效
- `AC-21-003-7`：房间模式下本地音效不影响他人

### FR-21-004 淡入淡出与无缝播放 【P2】

| 项 | 内容 |
|---|---|
| **功能目标** | 提升听感，减少切换突兀感 |
| **使用角色** | 全部 |

**功能**：

| 功能 | 说明 |
|---|---|
| **淡入** | 播放开始时音量从 0 渐变到设定值（300ms） |
| **淡出** | 暂停/切歌时音量渐变到 0（200ms） |
| **交叉淡化（Crossfade）** | 切歌时前一首淡出同时后一首淡入（需双 audio 元素） |
| **无缝播放（Gapless）** | 专辑连续曲目间无间隙（需预加载下一首 + 精确接续） |

**业务规则**：

- `BR-21-033`：**淡入淡出默认开启**（提升听感）。
- `BR-21-034`：**交叉淡化**（Crossfade）需要**双 audio 元素**，与"全局单例 audio"架构冲突。
  - **权衡**：交叉淡化需要同时播放两个音源。**方案**：仅在展开播放页创建第二个隐藏 audio 用于交叉淡化，切歌完成后销毁。
  - **【假设 A-27】** 交叉淡化**本期不做**（P2 且架构成本高），仅做淡入淡出。预留 `crossfadeDuration` 配置项。
- `BR-21-035`：**淡入淡出时长可配置**（默认 300ms/200ms）。
- `BR-21-036`：**暂停后恢复**不淡入（平滑恢复，避免"颤抖"）。
- `BR-21-037`：**用户拖动进度条**时不淡入。
- `BR-21-038`：**无缝播放**：专辑模式下预加载下一首，当前曲结束前 0.5 秒开始加载。
- `BR-21-039`：**淡入淡出关闭**时行为与基础播放一致。

**验收标准**：

- `AC-21-004-1`：播放有淡入效果
- `AC-21-004-2`：暂停有淡出效果
- `AC-21-004-3`：淡入淡出可关闭
- `AC-21-004-4`：恢复播放不重复淡入
- `AC-21-004-5`：专辑无缝播放（抽检）

**Service Worker 缓存策略**：

| 资源类型 | 策略 | 说明 |
|---|---|---|
| 应用外壳（HTML/JS/CSS） | `CacheFirst` + 版本更新 | 离线可打开应用 |
| 静态资源（字体/图标） | `CacheFirst`（长期） | — |
| 图片（封面/头像） | `StaleWhileRevalidate` | 优先缓存，后台更新 |
| API 请求（GET） | `NetworkFirst`（3s 超时降级缓存） | 离线可看缓存数据 |
| 音频文件 | **不缓存**（除离线下载，见下） | 音频太大，避免撑爆存储 |
| 音频（已离线下载） | `CacheFirst` | 用户主动下载的歌曲 |

**Service Worker 实现要点（Vite PWA 插件）**：

```typescript
// vite.config.ts
import { VitePWA } from 'vite-plugin-pwa';

export default defineConfig({
  plugins: [
    VitePWA({
      registerType: 'autoUpdate',        // 自动更新
      workbox: {
        globPatterns: ['**/*.{js,css,html,ico,png,svg,woff2}'],
        maximumFileSizeToCacheInBytes: 5 * 1024 * 1024,   // 5MB
        runtimeCaching: [
          {
            urlPattern: /^https:\/\/cdn\.example\.com\/.*\.(png|jpg|jpeg|webp)$/,
            handler: 'StaleWhileRevalidate',
            options: {
              cacheName: 'images',
              expiration: { maxEntries: 500, maxAgeSeconds: 30 * 24 * 60 * 60 },
              cacheableResponse: { statuses: [0, 200] },
            },
          },
          {
            urlPattern: /\/api\/v1\/(songs|playlists|artists)\/.*/,
            handler: 'NetworkFirst',
            options: {
              cacheName: 'api',
              networkTimeoutSeconds: 3,
              expiration: { maxEntries: 200, maxAgeSeconds: 24 * 60 * 60 },
            },
          },
        ],
      },
      manifest: { /* 见上 */ },
    }),
  ],
});
```

**业务规则**：

- `BR-21-040`：**必须**提供 `manifest.json` 且**通过 Lighthouse PWA 审计**。
- `BR-21-041`：Service Worker **必须**支持**安全更新**（`autoUpdate`，但避免在播放中刷新）。
- `BR-21-042`：**新版本就绪**时**必须**提示用户"有新版本，点击刷新"（不强制刷新，避免打断播放）。
- `BR-21-043`：**音频文件默认不缓存**（体积大）。
- `BR-21-044`：**缓存容量限制**：图片 500 张，API 200 条，总占用 ≤ 50MB。
- `BR-21-045`：**缓存清理**：超过容量的按 LRU 淘汰。
- `BR-21-046`：**离线状态提示**：检测 `navigator.onLine`，离线时顶部显示"当前处于离线状态"。
- `BR-21-047`：**离线可用页面**：首页（缓存数据）、我的喜欢、播放历史、已下载歌曲。
- `BR-21-048`：**离线不可用功能**：搜索、推荐、评论、私信 —— 提示"需要网络连接"。
- `BR-21-049`：**PWA 图标**必须包含 `maskable` 版本（Android 自适应图标）。
- `BR-21-050`：**安装提示**：在合适时机（用户第 3 次访问）显示"添加到主屏"提示，可关闭（30 天内不再提示）。
- `BR-21-051`：**HTTPS 必须**（Service Worker 前置条件）。

| `EX-21-005-6` | 离线时访问未缓存页面 | 显示离线页（含"网络已断开"提示与重试按钮） |

**验收标准**：

### FR-21-006 离线下载 【P2】

| 项 | 内容 |
|---|---|
| **功能目标** | 让用户离线听歌 |
| **使用角色** | 登录用户 |

**实现方案**：

| 方案 | 说明 | 限制 |
|---|---|---|
| **A. Cache API** | Service Worker 的 Cache Storage 存音频 | 需 SW 拦截；存储配额受限（浏览器通常 ≤ 60% 磁盘可用空间） |
| **B. IndexedDB (Blob)** | 存 Blob 到 IndexedDB | 更灵活；但大文件性能差 |
| **C. File System Access API** | 存到用户文件系统 | 仅 Chrome 支持；权限复杂 |

**选型**：**方案 A（Cache API）**——由 Service Worker 管理，与 PWA 架构一致。

**业务流程**：

```
用户在歌曲/歌单/专辑页点击"下载"
   ↓
[1] 检查：登录、音质权限、存储配额（navigator.storage.estimate()）
   ↓
[2] 加入下载队列（前端维护，串行下载，最多 3 个并发）
   ↓
[3] 每个歌曲：
     - 获取带签名的播放地址（签名有效期需延长到 7 天，见 BR-21-054）
     - fetch + 流式写入 Cache API（显示进度）
     - 同时缓存歌词、封面
   ↓
[4] 写入 IndexedDB 记录元数据（songId、大小、下载时间、音质、过期时间）
   ↓
[5] 完成 → 通知用户
   ↓
播放离线歌曲时：
     Service Worker 拦截音频请求 → 从 Cache 返回
```

**业务规则**：

- `BR-21-052`：**下载容量限制**：普通用户 **500 首**，VIP **无限制**（预留）。
- `BR-21-053`：**存储配额检查**：下载前检查 `navigator.storage.estimate()`，剩余不足则提示。
- `BR-21-054`：**离线播放地址签名**有效期需**延长至 7 天**（普通播放为 2 小时），或**离线时跳过签名校验**（用本地已下载文件）。
  - **实现**：离线播放走 Service Worker 缓存，**不经过签名校验**（文件已在本地）。
- `BR-21-055`：**离线文件有效期 30 天**，到期后需重新下载（版权考虑）。
- `BR-21-056`：**离线文件与账号绑定**：切换账号时**不可访问**另一账号的离线文件（存 `userId` 元数据并校验）。
- `BR-21-057`：**离线文件加密**（P2 可选）：使用 Web Crypto 加密存储，防止直接提取文件（**权衡**：增加复杂度与性能开销，本期**不做**，仅记录元数据绑定账号）。
- `BR-21-058`：**下载管理页**：展示已下载歌曲、大小、音质、删除、全部删除。
- `BR-21-059`：**下载失败**自动重试 2 次，仍失败标记为失败状态。
- `BR-21-060`：**下载中可暂停/继续**（Cache API 不支持断点续传，需重新下载；或用 Range 请求分片下载）。
  - **【假设 A-28】** 本期**不做断点续传**（实现复杂），下载中断后需重新下载。
- `BR-21-061`：**离线播放**时，播放历史**离线缓存**，联网后补报。
- `BR-21-062`：**存储清理**：浏览器可能自动清理（`navigator.storage.persist()` 申请持久化）。
- `BR-21-063`：**无版权/下架歌曲**不可下载。
- `BR-21-064`：**游客不可下载**。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-21-006-1` | 存储配额不足 | `80011`，提示清理空间或删除已下载 |
| `EX-21-006-2` | 下载超限（> 500 首） | `80012`，提示上限 |
| `EX-21-006-3` | 下载中断（网络） | 标记失败，提供重试 |
| `EX-21-006-4` | 歌曲下架 | 离线文件**立即失效**（联网时校验并删除） |
| `EX-21-006-5` | 账号切换 | 不可访问他人离线文件 |
| `EX-21-006-6` | 浏览器清理了缓存 | 离线文件失效，播放时提示需重新下载 |
| `EX-21-006-7` | 离线文件过期（30 天） | 删除并提示重新下载 |
| `EX-21-006-8` | 浏览器不支持 Cache API | 隐藏下载功能 |

**验收标准**：

- `AC-21-006-1`：可下载歌曲并离线播放
- `AC-21-006-2`：下载容量限制生效
- `AC-21-006-3`：下载管理页可查看与删除
- `AC-21-006-4`：切换账号不可访问他人离线文件
- `AC-21-006-5`：离线文件 30 天过期
- `AC-21-006-6`：下架歌曲的离线文件失效
- `AC-21-006-7`：下载失败可重试
- `AC-21-006-8`：游客不可下载

## 6. 跨设备同步

### FR-21-007 播放进度跨设备同步 【P1】

| 项 | 内容 |
|---|---|
| **功能目标** | 在 A 设备听到一半，B 设备继续 |
| **使用角色** | 登录用户 |

**同步机制**：

```
设备 A 播放
   ↓
每 30 秒上报进度：POST /api/v1/play/progress { songId, position, duration, deviceId }
   ↓
服务端存：ml:play:progress:{userId}:{songId}  Hash { position, duration, deviceId, updateTime }
          TTL 30 天
   ↓
设备 B 打开同一首歌
   ↓
GET /api/v1/play/progress?songId=xxx
   ↓
返回 { position: 62.5, deviceId: "device-A", updateTime: 1730000000000 }
   ↓
设备 B 判断：
  - 若本地无进度 → 使用服务端进度，播放条显示"继续上次播放 01:02"
  - 若本地有进度且比服务端新 → 使用本地
  - 若服务端更新 → 提示"是否从 01:02 继续播放？"（不自动跳转，避免打断）
```

**业务规则**：

- `BR-21-065`：进度上报**节流 30 秒**（避免高频写）。
- `BR-21-066`：**跨设备恢复不自动播放**（用户点击才播放）。
- `BR-21-067`：**冲突处理**：以**更新时间戳最新**的为准。
- `BR-21-068`：**同一设备**打开时使用本地进度（不查询服务端，省请求）。
- `BR-21-069`：**设备标识**：生成 `deviceId`（UUID 存 localStorage），上报时携带。
- `BR-21-070`：**进度展示**：在"继续播放"列表中标明来源设备（如"从手机继续"）。
- `BR-21-071`：**设备列表**：用户可在"账号安全"中查看登录设备，并可"退出该设备"。
- `BR-21-072`：**播放队列跨设备同步**（P2）：本期**不做**（队列数据大且价值低）。
- `BR-21-073`：**喜欢/收藏跨设备同步**：天然同步（存服务端），无需特殊处理。
- `BR-21-074`：**离线进度**：离线时进度存本地，联网后**合并**（以最新为准）。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-21-007-1` | 服务端进度比本地旧 | 用本地 |
| `EX-21-007-2` | 进度数据损坏 | 忽略，从头播放 |
| `EX-21-007-3` | 上报失败 | 静默失败，下次重试 |
| `EX-21-007-4` | 歌曲在不同设备上时长不同（音源替换） | 按百分比换算位置 |
| `EX-21-007-5` | 设备时钟不准 | 使用服务端时间戳（上报时不带客户端时间） |

**验收标准**：

- `AC-21-007-1`：A 设备进度可在 B 设备恢复
- `AC-21-007-2`：恢复不自动播放
- `AC-21-007-3`：冲突以最新为准
- `AC-21-007-4`：同设备不查服务端
- `AC-21-007-5`：设备列表可查看与登出
- `AC-21-007-6`：离线进度联网后合并

## 7. 弱网优化

### FR-21-009 弱网适配 【P1】

| 项 | 内容 |
|---|---|
| **功能目标** | 在网络差时仍可播放 |
| **使用角色** | 全部 |

**适配策略**：

| 场景 | 策略 |
|---|---|
| 网络类型 3G/2G | 强制标准音质 + 不预加载封面大图 |
| 网络类型 slow-2g | 提示"网络较慢"，仅允许流式播放 |
| 缓冲超时 > 3s | 自动降质（见 FR-21-001） |
| 缓冲超时 > 15s | 提示"网络异常" + 建议切换网络 |
| 频繁缓冲 | 预加载下一首减少间隔 |
| 离线 | 使用离线文件或提示不可用 |

**Network Information API 使用**：

```typescript
interface NetworkInformation extends EventTarget {
  readonly effectiveType: 'slow-2g' | '2g' | '3g' | '4g';
  readonly downlink: number;        // Mbps
  readonly rtt: number;             // ms
  readonly saveData: boolean;       // 用户开启省流量模式
}

const conn = (navigator as any).connection as NetworkInformation;
if (conn) {
  const applyNetworkPolicy = () => {
    const et = conn.effectiveType;
    if (et === 'slow-2g' || et === '2g') {
      player.setQuality('standard');
      player.setPreload('none');
      ui.showNetworkWarning();
    } else if (et === '3g') {
      player.setQuality('standard');
      player.setPreload('metadata');
    } else {
      player.setQuality(userPreference);
      player.setPreload('auto');
    }
    if (conn.saveData) player.enableDataSaver();
  };
  conn.addEventListener('change', applyNetworkPolicy);
  applyNetworkPolicy();
}
```

**业务规则**：

- `BR-21-081`：**必须**在播放开始前**检测网络**（若 API 支持）。
- `BR-21-082`：**弱网自动降质**见 FR-21-001。
- `BR-21-083**：**省流量模式**（`saveData`）：强制标准音质 + 不预加载 + 图片降质。
- `BR-21-084`：**网络恢复**时提示"网络已恢复"（不自动升质）。
- `BR-21-085`：**Network Information API 不支持**（Safari）时，通过**实际缓冲行为**判断：
  - 记录每次 `waiting` 事件的持续时间，若平均值 > 2s，视为弱网。
- `BR-21-086`：**弱网提示不频繁**（同一会话最多提示 2 次）。
- `BR-21-087`：**弱网下降低图片质量**（OSS 图片处理参数：`?x-oss-process=image/resize,w_96/quality,q_60`）。
- `BR-21-088`：**弱网下禁用**非必要请求（如埋点降采样 50%）。
- `BR-21-089`：**网络切换**（WiFi → 4G）时**提示**用户（可能产生流量）。
- `BR-21-090`：**弱网埋点**必须记录（网络类型、缓冲次数、卡顿时长）。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-21-009-1` | Network API 不支持 | 通过缓冲行为推断 |
| `EX-21-009-2` | 网络类型变化频繁 | 防抖 5 秒后应用策略 |
| `EX-21-009-3` | 弱网下所有音质都卡 | 提示"网络异常，请检查网络" |
| `EX-21-009-4` | 从 WiFi 切到 4G | 提示用户（避免意外耗流量） |

**验收标准**：

- `AC-21-009-1`：弱网下自动降为标准音质
- `AC-21-009-2`：省流量模式生效
- `AC-21-009-3`：网络恢复有提示
- `AC-21-009-4`：不支持 API 时有推断机制
- `AC-21-009-5`：WiFi→4G 切换有提示
- `AC-21-009-6`：弱网埋点完整

| `ml:play:url:{songId}:{quality}` | String | 播放地址缓存 | 1h |

| `ml:play:setting:{userId}` | String | 播放设置缓存 | 7 天 |
| `ml:play:download:{userId}` | Set | 已下载歌曲 ID（服务端记录，用于校验） | 永久 |
| `ml:device:{userId}` | ZSet | 用户设备（score=最后活跃时间） | 永久 |

## 12. 降级策略

| 依赖 | 故障 | 降级 |
|---|---|---|
| 高音质音源 | 不存在 | 降级为标准音质 |
| FLAC 支持 | 浏览器不支持 | 降级为 high（MP3） |
| Web Audio API | 不支持 | 隐藏均衡器 |
| CDN CORS | 未配置 | 隐藏均衡器（避免静音） |
| Network Info API | 不支持 | 通过缓冲行为推断 |
| Service Worker | 注册失败 | 正常网页可用，无离线 |
| Cache API | 不支持/配额满 | 隐藏下载功能 / 提示清理 |
| 跨设备同步服务 | 不可用 | 使用本地进度 |
| 存储配额 | 不足 | 提示清理 |
