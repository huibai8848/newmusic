# 10 · 模块 01：数据库 CRUD（通用数据访问能力）

> **优先级**：P0（全部业务模块的地基）
> **对应提示词条目**：1. 数据库 CRUD

---

## 1. 模块目标

为全部业务实体（歌曲、歌手、专辑、歌单、分类、标签、歌词、评论、用户、音乐房、动态、私信、通知等）提供**统一、标准、可复用**的增删改查能力，避免每个模块重复造轮子。

**衡量指标**：

- 新增一个实体的标准 CRUD 接口，开发者工作量 ≤ 0.5 人日。
- 所有列表接口统一支持分页/筛选/排序/模糊搜索，前端可复用同一套分页组件。
- 所有删除操作均为逻辑删除，可恢复、可审计。

---

## 2. 使用角色

| 角色 | 使用方式 |
|---|---|
| 游客 | 只读接口（列表、详情），仅限公开数据 |

| 平台管理员 / 运营 | 后台全量 CRUD |
| 超级管理员 | 含物理删除、批量高危操作 |

## 4. 技术实现方案

### 4.1 MyBatis-Plus 配置

```java
@Configuration
@MapperScan("com.example.newmusic.module.**.mapper")
public class MybatisPlusConfig {

    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();

        // 1. 分页插件（MySQL 方言）
        PaginationInnerInterceptor pagination = new PaginationInnerInterceptor(DbType.MYSQL);
        pagination.setMaxLimit(100L);          // 单页最大 100 条，防大结果集
        pagination.setOverflow(false);          // 超出总页数不回到第一页
        interceptor.addInnerInterceptor(pagination);

        // 2. 乐观锁插件（version 字段）
        interceptor.addInnerInterceptor(new OptimisticLockerInnerInterceptor());

        // 3. 防全表更新/删除（生产安全护栏）
        interceptor.addInnerInterceptor(new BlockAttackInnerInterceptor());

        // 4. 非法 SQL 拦截（防注入）
        interceptor.addInnerInterceptor(new IllegalSQLInnerInterceptor());
        return interceptor;
    }
}
```

> **`BlockAttackInnerInterceptor` 是强制项**：禁止无 `WHERE` 条件的 `UPDATE`/`DELETE`，防止误操作清库。

### 4.2 公共实体基类

```java
@Data
public abstract class BaseEntity implements Serializable {

    @TableId(type = IdType.ASSIGN_ID)          // 雪花算法
    @JsonSerialize(using = ToStringSerializer.class)  // Long → String，防 JS 精度丢失
    private Long id;

    @TableField(fill = FieldFill.INSERT)
    private LocalDateTime createTime;

    @TableField(fill = FieldFill.INSERT_UPDATE)
    private LocalDateTime updateTime;

    @TableField(fill = FieldFill.INSERT)
    private Long createBy;

    @TableField(fill = FieldFill.INSERT_UPDATE)
    private Long updateBy;

    @TableLogic                                 // 逻辑删除
    @TableField(select = false)
    private Integer deleted;

    @Version                                    // 乐观锁（有 version 字段的表才加）
    @TableField(update = "%s+1", whereStrategy = FieldStrategy.NOT_NULL)
    private Integer version;
}
```

**自动填充处理器**：

```java
@Component
public class MyMetaObjectHandler implements MetaObjectHandler {
    @Override public void insertFill(MetaObject metaObject) {
        this.strictInsertFill(metaObject, "createTime", LocalDateTime::now, LocalDateTime.class);
        this.strictInsertFill(metaObject, "updateTime", LocalDateTime::now, LocalDateTime.class);
        Long uid = UserContext.getUserId();
        this.strictInsertFill(metaObject, "createBy", () -> uid, Long.class);
        this.strictInsertFill(metaObject, "updateBy", () -> uid, Long.class);
    }
    @Override public void updateFill(MetaObject metaObject) {
        this.strictUpdateFill(metaObject, "updateTime", LocalDateTime::now, LocalDateTime.class);
        this.strictUpdateFill(metaObject, "updateBy", () -> UserContext.getUserId(), Long.class);
    }
}
```

> **注意**：MQ 消费者、定时任务等无用户上下文的场景，`createBy` 填 `0`（系统），须在 `MyMetaObjectHandler` 中兜底判空。

### 4.3 通用查询条件基类

```java
@Data
public class PageQuery {
    private Integer pageNum = 1;
    private Integer pageSize = 20;
    private String sortBy;
    private String sortOrder = "desc";
    private String keyword;              // 通用模糊搜索

    /** 归一化参数（Controller 入口调用） */
    public void normalize() {
        if (pageNum == null || pageNum < 1) pageNum = 1;
        if (pageSize == null || pageSize < 1) pageSize = 20;
        if (pageSize > 100) pageSize = 100;
        if (!"asc".equalsIgnoreCase(sortOrder) && !"desc".equalsIgnoreCase(sortOrder)) sortOrder = "desc";
        if (keyword != null) {
            keyword = keyword.trim();
            if (keyword.length() > 50) keyword = keyword.substring(0, 50);
        }
    }

    public <T> Page<T> toPage() {
        normalize();
        return new Page<>(pageNum, pageSize);
    }
}
```

### 4.4 通用 Service 基类

```java
public abstract class BaseServiceImpl<M extends BaseMapper<T>, T extends BaseEntity>
        extends ServiceImpl<M, T> implements BaseService<T> {

    /** 分页查询：自动注入逻辑删除条件与排序白名单校验 */
    protected <Q extends PageQuery> Page<T> pageQuery(Q query, QueryWrapper<T> wrapper,
                                                      Set<String> allowedSortFields) {
        applySort(wrapper, query, allowedSortFields);
        return this.page(query.toPage(), wrapper);
    }

    protected <Q extends PageQuery> void applySort(QueryWrapper<T> wrapper, Q q, Set<String> allowed) {
        String field = q.getSortBy();
        if (field == null || !allowed.contains(field)) field = "create_time";   // 白名单外回退
        boolean asc = "asc".equalsIgnoreCase(q.getSortOrder());
        wrapper.orderBy(true, asc, StrUtil.toUnderlineCase(field));
    }

    /** 安全批量删除（逻辑删除） */
    public boolean removeByIdsSafe(Collection<Long> ids) {
        if (CollUtil.isEmpty(ids)) return false;
        if (ids.size() > 500) throw new BizException(ResultCode.BATCH_SIZE_EXCEEDED);
        return this.removeByIds(ids);
    }
}
```

### 4.5 通用 Controller 基类（可选）

```java
public abstract class BaseController<S extends BaseService<T>, T extends BaseEntity> {

    @Autowired protected S service;

    @GetMapping("/{id}")
    public R<T> detail(@PathVariable Long id) { return R.ok(service.getByIdOrThrow(id)); }

    @DeleteMapping("/{id}")
    public R<Void> delete(@PathVariable Long id) {
        service.removeByIdSafe(id);   // 逻辑删除
        return R.ok();
    }

    @DeleteMapping("/batch")
    public R<Void> batchDelete(@RequestBody @NotEmpty List<Long> ids) {
        service.removeByIdsSafe(ids);
        return R.ok();
    }
}
```

## 5. 功能需求明细

### FR-10-001 通用分页查询 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 任意列表资源支持分页、条件筛选、排序、模糊搜索 |
| **使用角色** | 全部角色（按数据权限可见性不同） |
| **前置条件** | 已登录（部分公开资源允许游客） |

**操作流程**：

1. 前端发起 `GET /api/v1/{module}/{resource}?pageNum=1&pageSize=20&sortBy=createTime&sortOrder=desc&keyword=xxx&其他筛选字段...`
2. 后端 `PageQuery.normalize()` 归一化参数（页码、页大小、排序方向）。
3. 构建 `QueryWrapper`：拼接筛选条件 → 拼接模糊搜索 → 拼接数据权限 → 应用排序白名单。
4. 执行分页查询，返回 `PageResult<T>`。
5. 若 `pageNum > 100`，自动切换为游标分页（`lastId` + `LIMIT`）。

**业务规则**：

- `BR-10-001`：`pageSize > 100` 强制截断为 100，并在响应中标记 `truncated: true`。
- `BR-10-002`：`sortBy` 必须在**接口级白名单**内，否则回退默认排序，**不报错**。
- `BR-10-003`：默认排序为 `create_time DESC`（除排行榜类，默认 `hot_score DESC`）。
- `BR-10-004`：所有列表查询**自动附加** `deleted = 0`（MyBatis-Plus 逻辑删除自动处理）。
- `BR-10-005`：模糊搜索字段由各接口显式指定，**禁止** `LIKE '%kw%'` 跨所有列（性能与安全）。
- `BR-10-006`：`keyword` 长度限制 50 字符，超出截断；特殊字符 `%`、`_`、`\` 转义。

**模糊搜索字段配置示例**：

```java
// 歌曲列表：仅在 name / artistName / albumName 上模糊
public static final Set<String> SONG_SEARCH_FIELDS = Set.of("name", "artist_name", "album_name");

if (StrUtil.isNotBlank(query.getKeyword())) {
    String kw = escapeLike(query.getKeyword());
    wrapper.and(w -> {
        for (String f : SONG_SEARCH_FIELDS) {
            w.or().like(f, kw);
        }
    });
}
```

> **性能提示**：`LIKE '%kw%'` 无法走索引，歌曲表在数据量 > 100 万后必须改走 **Elasticsearch**（见 [15 章](./15-模块06-搜索与AI搜索.md)）。MySQL 模糊仅作为 ES 不可用时的**降级方案**。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-10-001-1` | `pageNum` 为负数或非数字 | 归一化为 1 |
| `EX-10-001-2` | `pageSize` 超大（如 10000） | 截断为 100 + 标记 |
| `EX-10-001-3` | `sortBy` 传入 SQL 片段 | 白名单拦截，回退默认排序，记录 WARN 日志 |
| `EX-10-001-4` | 深分页（pageNum=10000） | 自动游标分页；若无法支持则返回最大 100 页并提示"请使用筛选缩小范围" |
| `EX-10-001-5` | 查询结果为空 | 返回 `list: [], total: 0`，非错误 |
| `EX-10-001-6` | 数据库超时 | 返回 `90002`，触发告警 |

**验收标准**：

- `AC-10-001-1`：请求 `pageSize=999` 时，实际返回 ≤ 100 条且 `truncated=true`。
- `AC-10-001-2`：`sortBy=1;DROP TABLE` 时接口正常返回默认排序，无异常。
- `AC-10-001-3`：`pageNum=1000` 时响应时间 < 500ms。
- `AC-10-001-4`：`keyword` 含 `%` 时不匹配全表，只按字面匹配。
- `AC-10-001-5`：列表接口不返回 `deleted=1` 的数据。

### FR-10-002 通用详情查询 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 按 ID 查询单条记录，支持缓存 |
| **使用角色** | 全部角色 |

**业务规则**：

- `BR-10-007`：详情查询**优先走 Redis 缓存**（Key 规范见 [12 章](./12-模块03-Redis缓存.md)），未命中回源 DB 并回写。
- `BR-10-008`：记录不存在或 `deleted=1` 返回对应业务错误码（如 `30001` 歌曲不存在）。
- `BR-10-009`：数据权限校验（例：私密歌单非本人不可见 → `30004`）。
- `BR-10-010`：详情响应**不包含**内部字段（`deleted`、`version`、`create_by`）。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-10-002-1` | ID 不存在 | 返回业务错误码 + 空 data |
| `EX-10-002-2` | ID 格式非法（非数字字符串） | `10001` 参数校验失败 |
| `EX-10-002-3` | 记录已被逻辑删除 | 同"不存在"处理 |
| `EX-10-002-4` | 无权限查看（私密资源） | `40301` 或业务码 |

**验收标准**：

- `AC-10-002-1`：详情接口第二次请求命中缓存（Redis `keyspace_hits` 增长）。
- `AC-10-002-2`：响应体不含 `deleted` / `version` / `createBy` 字段。

### FR-10-003 通用新增 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 创建资源，自动填充审计字段与主键 |
| **使用角色** | 登录用户 / 管理员 |

**操作流程**：

1. 前端提交 `POST`，body 为 `XxxCreateReq`。
2. `@Valid` 校验基础字段。
3. Service 层业务校验（唯一性、状态、权限、配额）。
4. 构建实体，`save()`，自动填充 `id/createTime/createBy`。
5. 返回新建资源 ID 或详情。
6. 发布领域事件（如需，如 `SongCreatedEvent`）。

**业务规则**：

- `BR-10-011`：主键由雪花算法生成，**不接受**前端传入 `id`。
- `BR-10-012`：`createTime` / `createBy` 由框架自动填充，**不接受**前端传入。
- `BR-10-013`：唯一性冲突由 DB 唯一索引兜底，捕获 `DuplicateKeyException` 转为业务错误码。
- `BR-10-014`：新增涉及 Cache 的资源时，**不做**缓存预热（懒加载），避免写放大。
- `BR-10-015`：需要幂等的新增接口必须加 `@Idempotent` 注解。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-10-003-1` | 必填字段缺失 | `10001`，message 指明具体字段 |
| `EX-10-003-2` | 唯一键冲突 | 业务码（如 `20009` 昵称已存在） |
| `EX-10-003-3` | 无权限创建 | `40301` |
| `EX-10-003-4` | 超出配额（如歌单数已达 100） | 专属业务码 + 提示 |
| `EX-10-003-5` | 重复提交 | `@Idempotent` 拦截返回 `10005` |
| `EX-10-003-6` | DB 写入失败 | `90002` + 事务回滚 |

**验收标准**：

- `AC-10-003-1`：并发提交两次相同请求（含幂等键），仅创建 1 条。
- `AC-10-003-2`：前端传入 `id`、`createTime` 被忽略。
- `AC-10-003-3`：创建后 `create_by` 为当前登录用户 ID。
- `AC-10-003-4`：创建失败时事务完整回滚（无脏数据）。

### FR-10-004 通用更新 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 修改资源，支持全量（PUT）与局部（PATCH） |
| **使用角色** | 资源所有者 / 管理员 |

**业务规则**：

- `BR-10-016`：**数据权限强校验**：非所有者且无管理权限 → `40301`。
- `BR-10-017`：更新时 `updateTime` / `updateBy` 自动填充。
- `BR-10-018`：使用**乐观锁**（`version`）防并发覆盖；版本冲突返回 `10008`（数据已被他人修改，请刷新重试）。
- `BR-10-019`：不可更新字段白名单外置（`id`、`createTime`、`createBy`、计数字段）。
- `BR-10-020`：更新成功后**必须删除**相关 Redis 缓存（Cache-Aside 删除模式）。
- `BR-10-021`：状态机约束——非法状态迁移直接拒绝（如 `已上架 → 已上架` 的重复操作幂等返回成功）。

**乐观锁实现**：

```java
Song song = songMapper.selectById(id);          // 携带 version
song.setName(req.getName());
int rows = songMapper.updateById(song);         // WHERE id=? AND version=?
if (rows == 0) throw new BizException(ResultCode.CONCURRENT_MODIFY_CONFLICT);
```

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-10-004-1` | 资源不存在 | 业务码 |
| `EX-10-004-2` | 无权限（改他人资源） | `40301` |
| `EX-10-004-3` | 并发修改冲突 | `10008` + 前端自动刷新 |
| `EX-10-004-4` | 状态非法迁移 | 业务码 + 说明当前状态 |
| `EX-10-004-5` | 缓存删除失败 | 记 ERROR 日志 + 依赖 TTL 兜底过期 |

**验收标准**：

- `AC-10-004-1`：A、B 同时编辑同一歌曲，B 提交后返回 `10008`。
- `AC-10-004-2`：用户编辑他人歌单返回 `40301`。
- `AC-10-004-3`：更新成功后立刻查询详情，返回新值（缓存已失效）。
- `AC-10-004-4`：传入 `id`、`createTime` 字段被忽略。

### FR-10-005 通用删除（逻辑删除）【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 删除资源，保留数据可追溯、可恢复 |
| **使用角色** | 资源所有者 / 管理员 / 超管 |

**业务规则**：

- `BR-10-022`：**所有业务删除均为逻辑删除**（`deleted=1`），数据物理保留。
- `BR-10-023`：逻辑删除后，所有列表/详情查询默认不可见（MyBatis-Plus `@TableLogic` 自动过滤）。
- `BR-10-024`：删除关联数据时须**级联逻辑删除**（如删歌单 → 删 `t_playlist_song` 关联）。
- `BR-10-025`：**物理删除**仅超级管理员可执行，且必须走审批（`t_approval`），记录 `t_operation_log`（`is_sensitive=1`）。
- `BR-10-026`：删除后**必须清理**相关缓存、ES 文档、向量库记录。
- `BR-10-027`：支持恢复（`deleted=0`），仅管理员可操作，恢复需同步回各存储。

**删除传播链（以删除歌曲为例）**：

```
删歌曲
 ├─ t_song.deleted = 1
 ├─ 删 Redis: ml:music:song:{id}
 ├─ 删 ES 文档: music_song/_doc/{id}
 ├─ 删向量库: music_song_vec/{id}
 ├─ 更新歌手/专辑的 song_count - 1
 ├─ 关联歌单: t_playlist_song 逻辑删除 + 通知歌单作者（可选）
 └─ 记操作日志
```

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-10-005-1` | 删除他人资源 | `40301` |
| `EX-10-005-2` | 批量删除超过 500 条 | 拒绝，提示分批 |
| `EX-10-005-3` | ES 删除失败 | 记 ERROR + 重试队列；不影响 DB 删除结果 |
| `EX-10-005-4` | 重复删除 | 返回成功（幂等） |
| `EX-10-005-5` | 无 `WHERE` 条件的删除 | `BlockAttackInnerInterceptor` 抛异常 |

**验收标准**：

- `AC-10-005-1`：删除后 DB 中该行仍存在且 `deleted=1`。
- `AC-10-005-2`：删除后列表接口不再返回该数据。
- `AC-10-005-3`：删除歌曲后 ES 中对应文档消失（30 秒内）。
- `AC-10-005-4`：普通管理员执行物理删除被拒绝并要求审批。

### FR-10-006 批量操作 【P1】

| 项 | 内容 |
|---|---|
| **功能目标** | 批量新增/更新/删除，提升后台操作效率 |
| **使用角色** | 管理员 / 运营 |

**业务规则**：

- `BR-10-028`：单次批量上限 **500 条**，超出返回 `10009`。
- `BR-10-029`：批量操作采用**分批提交**（每批 200 条），避免大事务。
- `BR-10-030`：批量操作**部分失败**时，默认**整体回滚**（原子性）；后台管理类的批量（如批量上下架）可选择**尽力而为模式**，返回成功/失败明细。
- `BR-10-031`：批量操作必须记录操作日志（含 ID 列表摘要）。
- `BR-10-032`：批量接口须做**幂等**处理（基于请求体 hash）。

**响应结构**：

```json
{
  "total": 100,
  "successCount": 98,
  "failCount": 2,
  "failDetails": [
    { "id": "1857...001", "reason": "歌曲不存在" },
    { "id": "1857...002", "reason": "无权操作" }
  ]
}
```

**验收标准**：

- `AC-10-006-1`：批量 501 条被拒绝。
- `AC-10-006-2`：批量操作耗时 500 条 < 3 秒。
- `AC-10-006-3`：返回结果包含成功/失败明细。

### FR-10-007 条件筛选与高级查询 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 支持多条件组合、范围查询、枚举筛选 |
| **使用角色** | 全部 |

**支持的筛选类型**：

| 类型 | 示例 | 实现 |
|---|---|---|
| 等值 | `status=1` | `eq` |
| 多值 | `genre=流行,摇滚` | `in` |
| 范围（数值） | `bpmMin=120&bpmMax=180` | `ge` / `le` |
| 范围（时间） | `startTime=...&endTime=...` | `ge` / `le` |
| 模糊 | `keyword=晴天` | `like`（指定字段） |
| 空值判断 | `artistId=0` 表示"无专辑" | `isNull` |
| 排除 | `excludeIds=1,2,3` | `notIn` |

**业务规则**：

- `BR-10-033`：筛选条件之间为 **AND**；同一字段的多值为 **OR**（`in`）。
- `BR-10-034`：范围参数 `min > max` 时返回 `10001` 参数错误。
- `BR-10-035`：`excludeIds` 上限 200 个。
- `BR-10-036`：时间范围跨度上限 1 年（防大范围扫描）。

**验收标准**：

- `AC-10-007-1`：多条件组合筛选结果正确。
- `AC-10-007-2`：`bpmMin=200&bpmMax=100` 返回 `10001`。
- `AC-10-007-3`：`excludeIds` 超过 200 个返回错误。

### FR-10-008 数据导出 【P2】

| 项 | 内容 |
|---|---|
| **功能目标** | 后台将列表数据导出为 Excel/CSV |
| **使用角色** | 管理员 / 运营 |

**业务规则**：

- `BR-10-037`：单次导出上限 **10 万行**，超出提示缩小筛选范围。
- `BR-10-038`：导出 > 1 万行时**异步生成**，完成后通过站内通知提供下载链接（链接有效期 24h）。
- `BR-10-039`：导出内容**脱敏**（手机号 `138****8888`、邮箱部分掩码）。
- `BR-10-040`：导出操作记录日志（导出人、条数、筛选条件）。

**验收标准**：

- `AC-10-008-1`：导出 10 万行数据，文件内容完整且已脱敏。
- `AC-10-008-2`：超 1 万行导出异步执行，用户可继续操作。

## 7. 异常与降级策略

| 场景 | 策略 |
|---|---|
| Redis 不可用 | 详情查询直连 DB（`@Cacheable` 的 `cacheManager` 降级为 `NoOpCacheManager`） |
| DB 主库不可用 | 读请求切从库（只读）；写请求返回 `90002` + 告警 |
| 批量操作超时 | 拆分重试；失败明细返回给用户 |
| 缓存删除失败 | 记 ERROR + 依赖 TTL 兜底 |
