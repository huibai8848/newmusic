# 15 · 模块 06：音乐搜索 + AI 搜索

[← 上一章：模块05 音乐房](./14-模块05-音乐房.md) | [返回目录](./README.md) | [下一章：模块07 播放与歌词 →](./16-模块07-播放与歌词.md)

> **优先级**：关键词搜索 P0；AI 搜索 P1
> **对应提示词条目**：6. 音乐搜索 + AI

---

## 1. 模块目标

1. **关键词搜索**：让用户用最少的输入精准找到歌曲、歌手、专辑、歌单、歌词。
2. **AI 搜索**：让用户用自然语言（"适合跑步的周杰伦快歌"）直接表达意图，系统理解并返回结果 + 解释。

**衡量指标**：

| 指标 | 目标 |
|---|---|
| 搜索接口 P95 | ≤ 200ms |
| 搜索联想 P95 | ≤ 100ms |
| 搜索成功率（有点击/总搜索） | ≥ 75% |
| 搜索结果首屏命中率（Top10 内命中） | ≥ 80% |
| AI 搜索采纳率（点击结果/发起次数） | ≥ 50% |
| AI 搜索 P95 耗时 | ≤ 3s |
| AI 搜索缓存命中率 | ≥ 40% |

---

## 2. 使用角色

| 角色 | 能力 |
|---|---|
| 游客 | 关键词搜索、联想、热搜（只读），AI 搜索限 5 次/天 |
| 普通用户 | 全部搜索能力 + 搜索历史 + 无限 AI 搜索（有限流） |
| 运营 | 配置热搜词、同义词、停用词、置顶搜索词 |

---

## 3. 前置条件

- Elasticsearch 7.17 集群可用，已安装 IK 分词插件。
- 索引已创建（`music_song`、`music_artist`、`music_album`、`music_playlist`）。
- 数据同步管道（MySQL → ES）已建立。
- Redis 可用（热搜、历史、联想缓存）。
- AI 服务（LLM）可用的前提下启用 AI 搜索（可降级）。

## 4. 关键词搜索

### FR-15-001 多字段关键词搜索 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 一次输入，跨字段命中歌曲名/歌手/专辑/歌词/标签 |
| **使用角色** | 全部 |
| **前置条件** | ES 索引已建立并同步 |

**操作流程**：

1. 用户在搜索框输入关键词，回车或点击搜索（或 300ms 防抖触发联想）。
2. 前端 `GET /api/v1/search?keyword=晴天&type=all&pageNum=1&pageSize=20`
3. 服务端：
   - 参数校验（长度 ≤ 50，去首尾空格，非法字符过滤）
   - 敏感词检查（命中则拦截并提示）
   - 查询 Redis 热搜/联想缓存
   - 构造 ES 查询（`multi_match` + 字段权重 + 过滤 + 排序）
   - 执行查询，高亮匹配片段
   - 异步记录搜索历史与热搜
4. 返回分类结果（综合 Tab 返回各类 Top N；分类 Tab 返回该类分页列表）。

**ES 查询构造**：

```json
{
  "query": {
    "bool": {
      "must": [
        {
          "multi_match": {
            "query": "晴天",
            "fields": [
              "name^5",            // 歌曲名权重最高
              "name.pinyin^3",     // 拼音全拼
              "name.pinyin_first^4",// 拼音首字母
              "artist_name^3",     // 歌手名
              "album_name^2",      // 专辑名
              "tags^2",            // 标签
              "lyric^1"            // 歌词（权重最低，避免噪音）
            ],
            "type": "best_fields",
            "operator": "or",
            "minimum_should_match": "70%",
            "fuzziness": "AUTO"    // 容错，允许 1~2 个字符错误
          }
        }
      ],
      "filter": [
        { "term": { "status": 1 } },
        { "term": { "audit_status": 1 } },
        { "term": { "copyright_status": 1 } }
      ],
      "should": [
        { "function_score": { "field_value_factor": { "field": "hot_score", "factor": 0.001, "modifier": "log1p" } } }
      ]
    }
  },
  "sort": [
    { "_score": "desc" },
    { "hot_score": "desc" }
  ],
  "highlight": {
    "pre_tags": ["<em class=\"hl\">"],
    "post_tags": ["</em>"],
    "fields": { "name": {}, "artist_name": {}, "album_name": {}, "lyric": { "fragment_size": 100 } }
  },
  "from": 0,
  "size": 20
}
```

**排序策略**：

```
最终得分 = ES _score (相关性)
         + hot_score × 0.001 (热度，log1p 平滑)
         + 运营加权 (sort_weight × 0.01)
         - 时间衰减 (若为"最新"排序则反向)
```

**业务规则**：

- `BR-15-001`：关键词长度 1-50 字符；为空时返回热搜 + 历史。
- `BR-15-002`：关键词**必须**经过敏感词过滤，命中拦截级词汇返回 `50002`。
- `BR-15-003`：搜索结果**只返回** `status=1 且 audit_status=1 且 copyright_status=1` 的歌曲（无版权歌曲在搜索中标记"无版权"但可展示，点击不可播放）。
- `BR-15-004`：综合 Tab 返回：歌曲 10 条 + 歌手 3 条 + 专辑 3 条 + 歌单 3 条。
- `BR-15-005`：搜索结果**高亮**匹配片段（`<em>` 标签）。
- `BR-15-006`：搜索历史**异步**记录（不阻塞响应），仅登录用户记录。
- `BR-15-007`：热搜**异步**记录（`ZINCRBY`）。
- `BR-15-008`：搜索请求**限流**：游客 30 次/分钟，登录用户 60 次/分钟。
- `BR-15-009`：ES 不可用时**降级**：MySQL `LIKE` 查询（仅歌曲名 + 歌手名），提示"搜索结果可能不完整"。
- `BR-15-010`：单次搜索最多返回 1000 条（`from + size ≤ 1000`），超出使用游标（`search_after`）。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-15-001-1` | ES 集群不可用 | 降级 MySQL LIKE，响应头标记 `degraded: true` |
| `EX-15-001-2` | 关键词含敏感词 | `50002`，不返回结果 |
| `EX-15-001-3` | 关键词超长 | `70002`，前端提示"关键词过长" |
| `EX-15-001-4` | 无结果 | 返回空列表 + 推荐搜索词（`70003`） |
| `EX-15-001-5` | ES 查询超时（> 3s） | 熔断，返回降级结果 |
| `EX-15-001-6` | 深分页（> 1000） | 切换 `search_after` 游标 |
| `EX-15-001-7` | 关键词为纯符号 | 返回空结果 + 提示 |

**验收标准**：

- `AC-15-001-1`：搜索"晴天"能在 Top 3 命中《晴天》
- `AC-15-001-2`：搜索"周杰伦"返回该歌手及其歌曲
- `AC-15-001-3`：搜索歌词片段能命中对应歌曲
- `AC-15-001-4`：搜索"qingtian"（拼音）能命中《晴天》
- `AC-15-001-5`：搜索结果 P95 ≤ 200ms
- `AC-15-001-6`：ES 停止后搜索仍可用（降级）
- `AC-15-001-7`：搜索结果高亮正确

### FR-15-002 拼音搜索 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 支持全拼、首字母、混合输入 |
| **使用角色** | 全部 |

**支持的输入形式**：

| 输入 | 期望命中 | 说明 |
|---|---|---|
| `qingtian` | 晴天 | 全拼 |
| `qt` | 晴天 | 首字母 |
| `zhoujielun` | 周杰伦 | 歌手全拼 |
| `zjl` | 周杰伦 | 歌手首字母 |
| `qingt` | 晴天 | 部分拼音 |

**实现方案**：

1. **索引字段**：为 `name`、`artist_name`、`album_name` 建立拼音子字段。

```json
{
  "mappings": {
    "properties": {
      "name": {
        "type": "text",
        "analyzer": "ik_max_word",
        "fields": {
          "pinyin":       { "type": "text", "analyzer": "pinyin_analyzer" },
          "pinyin_first": { "type": "text", "analyzer": "pinyin_first_analyzer" }
        }
      }
    }
  }
}
```

2. **索引时**：使用 `elasticsearch-analysis-pinyin` 插件自动生成拼音（无需应用层处理）。

```json
{
  "settings": {
    "analysis": {
      "analyzer": {
        "pinyin_analyzer": {
          "tokenizer": "pinyin_tokenizer"
        },
        "pinyin_first_analyzer": {
          "tokenizer": "pinyin_first_tokenizer"
        }
      },
      "tokenizer": {
        "pinyin_tokenizer": {
          "type": "pinyin",
          "keep_first_letter": true,
          "keep_full_pinyin": true,
          "keep_joined_full_pinyin": true,
          "keep_original": true,
          "limit_first_letter_length": 16
        },
        "pinyin_first_tokenizer": {
          "type": "pinyin",
          "keep_first_letter": true,
          "keep_full_pinyin": false,
          "keep_original": true
        }
      }
    }
  }
}
```

> **【假设 A-18】** 使用 `elasticsearch-analysis-pinyin`（medcl 版）7.17.10。备选：应用层用 `pinyin4j` 生成拼音字段后写入。选择插件方案是因为**无需应用层改造**且 ES 升级更平滑。

**业务规则**：

- `BR-15-011`：拼音字段权重低于原文字段（`name^5` vs `name.pinyin^3`），保证中文精确匹配优先。
- `BR-15-012`：首字母匹配（`qt`）要求**完整词边界匹配**，避免大量误召回（如 `q` `t` 匹配过多）。
- `BR-15-013`：拼音搜索仅对歌曲名、歌手名、专辑名生效，**不**对歌词生效。
- `BR-15-014`：输入检测：若输入全为 ASCII 字母，则同时检索原文与拼音字段；若含中文，则仅检索原文（省性能）。

**验收标准**：

- `AC-15-002-1`：`qingtian` 命中《晴天》
- `AC-15-002-2`：`qt` 命中《晴天》
- `AC-15-002-3`：`zjl` 命中歌手"周杰伦"
- `AC-15-002-4`：拼音搜索不影响中文搜索的排序（中文结果仍优先）

### FR-15-003 搜索联想（Suggest）【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 输入时实时给出候选词，减少输入成本 |
| **使用角色** | 全部 |

**操作流程**：

1. 用户输入 → 前端防抖 300ms → `GET /api/v1/search/suggest?keyword=周&limit=10`
2. 服务端查 Redis `ml:search:suggest:{prefix}`（TTL 1h）
3. 未命中 → 调用 ES Completion Suggester 或 `prefix` 查询 → 写缓存
4. 返回候选项（含类型标记：歌曲/歌手/专辑/歌单）

**响应结构**：

```json
{
  "suggestions": [
    { "text": "周杰伦", "type": "artist", "id": "1857...", "highlight": "<em>周</em>杰伦" },
    { "text": "晴天",   "type": "song",   "id": "1857...", "extra": "周杰伦" },
    { "text": "周深",   "type": "artist", "id": "1857...", "highlight": "<em>周</em>深" }
  ],
  "hotWords": ["周杰伦", "周深", "晴天", "小情歌"]
}
```

**业务规则**：

- `BR-15-015`：联想结果上限 10 条。
- `BR-15-016`：联想**按类型分组排序**：歌手 > 歌曲 > 专辑 > 歌单。
- `BR-15-017`：联想接口**必须**极快（P95 ≤ 100ms），走缓存 + ES prefix 查询。
- `BR-15-018`：联想词**过滤敏感词与低质词**（如纯符号、单字符）。
- `BR-15-019`：输入 < 1 字符不触发联想；输入为空格不触发。
- `BR-15-020`：联想缓存 Key 只取**前 8 个字符**作为 prefix，提高缓存命中率。
- `BR-15-021`：无联想结果时返回热搜词兜底。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-15-003-1` | ES 超时 | 返回缓存的上次结果或热搜兜底 |
| `EX-15-003-2` | 无匹配 | 返回热搜词 |
| `EX-15-003-3` | 高频请求 | 前端防抖 + 服务端限流 |

**验收标准**：

- `AC-15-003-1`：输入"周"后 300ms 内返回联想，P95 ≤ 100ms
- `AC-15-003-2`：联想结果按类型分组
- `AC-15-003-3`：联想结果不含敏感词

### FR-15-004 搜索历史 【P1】

| 项 | 内容 |
|---|---|
| **功能目标** | 快速重搜，提升回访效率 |
| **使用角色** | 登录用户 |

**业务规则**：

- `BR-15-022`：历史保留最近 **20** 条，存储在 `ml:search:his:{userId}`（List）+ `t_search_history`（落库用于分析）。
- `BR-15-023`：重复搜索时**去重并置顶**（`LREM` + `LPUSH`）。
- `BR-15-024`：用户可删除单条或清空全部。
- `BR-15-025`：历史**仅自己可见**，不对外暴露。
- `BR-15-026`：历史保存在服务端（跨设备同步），同时本地存一份用于未登录场景。
- `BR-15-027`：搜索历史**不记录**敏感词搜索结果。

**接口**：

| 功能 | 方法 | 路径 |
|---|---|---|
| 获取历史 | GET | `/api/v1/search/history` |
| 删除单条 | DELETE | `/api/v1/search/history?keyword=xxx` |
| 清空 | DELETE | `/api/v1/search/history/all` |

**验收标准**：

- `AC-15-004-1`：历史最多 20 条
- `AC-15-004-2`：重复搜索置顶且不重复
- `AC-15-004-3`：跨设备同步（同账号不同浏览器一致）
- `AC-15-004-4`：清空后历史为空

### FR-15-005 热搜榜 【P1】

| 项 | 内容 |
|---|---|
| **功能目标** | 展示平台当下热门搜索，引导发现 |
| **使用角色** | 全部 |

**业务规则**：

- `BR-15-028`：热搜实时统计在 `ml:search:hot:realtime`（ZSet，`ZINCRBY` 累加）。
- `BR-15-029`：热搜榜 Top 10，**过滤**敏感词、低质词（纯符号、单字符、超高频无意义词）。
- `BR-15-030`：运营可**置顶**指定词（`is_top=1`），置顶词始终排在最前（最多 3 个）。
- `BR-15-031`：热搜榜每小时落库 `t_search_hot`，用于趋势与历史分析。
- `BR-15-032`：热搜榜**每 5 分钟**刷新一次展示（不必实时，避免炒作）。
- `BR-15-033`：热搜词支持**标记**（`热`/`新`/`爆`），依据增速计算。
- `BR-15-034`：热搜榜**不展示**搜索量（避免刷榜动机），仅展示排名。

**增速标记规则**：

```
增速 = 当前周期搜索量 / 上一周期搜索量
- 增速 > 5  且排名上升 → 标记 "爆"
- 增速 > 3               → 标记 "热"
- 首次进入 Top10 且为 24h 内新词 → 标记 "新"
```

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-15-005-1` | 刷榜（单用户高频搜同一词） | 同用户同词 1 分钟内只计 1 次 |
| `EX-15-005-2` | 热搜 ZSet 丢失 | 从 `t_search_hot` 重建最近一天数据 |
| `EX-15-005-3` | 榜单为空 | 展示运营配置的默认词 |

**验收标准**：

- `AC-15-005-1`：热搜榜 Top10 正确
- `AC-15-005-2`：热搜榜不含敏感词
- `AC-15-005-3`：同用户刷榜不计入
- `AC-15-005-4`：运营置顶词排在最前

| **使用角色** | 全部 |

**筛选维度**：

| 维度 | 取值 | 适用 |
|---|---|---|

| 排序 | 说明 |

- `BR-15-038`：筛选+关键词的组合结果数 > 0 时正常返回，= 0 时提示"没有符合条件的结果，试试放宽筛选"。
- `BR-15-039`：筛选状态**同步到 URL**（可分享/刷新保持）。

**验收标准**：

- `AC-15-006-1`：多条件筛选结果正确
- `AC-15-006-2`：筛选条件用 filter 实现（`_score` 不变）
- `AC-15-006-3`：无结果时提示放宽筛选
- `AC-15-006-4`：刷新页面筛选条件保持

### FR-15-007 搜索数据同步（MySQL → ES）【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | 保证 ES 与 MySQL 数据一致 |
| **使用角色** | 系统内部 |

**同步策略**：

| 方式 | 说明 | 延迟 | 适用 |
|---|---|---|---|
| **MQ 增量同步** | 歌曲变更 → 投递 MQ → 消费者写 ES | 秒级 | 主方案 |
| **定时全量对账** | 每日凌晨全量比对，修复差异 | 天级 | 兜底 |
| **双写（否决）** | 事务中同时写 MySQL 与 ES | — | 不用（易不一致） |

**实现**：

```java
// 1. 歌曲变更后投递 MQ（在事务提交后）
@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
public void onSongChanged(SongChangedEvent event) {
    rocketMQTemplate.syncSend("ml_search_sync_v1",
        SearchSyncMsg.of("song", event.getSongId(), event.getOp()));  // op: UPSERT / DELETE
}

// 2. 消费者同步 ES
@RocketMQMessageListener(topic = "ml_search_sync_v1", consumerGroup = "ml-search-sync-group")
public class SearchSyncConsumer implements RocketMQListener<String> {
    public void onMessage(String body) {
        SearchSyncMsg msg = JSON.parseObject(body, SearchSyncMsg.class);
        if ("DELETE".equals(msg.getOp())) {
            esClient.delete(index, msg.getId());
        } else {
            SongDoc doc = buildSongDoc(msg.getId());   // 从 MySQL 组装文档
            esClient.index(index, msg.getId(), doc);
        }
    }
}
```

**业务规则**：

- `BR-15-040`：同步**必须在事务提交后**投递（`@TransactionalEventListener`），避免读到未提交数据。
- `BR-15-041`：同步失败重试 3 次（指数退避），仍失败入死信队列 + 告警。
- `BR-15-042`：每日凌晨 3 点执行**全量对账**：比对 MySQL 与 ES 的 ID 集合与 `update_time`，修复差异。
- `BR-15-043`：批量变更（如批量上下架）合并为一次批量 ES 操作（`bulk`）。
- `BR-15-044`：ES 写入使用**版本控制**（`version_type=external`，版本号为 MySQL `update_time` 时间戳），防止乱序覆盖。
- `BR-15-045`：索引重建（Mapping 变更）时使用**别名切换**（`music_song_v1` → `music_song`），零停机。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-15-007-1` | MQ 消息丢失 | 全量对账任务修复 |
| `EX-15-007-2` | ES 写入失败 | 重试 → 死信队列 → 告警 + 对账修复 |
| `EX-15-007-3` | 消息乱序 | 用 `update_time` 作为外部版本号，旧版本被拒绝 |
| `EX-15-007-4` | ES 集群故障 | 消息积压，恢复后自动消费；搜索降级 MySQL |

**验收标准**：

- `AC-15-007-1`：歌曲上架后 5 秒内在 ES 可搜到
- `AC-15-007-2`：歌曲下架后 5 秒内在 ES 搜不到
- `AC-15-007-3`：乱序消息不会覆盖新数据
- `AC-15-007-4`：全量对账任务能修复人为制造的差异

### FR-15-008 AI 自然语言搜索 【P1】

| 项 | 内容 |

| **功能目标** | 用户用自然语言描述需求，系统理解并返回结果 |
| **使用角色** | 登录用户（游客限 5 次/天） |
| **前置条件** | AI 服务（LLM）可用；歌曲有情绪/场景/BPM 标注 |

**示例查询**：

| 自然语言输入 | 期望理解 |
|---|---|

| "适合睡前听的轻音乐" | 场景=睡前；风格=轻音乐/纯音乐；能量低 |

| "像《晴天》那样的歌" | 相似歌曲（向量召回） |
| "今年最火的华语流行" | 年份=当年；语种=国语；流行；按热度 |
| "适合写代码听的没有人声的" | 纯音乐/无人声；场景=专注 |
| "失恋了想听的歌" | 情绪=伤感/治愈 |

**完整处理管道**：

```
用户输入自然语言
   ↓
[0] 前置校验：长度、敏感词、限流
   ↓
[1] 缓存查询：ml:ai:search:{sha256(normalized_query)}
     命中 → 直接返回（含 explanation）
   ↓
[2] 意图识别（LLM）
     输出 JSON: { "intent": "find_song", "confidence": 0.95 }
     意图类型：find_song / find_artist / find_playlist / similar_song / unknown
   ↓
[3] 关键词与条件抽取（LLM，结构化输出）
     输出 JSON:
     {
       "artist": ["周杰伦"],
       "song_name": [],
       "language": null,
       "genre": ["流行", "说唱"],
       "era": null,
       "emotion": ["活力", "欢快"],
       "scene": ["运动", "跑步"],
       "bpm_min": 120,
       "bpm_max": null,
       "energy_min": 0.6,
       "duration_max": null,
       "keywords": ["快歌"],
       "free_text": "适合跑步"
     }
   ↓
[4] 条件补全（规则引擎）
     - 场景=运动 → 补全 bpm_min=120, energy_min=0.6
     - 情绪=伤感 → 补全 valence_max=0.4
     - 场景=睡前 → 补全 bpm_max=90, energy_max=0.4
     - 年代=90s → 补全 release_date 范围
     - 歌手缺失但风格存在 → 不补全歌手
   ↓
[5] 检索（混合策略）
     a. 条件充分（有实体或结构化条件）→ ES 结构化查询（filter + multi_match）
     b. 条件不足（纯语义，如"像晴天那样的歌"）→ 向量召回（Milvus）
     c. 两者都执行 → 结果融合（RRF 或加权）
   ↓
[6] 排序
     粗排：热度 + 相关性
     精排：LLM 重排（对 Top 30 打分，返回重新排序的 Top 20）
     兜底：LLM 不可用时用规则排序
   ↓
[7] 结果解释生成（LLM）
     "为你筛选了周杰伦节奏较快的歌曲（BPM>120），适合跑步时听"
   ↓
[8] 返回：结果列表 + 解释 + 可调整条件标签
   ↓
[9] 写缓存（TTL 1h）+ 埋点
```

**接口**：

```

  "query": "适合跑步的周杰伦快歌",

  "pageSize": 20,

}
```

### FR-15-010 条件补全规则引擎 【P1】

| 项 | 内容 |

| 触发条件 | 补全内容 |
|---|---|
| `scene` 含 "运动"/"跑步"/"健身" | `bpm_min=120`, `energy_min=0.6` |

| `emotion` 含 "伤感"/"失恋" | `valence_max=0.4` |
| `emotion` 含 "治愈" | `valence_min=0.5`, `energy_max=0.6` |

| `keywords` 含 "新歌" | `release_date ≥ 最近 90 天` |
| `keywords` 含 "今年" | `year = 当前年` |
| `keywords` 含 "无人声"/"纯音乐"/"BGM" | `language=纯音乐` |

**补全优先级**：

```
显式条件（LLM 抽取出的）> 规则补全条件 > 默认条件（无）

```

**业务规则**：

- `BR-15-062`：补全规则**不覆盖** LLM 已明确抽取的条件。
- `BR-15-063`：补全规则存储于 `t_sys_config`（`config_key=ai.search.completion.rules`，JSON），支持运营热更新。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-15-010-1` | 补全后无结果 | 逐步放宽条件（见 BR-15-065），最多放宽 4 次 |
| `EX-15-010-2` | 规则配置非法 | 使用内置默认规则 + 告警 |
| `EX-15-010-3` | 歌曲缺标注字段 | 跳过该条件，不参与过滤 |

**验收标准**：

- `AC-15-010-1`："跑步"补全 `bpm_min=120`
- `AC-15-010-2`：显式 BPM 不被场景规则覆盖
- `AC-15-010-3`：补全后无结果时自动放宽并返回结果
- `AC-15-010-4`：规则热更新后立即生效

### FR-15-011 结果解释与可调条件 【P1】

| 项 | 内容 |
|---|---|
| **功能目标** | 让 AI 搜索可理解、可调整 |
| **使用角色** | 登录用户 |

**解释生成**：

```java
String explanation = llmService.generateExplanation(conditions, resultStats);
// Prompt:
// "用户搜索：{query}。系统筛选条件：{conditions}。共找到 {n} 首歌曲。
//  请用一句不超过 50 字的中文说明筛选理由，语气友好自然，不要罗列全部条件。"
```

**可调条件**：

- 每个生效的（非实体）条件显示为一个可点击标签。
- 点击标签的"×"→ 移除该条件 → 重新检索（**不重新调用 LLM**，仅重跑检索与排序）。
- 移除后条件集合存入 `sessionId` 对应的缓存，支持连续调整。

**业务规则**：

- `BR-15-067`：解释生成**必须**走缓存（与搜索结果同缓存），避免重复调用 LLM。
- `BR-15-068`：解释**不得超过 50 字**，超出则截断。
- `BR-15-069`：可调条件中，**实体条件**（歌手、歌名）标为 `removable: false`（移除会完全改变语义）。
- `BR-15-070`：移除条件后重搜**复用**已解析的意图与实体，仅调整结构化条件（省 LLM 成本）。
- `BR-15-071`：用户可在结果页**二次提问**（多轮调整，P2）。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-15-011-1` | 解释生成失败 | 使用模板化解释："根据你的描述为你筛选了以下歌曲" |
| `EX-15-011-2` | 移除条件后无结果 | 提示"移除后无结果，已为你保留原条件"并回滚 |
| `EX-15-011-3` | sessionId 过期 | 视为新查询，重新解析 |

**验收标准**：

- `AC-15-011-1`：AI 搜索结果附带 ≤ 50 字的解释
- `AC-15-011-2`：点击条件标签可移除并重新检索
- `AC-15-011-3`：移除条件不重新调用 LLM（成本可控）
- `AC-15-011-4`：实体条件不可移除

### FR-15-012 向量召回（语义相似）【P1】

| 项 | 内容 |
|---|---|
| **功能目标** | 支持"像《晴天》那样的歌"这类语义查询 |
| **使用角色** | 系统内部 |

**向量化方案**：

| 项 | 方案 |
|---|---|
| 模型 | `bge-large-zh-v1.5`（1024 维）【假设 A-13】 |
| 向量库 | Milvus 2.x（Collection: `song_vec`） |
| 向量内容 | `歌曲名 + 歌手 + 标签 + 情绪 + 场景 + AI 摘要` 拼接后编码 |
| 索引类型 | HNSW（M=16, efConstruction=200） |
| 距离度量 | 内积（IP，向量已归一化） |

**Collection 结构**：

```
Collection: song_vec
Fields:
  - id: BIGINT (主键, songId)
  - embedding: FLOAT_VECTOR(1024)
  - song_id: BIGINT (标量字段，用于回表过滤)
  - status: INT8
  - genre: VARCHAR
Index: HNSW on embedding (IP)
```

**查询流程**：

```
查询文本 "像晴天那样的歌"
  → 意图识别得 intent=similar_song, song_name=["晴天"]
  → 若指定了具体歌曲：直接取该歌曲的向量，ANN 检索 Top 100（排除自身）
  → 若未指定歌曲（纯语义）：将查询文本编码为向量，ANN 检索 Top 100
  → 过滤：status=1, copyright_status=1
  → 精排：LLM 重排 Top 30 → 返回 Top 20
  → 生成解释
```

**业务规则**：

- `BR-15-072`：向量召回结果**必须**与结构化过滤结合（Milvus 标量过滤），避免返回下架歌曲。
- `BR-15-073`：歌曲上架/下架时**同步**更新向量库（同 ES 同步管道）。
- `BR-15-074`：向量召回 Top N = 100（足够精排使用）。
- `BR-15-075`：相似度阈值：`score < 0.5` 的结果丢弃。
- `BR-15-076`：Milvus 不可用时降级为**标签相似度**（Jaccard 相似度，基于 `t_song_tag`）。
- `BR-15-077`：向量生成**异步批处理**（每日增量 + 全量重建），不阻塞主流程。
- `BR-15-078`：Embedding 调用**计入 AI 成本**，需缓存（相同文本不重复编码）。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-15-012-1` | Milvus 不可用 | 降级标签相似度 |
| `EX-15-012-2` | Embedding 服务不可用 | 降级关键词/标签搜索 |
| `EX-15-012-3` | 歌曲无向量（新增未同步） | 跳过向量召回，仅结构化检索 |
| `EX-15-012-4` | ANN 结果为空 | 返回空 + 提示放宽条件 |

**验收标准**：

- `AC-15-012-1`："像晴天那样的歌"返回风格相似的歌曲
- `AC-15-012-2`：向量召回结果不含下架歌曲
- `AC-15-012-3`：Milvus 不可用时降级标签相似度
- `AC-15-012-4`：歌曲上下架后向量库 30 秒内同步

### FR-15-013 AI 搜索降级与成本控制 【P0】

| 项 | 内容 |
|---|---|
| **功能目标** | AI 不可用或成本超限时保证服务可用 |
| **使用角色** | 系统内部 |

**降级链路（逐级）**：

```
1. LLM 可用           → 完整 AI 搜索（意图识别 + 抽参 + 补全 + 检索 + 精排 + 解释）
2. LLM 超时/失败       → 纯规则解析（正则 + 词典匹配）→ 结构化检索 + 模板解释
3. 规则解析也失败      → 关键词搜索（ES multi_match）
4. ES 不可用          → MySQL LIKE 搜索
5. 全部不可用          → 返回热门歌曲 + 提示"搜索服务暂时不可用"
```

**成本控制手段**：

| 手段 | 说明 | 预期节省 |
|---|---|---|
| **结果缓存** | 相同查询（归一化后）1 小时内复用 | 40%+ |
| **Prompt 精简** | 白名单/枚举精简，System Prompt 压缩到最短 | 20% token |
| **分级模型** | 意图识别用小模型（如 qwen-turbo），解释生成用小模型；仅精排用大模型 | 50%+ 成本 |
| **批量调用** | 精排时把 30 首合成 1 次调用（而非 30 次） | 大幅降本 |
| **禁用精排**（低流量时段可开关） | 直接按规则排序 | 60% |
| **每日预算熔断** | 当日 AI 成本超过预算 → 全局降级为规则解析 | — |
| **用户配额** | 登录 20 次/小时，游客 5 次/天 | — |
| **Embedding 缓存** | 相同文本不重复编码 | — |

**预算熔断实现**：

```java
@Component
public class AiBudgetGuard {

    private static final String KEY = "ml:ai:cost:{date}";   // 单位：分

    @Autowired private StringRedisTemplate redis;
    @Autowired private SysConfigService configService;

    /** 调用前检查 */
    public void checkBudget() {
        String date = LocalDate.now().format(DateTimeFormatter.BASIC_ISO_DATE);
        String used = redis.opsForValue().get(KEY.replace("{date}", date));
        long usedCent = used == null ? 0 : Long.parseLong(used);
        long budgetCent = configService.getLong("ai.daily.budget.cent", 10_000L);  // 默认 100 元
        if (usedCent >= budgetCent) {
            throw new BizException(ResultCode.AI_QUOTA_EXCEEDED);   // 触发全局降级
        }
    }

    /** 调用后累加成本 */
    public void recordCost(long costCent) {
        String date = LocalDate.now().format(DateTimeFormatter.BASIC_ISO_DATE);
        String key = KEY.replace("{date}", date);
        redis.opsForValue().increment(key, costCent);
        redis.expire(key, Duration.ofDays(2));
    }
}
```

**业务规则**：

- `BR-15-079`：降级**必须**对用户可见但友好（"已为你展示关键词搜索结果"），不暴露内部错误。
- `BR-15-080`：降级发生时**必须**上报监控指标（`ai_search_degraded_total{reason=...}`）。
- `BR-15-081`：每日 AI 成本超过预算的 80% 时**告警**，100% 时**熔断**。
- `BR-15-082`：成本统计精确到**分**，记录到 `t_ai_call_log`。
- `BR-15-083`：成本数据按场景、模型、用户维度可查（运营成本分析）。
- `BR-15-084`：预算与模型路由配置存 `t_sys_config`，支持热更新（无需重启）。

**异常情况**：

| 编号 | 场景 | 处理 |
|---|---|---|
| `EX-15-013-1` | 成本熔断触发 | 全局降级规则解析 + 提示用户 |
| `EX-15-013-2` | 单用户超配额 | `60002` + 提示配额重置时间 |
| `EX-15-013-3` | 缓存 Redis 不可用 | 仍调用 LLM（成本上升），告警 |
| `EX-15-013-4` | 成本统计写入失败 | 记日志，不影响主流程 |

**验收标准**：

- `AC-15-013-1`：模拟 LLM 超时，用户仍能拿到关键词搜索结果
- `AC-15-013-2`：缓存命中率 ≥ 40%（相同查询复用）
- `AC-15-013-3`：日成本超预算后 AI 调用被熔断
- `AC-15-013-4`：降级时用户可见友好提示
- `AC-15-013-5`：降级指标在监控面板可见
