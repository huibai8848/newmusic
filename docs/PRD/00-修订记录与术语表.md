## 2. 术语与缩写表

### 2.1 业务术语

| 术语 | 英文 / 缩写 | 定义 |
|---|---|---|
| **音乐房** | Music Room | 多人在线实时听歌房间，房主控制播放，成员可聊天/弹幕/排麦。核心社交场景。 |
| **房主** | Owner / Host | 房间创建者，拥有最高权限（控播、踢人、禁言、转让、解散）。 |
| **房管** | Room Admin | 由房主指派的房间管理员，可禁言/踢人/排麦管理，不可解散房间。 |
| **麦位** | Mic Seat | 房间内的语音/互动位。本平台一期麦位为"**排麦出歌**"语义（排队点歌上麦），非实时语音连麦。 |
| **排麦** | Mic Queue | 成员申请上麦形成的排队队列，按序上麦。 |
| **控播** | Playback Control | 房主/房管对房间内播放器的播放、暂停、切歌、进度同步操作。 |
| **进度校准** | Progress Sync | 客户端与服务端权威播放进度对齐，消除累积误差。 |
| **歌单** | Playlist | 用户或系统组织的歌曲集合。分用户歌单、编辑歌单、算法歌单。 |
| **动态** | Feed / Moment | 用户发布的短内容（文字/图片/歌曲/歌单），进入关注流。 |
| **关注流** | Following Feed | 用户关注对象的动态聚合流。 |
| **麦位投票** | Vote Skipping | 房间成员投票决定切歌/跳过，达阈值后执行。 |
| **冷启动** | Cold Start | 新用户/新歌曲/新歌单缺乏行为数据时的推荐策略。 |
| **多路召回** | Multi-Route Recall | 从多个策略通道并行召回候选集再融合。 |
| **北极星指标** | North Star Metric | 衡量产品核心价值的第一指标。本产品为 **日有效播放用户数（DAU-Play）**。 |

## 3. 全局命名规范

### 3.1 数据库

| 对象 | 规范 | 示例 |
|---|---|---|
| 表名 | `t_` 前缀 + 小写下划线 + 单数 | `t_song`、`t_room_member` |
| 字段 | 小写下划线 | `create_time`、`play_count` |
| 主键 | `id`，BIGINT，雪花算法 | `1857032849571328001` |
| 布尔 | `is_xxx` / `xxx_status`，TINYINT(1) | `is_deleted`、`audit_status` |
| 时间 | `xxx_time`，DATETIME(3) | `create_time`、`publish_time` |
| 金额 | `xxx_amount`，DECIMAL(12,2) 或 BIGINT（分） | `price_amount` |
| 比例 | `xxx_rate`，DECIMAL(6,4) | `completion_rate` |
| 索引 | `idx_{表简写}_{字段}` / `uk_{表简写}_{字段}` | `idx_song_artist`、`uk_user_phone` |
| 外键 | **不建物理外键**，由应用层保证 | — |

### 3.3 API 路径规范

```
/api/v1/{module}/{resource}[/{id}][/{action}]
```

| 操作 | 方法 | 路径示例 |
|---|---|---|
| 列表/分页 | GET | `/api/v1/music/songs?pageNum=1&pageSize=20` |
| 详情 | GET | `/api/v1/music/songs/{id}` |
| 创建 | POST | `/api/v1/music/playlists` |
| 全量更新 | PUT | `/api/v1/music/playlists/{id}` |
| 局部更新 | PATCH | `/api/v1/music/playlists/{id}` |
| 删除 | DELETE | `/api/v1/music/playlists/{id}` |
| 动作型 | POST | `/api/v1/room/{roomId}/kick` |
| 后台接口 | — | `/api/v1/admin/...`（统一 admin 前缀） |
| 内部接口 | — | `/api/v1/internal/...`（仅内网，需服务间 token） |

- 路径**全部小写、中划线分词**，禁止动词混入资源名（用 `/{action}` 表达动作）。
- 分页参数统一 `pageNum`（**从 1 开始**）、`pageSize`（默认 20，最大 100）。
- 排序统一 `sortBy` + `sortOrder`（`asc`/`desc`）。
- 时间统一 ISO-8601：`2026-10-12T14:30:00+08:00`，服务端时区 `Asia/Shanghai`。

### 3.4 Redis Key 规范

```
ml:{业务域}:{子域}:{标识}
```

示例：`ml:music:song:1857032849571328001`、`ml:room:online:{roomId}`、`ml:limit:api:{userId}:{api}`

- 统一前缀 `ml:`（musiclive），便于 `SCAN`/`KEYS` 隔离与多环境共用集群。
- 每个 Key **必须显式设置 TTL**（除明确的有状态结构），禁止永久 Key。
- 大 Key 阈值：String ≤ 10KB，Hash/Set/ZSet 元素数 ≤ 5000；超限须拆分或改用其他结构。

### 3.5 MQ Topic 规范

```
ml_{域}_{事件}_{版本}
```

示例：`ml_play_event_v1`、`ml_room_broadcast_v1`、`ml_audit_task_v1`

- 消费者组命名：`{应用名}-{用途}-group`。
- 消息体统一含 `eventId`（幂等键）、`eventTime`、`traceId`、`payload`。

### 3.6 前端命名

| 对象 | 规范 | 示例 |
|---|---|---|
| 组件文件 | PascalCase | `PlayerBar.tsx` |
| 页面文件 | PascalCase + `Page` | `HomePage.tsx` |
| Hook | `use` 前缀 | `usePlayer()`、`useWebSocket()` |
| Store | `use{X}Store` | `usePlayerStore` |
