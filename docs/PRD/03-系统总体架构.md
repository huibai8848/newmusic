## 1. 架构原则

| 编号 | 原则 | 落地方式 |
|---|---|---|
| AP-01 | **模块化单体优先** | 按业务域分包，模块间只通过 Service 接口 + 领域事件通信，禁止跨模块直连 Mapper |
| AP-02 | **为拆分预留** | 每个模块自治（自己的表、自己的 Service、自己的 MQ 主题），未来可按模块水平拆出 |
| AP-03 | **读写分离思路** | 高频读走 Redis/ES，低频写走 MySQL；统计走 ClickHouse |
| AP-04 | **异步解耦** | 通知、埋点、审核、推荐特征、转码全部走 MQ 异步 |
| AP-05 | **能力可插拔** | AI 供应商、推荐算法、存储、MQ 均通过 SPI/接口抽象 |
| AP-06 | **失败可降级** | 非核心依赖（推荐/AI/搜索）失败时降级到兜底策略，绝不阻断主链路 |
| AP-07 | **一切可观测** | 全链路 TraceId、结构化日志、指标埋点、健康检查 |

### 3.4 版本锁定风险提示

| 风险 | 说明 | 缓解 |
|---|---|---|
| Springfox 3.0.0 与 Boot 2.6 路径匹配冲突 | 启动报 `documentationPluginsBootstrapper` NPE | 配置 `spring.mvc.pathmatch.matching-strategy=ant_path_matcher` |

| Redis Cluster 与 Redisson | 需正确配置 `cluster` 模式 | 使用 `RedissonClusterConfig` |
| Boot 3 / JDK 17 迁移 | 长期天花板 | 预留：不在业务代码中使用已废弃 API，Mapper 不依赖具体版本特性 |

| 基础设施 | `infra` | Redis/MQ/ES/存储/限流封装 | 各 `*Template` | — |

**跨模块调用规则**：

- ✅ 允许：`A.service` 注入 `B.service`（接口）
- ❌ 禁止：`A.mapper` 注入 `B.mapper`（跨域直连数据库）
- ❌ 禁止：跨模块 JOIN 查询（须通过服务组合或冗余字段）
- ✅ 推荐：跨模块副作用走**领域事件**（MQ）解耦

## 9. 架构决策记录（ADR）

| 编号 | 决策 | 备选 | 结论 | 理由 |
|---|---|---|---|---|
| ADR-01 | 单体 vs 微服务 | 单体 / 微服务 | **模块化单体** | 团队规模与工期约束 |
| ADR-02 | WebSocket 实现 | 原生 WS / STOMP / Netty | **原生 WS + 自定义 JSON 协议** | 协议可控、心跳重连自研、无 STOMP 复杂度 |
| ADR-03 | 搜索客户端 | Spring Data ES / RestHighLevelClient | **RestHighLevelClient** | 版本解耦，避免 Boot 版本绑定 |
| ADR-04 | 向量库 | Milvus / RedisSearch / ES 向量 | **Milvus** | 大规模 ANN 性能好；RedisSearch 作轻量备选 |
| ADR-05 | 埋点存储 | MySQL / ClickHouse / Doris | **ClickHouse** | 写入吞吐与聚合性能 |
| ADR-06 | 消息队列 | RocketMQ / Kafka / RabbitMQ | **RocketMQ** | 支持事务消息、延迟消息、广播模式 |
| ADR-07 | 状态管理 | Redux / Zustand | **Zustand** | 轻量、无样板代码、适合播放器全局状态 |
| ADR-08 | 请求缓存 | 自研 / React Query | **TanStack Query** | 缓存/重试/失效开箱即用 |
