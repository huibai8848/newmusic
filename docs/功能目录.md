## 0. 本次修复与验证（先看这一节）

| # | 你反馈的现象 | 根因 | 现在的行为 | 怎么验 |
|---|---|---|---|---|
| 1 | 歌曲上传后没有歌词 | 音频文件只带音频，平台的 `t_lyric` 表没有任何自动来源；新增/导入接口原来也不接收歌词 | `SongSaveReq` 新增 `lyric`/`lyricContentType`；新增、编辑、JSON 批量导入都能随歌曲写歌词；后台歌曲抽屉多了「歌词」文本域；本地导入脚本会读同名 `.lrc` 与内嵌歌词（ID3 USLT / TXXX / FLAC LYRICS / WAV ILYR） | 见 §0.1 |
| 2 | 播放时进度条拖不动 | 搜索结果列表 VO（`SearchSongVO`）不返回音源字段，前端 `isPlayable` 只看音源字段 → 判定不可播放 → 进度条与播放按钮 `disabled` | 前端 `isPlayable` 改为「有音源 或 服务端 `playable=true`」；`AudioEngine` 还会先把接口返回的时长写进播放器 | 见 §0.2 |
| 3 | 上传后想上架，审核列表里没有这首歌 | 审核工作台的任务原来只由「内容安全机审 REVIEW」和「申诉」创建，歌曲新增/导入从来不建任务 | 歌曲进入待审（`audit_status=0`）时自动建 `SONG` 审核任务；启动时还会回填历史待审歌曲（每次最多 500 首） | 见 §0.3 |
| 4 | 热门搜索里点击「排行榜」不跳转 | 热搜词点击先改 URL，紧接着输入框同步逻辑又用旧关键词把 URL 覆盖回去（`push:/search?keyword=…` 后立刻 `push:/search`） | 只有「用户真的在输入」才会把输入框写回 URL；热搜词/历史词/联想词点击不再被回滚 | 见 §0.4 |

### 0.1 歌词：三条可测路径

**路径 A：本地音频 + 同名 `.lrc`（推荐）**

1. 准备一个目录，例如 `D:\Music\周杰伦\`，里面放 `周杰伦 - 晴天.mp3` 和 `晴天.lrc`（编码 UTF-8 或 GBK 都行）。
2. 先预览解析结果（不登录、不写库）：
   ```powershell
   node scripts/import-local-songs.mjs "D:\Music\周杰伦" --dry-run
   ```
   每个文件应显示 `… / 歌词 1234 字（lrc-file）`；没有歌词会显示 ` / 无歌词`。
3. 确认无误后正式导入（不带 `--publish` 时默认待审核，会进审核工作台）：
   ```powershell
   node scripts/import-local-songs.mjs "D:\Music\周杰伦" --create-artist
   ```
4. C 端（5173）打开导入的歌曲详情/全屏播放页，歌词应随播放滚动。
5. 后台（5174）→ 歌曲管理 → 编辑该歌曲，抽屉里的「歌词（LRC 或纯文本）」应有内容，可直接改并保存。

**路径 B：给已经导入过、只是缺歌词的歌曲补词**

```powershell
node scripts/import-local-songs.mjs "D:\Music\周杰伦" --lyrics-only --dry-run
node scripts/import-local-songs.mjs "D:\Music\周杰伦" --lyrics-only
```
- `--lyrics-only` 不上传音频、不新建歌曲，只按「歌名 + 歌手」找到库中已有歌曲，调用
  `PUT /api/v1/admin/songs/{id}/lyric` 覆盖歌词正文。
- 找不到同名同歌手的歌曲会明确报「库中没有同名同歌手的歌曲」，不会误建新歌。

**路径 C：后台手工编辑**

- 后台 → 歌曲管理 → 新增/编辑 → 「歌词（LRC 或纯文本）」文本域。
- 留空表示不改动；填写后覆盖该歌曲现有歌词（翻译、罗马音不受影响）。
- 接口：`GET /api/v1/admin/songs/{id}/lyric`、`PUT /api/v1/admin/songs/{id}/lyric`。

> 说明：`--publish` 会把 `auditStatus` 直接写成 1 并上架，**按设计不会产生审核任务**。
> 想测审核工作台，请不要加 `--publish`。

### 0.2 进度条：验证步骤

1. 打开 `http://localhost:5173/search`，搜索「花海」。
2. 点结果行里的「播放」。
3. 底部播放条进度条应可拖动，右侧总时长显示 `04:24`；拖动后歌词与时间同步。
4. 全屏播放页（点播放条封面）里的进度条同样可拖动；`Esc` 收起。

修复前：搜索结果页播放后进度条 `aria-disabled=true`、总时长为 `--:--`。

### 0.3 审核工作台：验证步骤

1. 后台（5174）→ 歌曲管理 → 新增一首歌（上传标准音源会自动读取标签填歌名/歌手/专辑等，也可手填），保存。
   - 新歌默认 `待审核 / 下架`，保存后提示「默认进入待审核状态」。
2. 左侧菜单 → 审核工作台 → 任务类型筛选 `SONG`（或目标类型 `SONG`）。
   - 应看到标题为「歌名 - 歌手」的任务，状态「待领取」，优先级「普通」。
3. 点「领取」→ 任务变「处理中」（10 分钟领取锁）。
4. 打开详情 → 选「通过」→ 提交。
   - 歌曲管理里该歌的审核状态变为「已通过」。
   - 任务详情的时间线有两步：领取、审核通过。
5. 回到歌曲管理 → 点「上架」。
   - 上架前置条件：审核通过 + 版权已授权 + 有标准音源 URL；缺一项会提示「歌曲不满足上架条件」。
6. 拒绝路径：审核时选「拒绝」必须填 ≥5 个字的理由；拒绝后歌曲保持/变为下架。
7. 历史数据：后端每次启动会给 `audit_status=0` 的歌曲补建任务（幂等，同一首歌只保留一条未完成任务）。

> 审核任务只对「待审核」歌曲建。已经是「已通过」的歌曲（例如 `--publish` 导入的）不会出现在待审列表里，这是正常的。

### 0.4 热搜跳转：验证步骤

1. `http://localhost:5173/search`（不带关键词）→ 页面显示「热搜榜」。
2. 点任意热搜词（如「花海」）→ 地址栏变为 `/search?keyword=%E8%8A%B1%E6%B5%B7`，结果区刷新。
3. 浏览器后退 → 回到搜索首页（热搜榜 + 历史）。
4. 再点历史词、联想词，行为一致。

> **关于「排行榜」**：项目目前没有独立的 `/rank` 排行榜页面（PRD 模块 02 把它列为 P1，尚未实现）。
> 「热搜榜」就是当前的排行榜入口；如果你期望的是一个单独的「排行榜」页面（新歌榜/热歌榜等），
> 那是尚未开发的功能，不是本 bug。本次修复的是「热搜榜里的词点了不跳转」。

### 0.5 遗留修复的手工验证点

| 场景 | 操作 | 期望 |
|---|---|---|
| 歌词删了再传 | 后台歌词抽屉清空/删除该歌歌词（或调用 `DELETE /api/v1/music/lyrics/{lyricId}`），再重新保存歌词 | 保存成功，正文可读；数据库里仍是同一行 `t_lyric.id`（复活墓碑行，不会报 10010/99001） |
| 并发写同一首歌词 | 两个终端同时对同一首歌 `PUT /api/v1/admin/songs/{id}/lyric` | 两个请求都返回 `code=0`；`t_lyric` 只有一行，正文是其中一次写入 |
| 审核任务不重复 | 对同一首待审歌曲连续点两次「保存」或并发提交 | 审核工作台只有一条未完成 `SONG` 任务（数据库唯一索引兜底） |
| 丢失/孤儿任务自动修 | 手工把一条 SONG 任务置为待领，再把歌曲审核通过或删除；最多等 5 分钟 | 该任务自动变为「4 自动关闭」，审核台不再出现点进去查无此歌的条目 |
| 带空格的音源 URL | 后台把音源改成前后带空格的地址（如 `" /media/demo/demo-01.wav "`） | 播放器能正常加载；不再出现「按钮可点但加载失败」 |
| 编辑已上架歌曲 | 后台 → 歌曲管理 → 编辑任一「上架」歌曲 → 只改副标题 → 保存 | 保存成功（不再报 30043），提示「歌曲已更新」；重新打开抽屉改动仍在 |
| 补歌词后 C 端可见 | 后台给一首原本「暂无歌词」的歌补 LRC → C 端刷新歌曲详情 | 刷新后显示新歌词（`localStorage` 的负结果缓存已不再长期保留）；同一标签页不刷新时最多等内存缓存 10 分钟 |
| 音频失败与恢复 | 播放器播放一首歌时，用 DevTools 把音频请求改为失败，再恢复后点「重新播放」 | 有可读失败提示、loading 消失；恢复后从详情页点「重新播放」能继续出声，不会无限重试同一首 |

> 既有库升级必须先执行一次 `sql/20-audit-task-open-unique.sql`，否则审核任务的数据库级去重不生效。
> 详细修复说明与自动化结果见 `docs/测试报告-歌词审核修复.md` §5。

### 2.2 全局播放器（每个页面都在）

## 6. 关键业务规则（测试时容易踩）

1. **上架三条件**：审核通过（`audit_status=1`）+ 版权已授权（`copyright_status=1` 且未过期）+ 有标准音源 URL。
2. **新增默认值**：`status=0`（下架）、`audit_status=0`（待审）、`copyright_status=0`、语种默认「国语」。
3. **审核任务**：只有待审内容才建任务；同一歌曲同一时间只保留一条未完成任务（待领/已领取）；
   领取锁 10 分钟，超时自动放回；超过 24 小时未处理会标记升级。
4. **歌词**：`t_song.lyric_id` 指向 `t_lyric`；没有歌词指针或没有歌词记录，播放器显示「暂无歌词」。
   歌词正文更新会同步 ES 文档（搜歌词能命中新内容）。
5. **搜索结果播放**：列表 VO 不保证带音源字段；前端以服务端 `playable` 为准，不再错误禁用控件。
6. **搜索 URL 是唯一事实来源**：关键词/Tab/筛选/排序都在 query string 上，刷新/分享/后退不丢状态。
7. **分页**：搜索用游标（`cursor`），第 1000 条以后拒页码深分页；管理后台列表用 `pageNum/pageSize`。
8. **ID**：19 位雪花 ID 在 JS 里必须按字符串处理，转 `Number` 会丢精度（脚本/接口测试尤其注意）。
9. **缓存**：歌曲详情等有两级缓存；后台改歌/上下架/审核后会主动失效，不需要重启。
10. **降级**：ES 不可用时搜索自动降级 MySQL（状态接口会标 `degraded=true`），不影响基本检索。

## 7. 已知未实现 / 已知限制

- **独立排行榜页面 `/rank` 未实现**（PRD P1）；目前「热搜榜」承担排行榜入口。
- 后台音质字段可直接上传音频（≤50MB），但**不做转码**：上传 flac/wav 就按原格式保存；
  多音质需要分别上传对应的源文件，或使用导入脚本。
- 本机未安装 IK 分词插件，ES 走 lite 映射（`standard` + `cjk_bigram`）；full 映射与远程词典未实跑。
- 本机没有 Prometheus/Grafana/SkyWalking/RocketMQ/Redis Cluster/K8s，模块 19 的运维面是应用内实现。
- 浏览器人工走查项（词典页、播放体验、音乐房双端、内容安全面板等）见 `docs/待办.md` P0 清单。

## 8. 快速冒烟（10 分钟）

1. 启动后端 + C 端 + 后台，三端都能打开。
2. C 端登录 `admin/admin123` → 搜索「花海」→ 播放 → 拖进度条 → 打开全屏歌词。
3. 搜索页清空关键词 → 点热搜词 → URL 带 `keyword`；后退回榜单。
4. 后台登录 → 歌曲管理新增一首（不填歌词）→ 审核工作台出现 SONG 任务 → 领取 → 通过 → 上架。
5. 后台编辑该歌 → 粘贴一段 LRC 到「歌词」→ 保存 → C 端详情页能看到歌词并滚动。
6. 用 `.lrc` + `--dry-run` 跑一次导入脚本，确认「歌词 N 字（lrc-file）」；正式导入后重复第 5 步验证。
7. 后台 → 审核工作台 → 任务类型 `SONG`，确认历史待审歌曲也都出现了。
8. 跑 `node scripts/smoke.mjs`、`npm --prefix web run test`，确认基础回归无红。
