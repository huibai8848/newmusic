## 2. 系分决策（ADR）

| 编号 | 决策 | 理由 | 影响面 |
|---|---|---|---|
| **D-01** | 后台是**完全独立的认证域**：`@Order(1)` 过滤链只匹配 `/api/v1/admin/**`；独立 RSA 密钥对、issuer `ml-admin`、Cookie 名 `ml_admin_access` / `ml_admin_refresh` | C 端 Token 和后台 Token 必须互不通用。仅靠角色判断无法防止 C 端 Token 被塞进后台请求；独立签名密钥 + issuer 让两侧在解析阶段就失败（FR-18-001） | `AdminSecurityConfig` / `AdminJwtTokenProvider` / `AdminJwtProperties` |
| **D-02** | 后台错误码段固定为 **80001 / 80011–80030**，不复用 C 端 4xxxx / 9xxxx | 前端需要区分「账号密码错误」「验证码错误」「TOTP 错误」「最后一个超管」等分支；复用错误码会让登录页只能显示一句模糊提示 | `ResultCode`、`web-admin` 的 `errorMessage` |
| **D-03** | Token 只放 **httpOnly + SameSite=Strict Cookie**，响应体不返回 Token，前端不写 localStorage | 防 XSS 直接窃取；页面刷新靠 `/auth/me` 重新确认身份。access 路径 `/api/v1/admin`，refresh 路径 `/api/v1/admin/auth`，业务接口拿不到 refresh | `AdminCookieSupport`、`AuthContext` |
| **D-04** | CSRF 采用 **Origin / Referer 白名单**，不做 CSRF Token | 后台是纯前后端分离 SPA，写请求均带 Origin；非浏览器客户端没有 Origin，也无法利用受害者 Cookie。白名单默认 `http://localhost:5174,http://127.0.0.1:5174`，可用 `admin-jwt.allowed-origins` 覆盖 | `AdminCsrfFilter` |
| **D-05** | 会话失效用 **每管理员会话版本号 `sv`**：密码重置、角色变更、禁用、重置 TOTP 都 `bumpVersion`；Redis 不可用时后台 **fail-closed** | 只有 refresh 轮换无法让 access Token 立即失效；版本号进入 JWT claim，每次请求比对，实现「下一个请求立刻踢下线」 | `AdminSessionStore`、`AdminJwtAuthenticationFilter` |
| **D-06** | refresh **一次性轮换**：旧 refresh 再次出现视为重放，直接递增版本踢掉所有设备 | 8 小时 refresh 是长期凭证，必须可检测重放；宁可让用户重新登录，也不接受可能已泄露的凭证 | `AdminAuthService#refresh` |
| **D-07** | 验证码 **Redis 存储 2 分钟、一次性消费**，演示环境回显 `code` | 本机验收需要自动化登录；回显由 `ADMIN_CAPTCHA_ECHO` 控制，生产关闭。验证码不在内存缓存，多实例也一致 | `AdminCaptchaService` |
| **D-08** | 登录失败计数 **按用户名** 记 Redis，5 次锁 30 分钟；同时写登录日志，失败 ≥3 次标 `suspicious=1` | 锁定语义必须跨实例；按用户名而不是 IP，避免攻击者换 IP 绕过。可疑标记供日志页筛选 | `AdminSessionStore`、`LoginLogService` |
| **D-09** | TOTP 用 **Java 自实现 RFC 6238**（HMAC-SHA1、30 秒窗口、±1 窗口容错），不引第三方库 | 只依赖 JDK 加密 API，避免为一个小功能引入维护面；密钥以 Base32 返回给管理员手动绑定 | `TotpSupport` |
| **D-10** | TOTP 只能通过 **「重置 TOTP」** 生成并回传密钥；创建 / 编辑接口不会直接开启 TOTP | 若创建时 `totp_enabled=1` 但没有密钥，账号会进入「要求动态码但永远验证失败」的死锁。`update` 对启用但无密钥的请求返回参数错误 | `AdminAccountService` |
| **D-11** | 审核领取用 **条件 UPDATE**（`status=0`）+ 10 分钟 `claim_expire_at`；处理也用条件 UPDATE（原状态 + 领取人 + 未过期） | 并发下只有一个管理员能领取/处理成功；过期任务由定时任务放回池子，离线审核员不会永久占坑 | `AuditTaskMapper`、`AuditService` |
| **D-12** | 审核业务联动 **只对 SONG 真实生效**；其它任务类型只写审核记录并置 `action_applied=0` | 评论 / 歌单 / 房间公告等模块尚未交付，不能假装改动了不存在的表。前端在详情里直接说明联动范围 | `AuditService#applyBusinessAction` |
| **D-13** | 举报处理一次事务完成「状态 + 联动处置 + 合并 + 通知」；通知失败只 WARN | 不能出现「举报已标记处理但内容还在」；通知是副作用，不能反向回滚处置结果 | `ReportService` |
| **D-14** | 系统配置 **按 `value_type` 校验**（1 字符串 / 2 整数 / 3 布尔 / 4 JSON），键名命中 password/secret/token/private key/credential 直接拒绝（80026） | 配置会写历史、可导出，不是密钥仓库。类型不校验会把 `abc` 写进布尔开关，直到运行时才炸 | `SysConfigService` |
| **D-15** | 配置修改写历史 + 支持回滚；**只有 `search.sensitive.words` 声明热重载** | 大多数配置在启动时读取，谎称热更新会让运营以为已生效。敏感词有真实消费者 `SensitiveWordSupport`，修改后立即 `invalidate()` | `SysConfigService#invalidateIfNeeded` |
| **D-16** | 仪表盘只用 **真实表聚合**，没有数据的指标返回 0，趋势补齐缺失日期 | 不造演示数字；缺失日期补 0，避免前端柱状图日期跳动 | `DashboardMapper`、`AdminDashboardService` |
| **D-17** | 操作日志由 **AOP** 写入，标注 `sensitive=true` 的接口额外记录敏感标记；参数/响应中的 password、token、captcha、authorization 字段脱敏 | 日志必须可追溯（BR-18-067），但不能把密码和密钥写进日志 | `OperationLogAspect` |
| **D-18** | 强制改密：管理员重置 C 端密码 / 后台账号初始密码、密码超过 90 天，均置 `force_change_password=1`；改密成功后 `revokeAllSessions` | 临时密码必须一次性；改密后旧会话必须立即失效，否则临时密码形同虚设 | `AdminUserManageService`、`AuthServiceImpl`、`UserServiceImpl#changePassword` |
| **D-19** | 定时任务用 **三个独立 `@Scheduled`**，各自 try/catch，间隔可配 | 一个任务抛异常不能拖垮另外两个；本机不引入 XXL-Job，保持与模块 06/08 一致 | `AdminScheduledJobs` |
| **D-20** | 前端构建使用 SWC（`@vitejs/plugin-react-swc`），`build` 先跑 `tsc --noEmit` | 构建阶段就拦住类型错误；SWC 比 Babel 快，适合小后台迭代 | `web-admin/vite.config.ts` |

### 3.1 认证流程

```
GET  /api/v1/admin/auth/captcha         → captchaId + PNG(base64)，Redis 2min
POST /api/v1/admin/auth/login           → 校验验证码 → 锁定检查 → 密码 → 状态 → IP 白名单 → TOTP
                                          → 写登录日志 → 签发 access(1h) + refresh(8h)
                                          → Set-Cookie（httpOnly + SameSite=Strict）
GET  /api/v1/admin/auth/me              → 返回管理员 + 角色 + 展开后的权限码
POST /api/v1/admin/auth/refresh         → 消费旧 refresh（重放检测）→ 轮换新对
POST /api/v1/admin/auth/logout          → 清 Cookie + refresh 黑名单
POST /api/v1/admin/auth/password        → 校验旧密码 → 更新 → bumpVersion（其它会话全部失效）
```

- access Token claim 含 `adminId`、`sv`、`jti`、`iss=ml-admin`；过滤器每次请求比对 `sv`
- 禁用账号 / 重置密码 / 角色变更 → `bumpVersion` → 下一请求 401
- 后台没有 HttpSession，`SessionCreationPolicy.STATELESS`

### 3.2 审核领取状态机

```
待领取(0) ──claim(条件UPDATE)──▶ 处理中(1) ──handle──▶ 已通过(2) / 已拒绝(3)
    ▲                                  │
    └──── release / 10min 超时释放 ─────┘
超过 24h 未处理 → escalated=1（只标一次，不改变状态）
```

- 拒绝必须填写 ≥5 字原因（80028），并给提交人发站内信
- 通过 / 拒绝快捷键：详情抽屉打开时按 `A` / `R`（输入框内不触发）

### 3.3 举报处理

```
成立(VALID)       → 可联动 OFFLINE_SONG / BAN_USER / CLOSE_ROOM，可合并同目标待处理举报
不成立(INVALID)   → 只记录结论，不联动
待补充(NEED_MORE)→ 可再次处理
```

- 联动动作与目标类型不匹配时后端拒绝（如对 COMMENT 执行 OFFLINE_SONG）
- 处理说明 2–500 字，必填；结果通知举报人

### 3.4 系统配置热重载边界

| 配置键 | 修改后 | 说明 |
|---|---|---|
| `search.sensitive.words` | **立即生效** | 调用 `SensitiveWordSupport.invalidate()`，下一次搜索重新读取 |
| 其它配置 | 重启生效 | 服务端在启动时读取，后台页面明确提示 |

配置值类型：

| valueType | 校验 |
|---|---|
| 1 字符串 | ≤ 10,000 字符 |
| 2 整数 | `BigDecimal` 可解析 |
| 3 布尔 | `true` / `false` |
| 4 JSON | `ObjectMapper.readTree` 可解析 |

## 4. 数据模型

### 4.1 新增表（`sql/09-admin-seed.sql`，全部 `newmusic.` 限定）

| 表 | 说明 |
|---|---|
| `t_admin_user` | 管理员账号：密码 BCrypt、TOTP 密钥、失败次数、锁定截止、`force_change_password` |
| `t_admin_role` | 角色：SUPER_ADMIN / ADMIN / OPERATOR |
| `t_admin_permission` | 权限码 9001–9094（`admin:*`），超管额外 `*:*:*`(9100) |
| `t_admin_role_permission` | 角色-权限 |
| `t_admin_user_role` | 管理员-角色 |
| `t_admin_operation_log` | 操作日志（含 traceId / before / after / 敏感标记） |
| `t_admin_login_log` | C 端 + 后台登录日志（result 0/1/2，suspicious） |
| `t_audit_task` | 审核任务（taskType/targetType/targetId、优先级、领取锁、escalated） |
| `t_audit_record` | 审核留痕（CLAIM / RELEASE / APPROVE / REJECT） |
| `t_report` | 举报（reasonType、evidenceUrls、priority、mergedIntoId） |
| `t_sys_config` | 系统配置（valueType、configGroup、isPublic、status） |
| `t_sys_config_history` | 配置变更历史（old/new、changeType、changedBy、remark） |

### 4.2 既有表最小改动

- `t_user.force_change_password`（TINYINT，默认 0）：`sql/09-admin-seed.sql` 用 information_schema 判断后动态 `ALTER`，**不重建表、不影响其它项目库**
- 房间创建限制 **不新增表**：使用 Redis `ml:admin:room:createban:{userId}`，`hours<=0` 表示永久；定时任务扫描到期键

### 4.3 Redis 键（全部 `ml:` 前缀）

| 键 | TTL | 用途 |
|---|---|---|
| `ml:admin:captcha:{id}` | 2 min | 图形验证码 |
| `ml:admin:login:fail:{username}` | 30 min | 登录失败计数（5 次锁定） |
| `ml:admin:refresh:{jti}` | 8 h | refresh 一次性账本 |
| `ml:admin:refresh:user:{adminId}` | 8 h | 该管理员所有 refresh（批量撤销） |
| `ml:admin:blacklist:{jti}` | 剩余时长 | 已注销的 access |
| `ml:admin:session:ver:{adminId}` | 无 | 会话版本号 |
| `ml:admin:room:createban:{userId}` | 按 hours | 创建房间限制 |

> 本机 Redis 为共享实例：禁止 `FLUSHDB/FLUSHALL`，脚本只操作上述前缀并在结束时清理自己创建的键。

| `admin:adminuser:manage` | 管理员账号（仅超管） |
| `admin:danger:reindex` / `admin:danger:clearcache` | 预留危险操作 |

角色默认映射：

| 角色 | 权限 |
|---|---|
| SUPER_ADMIN | 全部（`*:*:*` 展开）+ 危险操作 |
| ADMIN | 用户 / 内容 / 房间 / 审核 / 举报 / 运营配置 / 日志（不含账号管理、配置、导出） |
| OPERATOR | 仪表盘、运营配置、仅本人日志 |

## 7. 与 PRD 的偏差

| 偏差 | 原因 | 影响 |
|---|---|---|
| 后台接口路径使用 `/api/v1/admin/**`，与 PRD 示例 `/api/v1/admin/audit/tasks` 略有差异 | 统一 REST 资源名，实际以前端与验收脚本为准 | 契约以内置接口文档为准 |
| 未实现音频转码（标准/高/无损） | 本机无 ffmpeg / 转码服务；上传只校验格式与大小 | `AC-18-007-3` 不满足；前端不提供“转码”按钮 |
| JSON 导入替代 Excel | 避免引入 POI；错误行报告结构一致 | Excel 模板后置 |
| 审核业务联动仅 SONG | 评论 / 歌单 / 房间公告模块尚未交付 | 其它任务类型只记录结论并明确提示 |
| 歌手合并、曲目拖拽排序未实现 | P2 / 依赖前端拖拽组件 | 后置 |
| 推荐配置、官方歌单、分类标签未实现 | P1 | 后置 |
| 仪表盘只做当前实时聚合，无历史趋势表 | 无埋点数仓 | 趋势基于业务表的 `create_time` 直接分组 |
| 上传文件不做内容安全检查 / 病毒扫描 | 依赖模块 18 | 文件类型与大小白名单已做 |

## 8. 自动化验收

脚本：`scripts/verify-09.mjs`（Node ≥ 18，零依赖）

覆盖：

1. **认证隔离**：无 Cookie 访问后台接口 401；C 端 Token 不能访问后台；错误验证码 / 密码 / 锁定 / TOTP 分支
2. **RBAC**：operator 访问账号管理 / 配置修改被 403；超管可访问
3. **用户 / 歌曲 / 歌手 / 专辑**：分页、创建、编辑（乐观锁）、状态变更、删除保护
4. **审核**：领取冲突、拒绝原因校验、审核记录、版本回滚
5. **举报**：处理、联动、重复处理 80025、合并
6. **房间**：强制关闭、创建限制、解除限制
7. **配置**：类型校验、密钥拒绝 80026、历史、回滚、敏感词热重载
8. **日志**：操作日志落库、登录日志落库、仅本人过滤
9. **数据清理**：删除脚本创建的 C 端用户 / 歌曲 / 歌手 / 专辑 / 配置 / 审计任务 / 举报；清理 Redis `ml:admin:*` 测试键
10. **共享实例体检**：断言 `emp_db` / `music_db` 与本项目业务表未被误删；断言 Redis 中其它项目 `ranking:*` 键仍在

运行：

```bash
MYSQL_PASSWORD=*** node scripts/verify-09.mjs
# 可选：BASE_URL / MYSQL_HOST / MYSQL_PORT / MYSQL_USER / REDIS_HOST
```

注意事项：

- 登录失败计数与验证码会持久化：脚本为每次运行生成随机 `X-Forwarded-For`，并使用独立的测试账号 / SQL 清理
- 所有断言前先构造**非空控制集**，避免「空集合上恒真」
- 脚本不会执行 `FLUSHDB/FLUSHALL`，不会操作 `newmusic` 以外的数据库
- `boot.log` 为 GBK，日志核对只使用 ASCII 锚点（`verify-09` / `ERROR`）
