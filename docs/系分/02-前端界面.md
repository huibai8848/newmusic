## 2. 系分决策（ADR）

| 编号 | 决策 | 理由 | 影响面 |
|---|---|---|---|
| **D-01** | 前端独立工程 `web/`，与后端同仓不同根；不做 monorepo 工具链（pnpm workspace 等） | MVP 只有一个前端，引入 workspace 只增加构建复杂度 | `web/` |
| **D-02** | 状态分层：**服务端状态**用 TanStack Query（缓存/重试/失效），**客户端会话状态**用 Zustand（用户、主题、播放器） | 播放器状态需高频更新且跨路由常驻，放 Query 会被 GC；接口数据放 Zustand 则要手写缓存失效 | `src/stores`、`src/api` |
| **D-03** | **Ant Design 5 全量引入**（MVP 阶段不做按需/`babel-plugin-import`），通过路由级 `React.lazy` 保证首屏 chunk 可控 | 按需引入在 Vite + AntD5（CSS-in-JS）下收益有限，先保正确性；首屏体积指标 `AC-11-206` 在模块 02 只做记录 | `vite.config.ts` |
| **D-04** | 请求层统一拆包：拦截器直接把 `R<T>` 的 `data` 返回给调用方，业务错误（`code !== 0`）统一 reject 为 `ApiError{code,message,traceId}`；HTTP 401 触发一次静默刷新并重放，失败才跳登录 | 页面代码不重复写 `res.data.data`；`traceId` 必须能被错误提示与日志收集到 | `src/api/request.ts` |
| **D-05** | **Token 存储**：`accessToken` 与 `refreshToken` 均存 `localStorage`（`ml.accessToken` / `ml.refreshToken`），不使用 Cookie | 纯前端 SPA + 无状态 JWT，避免 CSRF（PRD `BR-11-014`） | `src/utils/storage.ts` |
| **D-06** | 权限判断用**权限码集合**（`perms`），支持 `*:*:*` 与资源级通配：`hasPerm(code)` 内部对 `music:artist:create` 依次尝试 `music:artist:*`、`music:*`、`*:*:*` | 后端登录态下发的就是展开后的具体码 + 原始通配码（模块 01 D-14），前端保持同一套语义 | `src/stores/userStore.ts` |
| **D-07** | 播放器 `<audio>` 挂在**应用根节点**（`src/main.tsx`，在任何路由树之外），底部 `PlayerBar` 由 `MainLayout` / `AdminLayout` 各自渲染；`playerStore` 只持有状态与命令，DOM 操作集中在 `AudioEngine` 组件 | 满足 `AC-11-201`「切路由不中断播放」。挂在根节点比挂在 `MainLayout` 更强：进后台、跳登录页（`BlankLayout`）也不销毁音频元素 | `src/main.tsx`、`src/layouts/*`、`src/components/player` |
| **D-08** | MVP 播放地址直接取 `song.audioStandard`（模块 01 响应已带）；预留 `resolveUrl(song, quality)` 适配层，模块 07 换成 `GET /player/url` 时只改一处 | 模块 07 的签发接口尚未存在，但页面与状态机不该为此返工 | `src/api/player.ts` |
| **D-09** | 样式：CSS Modules + Less + CSS 变量；**禁止硬编码色值**（含 AntD 组件内联色），全部走 `var(--color-*)` | PRD §6.2 硬性规则，否则暗黑模式必然漏改 | `src/styles/*.less` |
| **D-10** | 「区块独立失败」用 `<SectionBoundary>`（局部 `ErrorBoundary`）+ Query 的 `retry: false` 兜底：单区块异常只渲染该区块的失败态 | `AC-11-204`、`BR-11-002` | `src/components/common/SectionBoundary.tsx` |
| **D-11** | 列表默认每页 20，`hasNext` 决定触底加载；`truncated=true` 时前端提示「已限制 100 条/页」 | 与后端 `PageResult.truncated`（模块 01 AC-10-001-1）对齐，避免用户以为数据丢失 | `src/hooks/useInfiniteList.ts` |
| **D-12** | 后端 ID 一律按 **string** 处理（`Long` > 2^53 被序列化为字符串），TS 类型统一 `type Id = string` | 模块 01 AC-10-104；前端若按 number 处理会静默丢精度 | `src/types/api.ts` |

## 4. 接口契约（前端消费面）

统一响应（模块 01 §5.1）：`{ code, message, data, traceId, timestamp }`；`code === 0` 为成功。
**HTTP 200 = 业务成功或业务失败**，仅 401 / 403 具有独立 HTTP 语义；前端不得用 HTTP 状态码判断业务结果。

| 场景 | 方法 | 路径 | 说明 |
|---|---|---|---|
| 登录 | POST | `/api/v1/auth/login` | body `{account, password}` → `{accessToken, refreshToken, expiresIn, user}` |
| 注册 | POST | `/api/v1/auth/register` | body `{username, password, nickname}` → `UserVO`；前端注册成功后**自动**用同一份凭证调登录，省一次手工输入 |
| 刷新 | POST | `/api/v1/auth/refresh` | body `{refreshToken}` → 新的双 Token（轮换） |
| 登出 | POST | `/api/v1/auth/logout` | 无状态，前端丢弃 Token |
| 当前用户 | GET | `/api/v1/users/me` | → `UserVO`（含 `roles` / `perms`） |
| 改本人资料 | PUT | `/api/v1/users/me` | body `{nickname, avatar, gender, birthday, signature}`；`version` 由服务端自取，前端**不需**回传 |
| 歌曲列表 | GET | `/api/v1/music/songs` | `pageNum/pageSize/keyword/sortBy/sortOrder/artistId/albumId/genre/language/status/auditStatus/tagId` |
| 歌曲详情 | GET | `/api/v1/music/songs/{id}` | 无权限者取不到未上架歌曲（`30001`） |
| 歌词 | GET | `/api/v1/music/lyrics/{songId}` | 无歌词时 `data: null`（模块 07 消费） |
| 歌手/专辑 | GET | `/api/v1/music/artists[/{id}]`、`/api/v1/music/albums[/{id}]` | 列表 + 详情 + 按 `artistId` 过滤歌曲 |
| 歌单 | GET | `/api/v1/music/playlists[/{id}]` | 详情返回 `{playlist, songs}`；私密歌单越权 → `30004` |
| 歌单增删改 | POST/PUT/DELETE | `/api/v1/music/playlists/{id}/songs`、`/songs/order` | 移歌/重排 body `{songIds:[...]}`；越权 → `30005`（HTTP 403） |
| 标签 | GET | `/api/v1/music/tags`、`/hot`、`/song/{songId}` | 歌曲详情页标签展示 |
| 分类 | GET | `/api/v1/music/categories/enabled` | 已封装 `categoryApi.enabled()`，**本期无页面消费**（分类筛选属模块 06 的筛选面板） |

**前端约定**：

- `Id`（`Song.id` 等）一律为 `string`（D-12）
- 列表分页字段：`{list, total, pageNum, pageSize, pages, hasNext, truncated}`
- 写接口（PUT）必须回传详情拿到的 `version`；缺失会拿到 `10001`（模块 01 D-11）
- 本地存储键：`ml.accessToken`、`ml.refreshToken`、`ml.user`、`ml.theme`、`ml.player`（模块 07 写入）

## 5. 路由与状态设计

### 5.1 路由表（MVP 子集）

| 路由 | 布局 | 守卫 | 页面 |
|---|---|---|---|
| `/` | MainLayout | — | 首页（推荐歌单 + 新歌速递 + 热门歌手 + 猜你喜欢） |
| `/login`、`/register` | BlankLayout | 已登录则 `Navigate` 到 `redirect ?? /` | 登录 / 注册 |
| `/search?keyword=&type=song\|artist\|album\|playlist` | MainLayout | — | 搜索（关键词与 Tab 都放 URL，可分享/回退） |
| `/song/:id` | MainLayout | — | 歌曲详情（信息 + 标签 + 版权/音质 + 歌词原文预览 + 同歌手作品） |
| `/artist/:id`、`/album/:id` | MainLayout | — | 歌手（歌曲/专辑 Tab） / 专辑详情 |
| `/playlist/:id` | MainLayout | — | 歌单详情（播放全部 + 创建者可编辑/移歌/单页内上下移排序） |
| `/user?tab=profile\|history\|playlists` | MainLayout | RequireAuth | 个人中心（Tab 走 query，刷新不丢） |
| `/admin/songs`、`/admin/artists` | AdminLayout | RequireAuth + RequirePerm | 后台管理（`/admin` 重定向到 `/admin/songs`） |
| `/403`、`/404`、`*` | MainLayout | — | 无权限 / 404 |

> `/user` 用 `?tab=` 而不是嵌套路由：三个 Tab 共享同一份用户上下文与返回逻辑，
> 嵌套路由会多出三层 `Outlet` 却没有独立的路由级状态可缓存。

### 5.2 状态归属

| Store | 状态 | 持久化 |
|---|---|---|
| `userStore` | `accessToken / refreshToken / user / isLogin / logging`，`login() / refreshUser() / logout() / hasPerm() / hasAnyPerm()` | `ml.accessToken`、`ml.refreshToken`、`ml.user`（D-05） |
| `themeStore` | `mode: 'light' \| 'dark' \| 'system'` + `resolved`，切换时写入 `<html data-theme>` 与 `color-scheme`；AntD 侧由 `ConfigProvider` 的 `darkAlgorithm` 跟随 `resolved` | `ml.theme` |
| `playerStore` | `queue / currentIndex / currentSong / isPlaying / isBuffering / currentTime / duration / volume / muted / playMode / quality / seekRequest`（模块 07 扩充：歌词行、随机序列、预取） | `ml.player`（队列/进度位置/音量/模式/音质） |
| 最近播放 | `services/history.ts`，最多 100 条，同曲去重置顶 | `ml.history`（后端播放历史属模块 12/17） |
| TanStack Query | 所有接口数据（`queryKey` 见 `src/api/*.ts`） | 内存（`staleTime` 60s） |

**关键实现细节**：`seek` 通过 `seekRequest{time, nonce}` 传递——每次拖动 `nonce` 自增，
`AudioEngine` 据此识别「新请求」，因此同一秒内连续拖动同一位置也能生效；
「上一首」在播放超过 3 秒时退化为「回到开头」（`BR-11-042`），与 `seek` 复用同一机制。

### 5.3 权限控制

- 路由级：`RequireAuth` 未登录 → `/login?redirect=<当前路径>`；`RequirePerm` 已登录但无权限 → `/403`（`AC-11-207`）
- 元素级：`usePerm('music:song:create')` / `useAnyPerm([...])` 控制按钮显隐
- **仅为体验优化**：所有写接口后端仍有 `@PreAuthorize` 二次校验（`BR-02-011`）

实际用到的权限码（与 `sql/data.sql` 的 `t_permission` 对齐）：

| 页面/按钮 | 权限码 |
|---|---|
| 顶部「管理后台」入口、`/admin` 守卫 | `music:song:update`、`music:artist:update`（任一） |
| 后台·新增歌曲 | `music:song:create` |
| 后台·编辑歌曲 / 编辑歌手 | `music:song:update` / `music:artist:update` |
| 后台·上架下架 | `music:song:online`、`music:song:offline`、`music:song:update`（任一，与后端 `hasAnyAuthority` 一致） |
| 后台·审核通过/驳回 | `music:song:audit` |
| 后台·删除歌曲（含批量）/ 删除歌手 | `music:song:delete` / `music:artist:delete` |
| 歌单详情·编辑/移歌/排序 | 创建者本人，或 `music:playlist:manage`（后端同款判断） |

## 6. 关键时序

### 6.1 登录

```
LoginPage → userStore.login({account, password})
  → POST /auth/login
  → writeRaw(accessToken/refreshToken) + writeJson(user) 落 localStorage
  → 跳转 searchParams.get('redirect') ?? '/'
未登录访问受保护路由时，RequireAuth/RequirePerm 已把当前路径编码进 ?redirect=
```

> 注意：`accessToken` / `refreshToken` 必须用 `writeRaw`（裸字符串）而不是 `writeJson`，
> 否则会写入带引号的 JSON 字符串，`Authorization: Bearer "eyJ..."` 直接被服务端判为非法。

### 6.2 401 静默刷新并重放（D-04）

```
任意请求 → 401（40101/40102/40103）
  → 若有 refreshToken 且本次未重试过：
       POST /auth/refresh → 新双 Token 落库 → 用新 accessToken 重放原请求
  → 刷新失败（或 refresh 接口本身 401）：清空登录态 → 跳 /login?redirect=当前路径
并发保护：同时多个 401 时，只发起一次 refresh，其余请求排队等其结果
```

### 6.3 首页区块独立失败（D-10）

```
HomePage 并行发 3 个 Query（热门歌曲/推荐歌单/新歌榜）
  任一 Query 出错 → 只有该区块的 SectionBoundary 渲染 ErrorState（含重试按钮）
  其余区块正常渲染（AC-11-204）
```

## 9. 风险与已知偏差

| 项 | 说明 | 处置 |
|---|---|---|
| 播放器为「外壳」 | 本期只实现播放/暂停/切歌/音量/进度条；歌词、随机模式、队列抽屉、预取属模块 07 | 接口与 store 已按模块 07 的 PRD 结构预留字段 |
| 播放地址未签发 | MVP 直接用 `song.audioStandard`（`/media/demo/demo-0N.wav`），无过期与鉴权 | D-08 适配层，模块 07 替换为 `/player/url` |
| 演示音频未生成 | `/media/demo/*.wav` 由模块 07 的 `scripts/make-demo-audio.mjs` 生成，缺失时播放失败但页面正常 | 模块 07 交付 |
| 搜索能力受限 | 未接 ES，仅用后端 `keyword` 的 LIKE 查询；无联想、无筛选面板 | 模块 06 交付；`EX-11-003-1` 的降级态即本期形态 |
| 无 Mock 层 | 前端直连后端 8081；后端未启动时页面展示失败态 | 联调需先启动后端（模块 01 §8） |
| 首次构建需联网 | `npm install` 拉取依赖；实测 `registry.npmjs.org` 本机约 192 KB/s（单个 packument 请求 25s+），换 `registry.npmmirror.com` 后约 5.4 MB/s | 本机走镜像安装：`npm install --registry=https://registry.npmmirror.com`；`web/README.md` 记录 Node/npm 版本要求与镜像用法 |
| **后台无用户管理页** | 模块 01 的 `UserController` 只暴露 `/users/me`，没有用户列表/封禁/改角色接口，写了页面也只能造数据 | 后置模块 16/09；`AdminLayout` 的菜单是数组配置，加项 + 加路由即可 |
| **后台无专辑管理页** | 同上：`AlbumController` 有增删改接口但本模块未做页面，歌曲表单里的专辑只能从已有专辑中选 | 归入模块 09 的内容管理 |
| 单页内才支持歌单排序 | 重排接口要求传**完整有序**的 `songId` 数组；超过一页（50 首）时前端拿不全，会传半截数组把顺序改坏 | 因此按钮在 `total > 50` 时禁用并给出说明；完整拖动排序归模块 09 |
| 后台下拉选项取前 100 条 | 歌曲表单的歌手/专辑/标签下拉一次性取 100 条后本地过滤，数据量上去会漏 | 模块 09 改为服务端搜索的下拉组件 |
| 主包偏大 | 构建后 `index-*.js` 989.59 kB（gzip 322.05 kB），已超过 Vite 默认 500 kB 告警阈值；`antd` + `@ant-design/icons` 占大头，路由已懒加载但 AntD 全量引入 | T118：`manualChunks` 拆 vendor + 按需引入图标；`AC-11-206` 在拆分后复测 |
| 前端构建产物与依赖目录易失 | 本机安装过程中 `web/node_modules` 曾整体消失一次（`npm` 日志显示 esbuild 等已 ADD 且 postinstall 成功，随后目录不存在，重新 `npm install` 后恢复），未定位到原因，疑似本机清理/杀软行为 | 遇到 `Cannot find package ... esbuild` 直接重跑 `npm install --registry=https://registry.npmmirror.com`；这台机器上以镜像安装，13s 内完成 |
