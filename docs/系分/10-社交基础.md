> PRD：`docs/PRD/19-模块10-社交基础.md`
> 交付范围：评论 / 点赞 / 收藏 / 关注 / 拉黑 / 通知 / 举报为 **P0**；分享短链、私信、通知与隐私设置为 **P1**。

## 1. 模块结构

```
module/social
├── config/SocialProperties           # 评论审核天数、短链域名等
├── controller                        # comment / like / collect / follow / blacklist /
│                                     # notification / privacy / report / share / message
├── dto                               # 写请求与查询参数
├── entity                            # t_comment / t_like / ... / t_user_privacy_setting
├── mapper                            # 以 BaseMapper + @Select/@Update 为主
├── service                           # 每个聚合一个服务；通知统一走 module/ws 的 NotificationService
├── support
│   ├── SocialTargets                 # 目标存在性/可互动性校验与展示名解析
│   ├── SocialUserSupport             # 用户摘要、黑名单双向判定
│   └── ContentSanitizer              # 长度、纯表情、HTML 标签清理
└── vo                                # 对外视图
```

复用既有能力：

- 通知落库与 WS 推送：`module/ws/service/NotificationService`、`WsPushService`。
- 敏感词：`module/search/support/SensitiveWordSupport`（继续使用 `search.sensitive.words` 配置，不另建词库）。
- 限流：`@RateLimit` + `RateLimitService`。
- Redis：`RedisOps`（`ml:` 前缀硬约束、熔断后降级）。
- 逻辑删除/乐观锁：`BaseEntity`；关联表（点赞/收藏/关注/拉黑/歌手关注）用 `BaseLinkEntity` 物理删除。

## 2. 关键决策

### D-01 错误码统一落在 50xxx，不复用 PRD 的 40016~40030 / 70004~70005

PRD 10 章沿用了其它模块的编号：`40016` 禁言、`40017` 频率、`40026` 重复举报、`70004` 目标不存在等。但本项目：

- `40xxx` 已被模块 05 音乐房整段占用（`ROOM_KICK_COOLDOWN=40016`、`ROOM_BLACKLIST_FULL=40017`…）；
- `70xxx` 已被模块 06 搜索占用（`SEARCH_KEYWORD_ILLEGAL=70004`、`SEARCH_CURSOR_REQUIRED=70005`）。

同一进程出现两个同号不同语义的错误码，前端无法判断该提示「房间黑名单已满」还是「评论太频繁」。因此社交错误码全部放在 `ResultCode` 已划定的 **50xxx** 段：

| 场景 | 采用码 |
|---|---|
| 评论不存在/已删 | `50001` |
| 敏感词/纯表情 | `50002` |
| 评论频率 | `50003`（接口注解也可能先返回 `10004`） |
| 自己关注自己 | `50004` |
| 被对方拉黑 | `50005` |
| 重复评论 | `50009` |
| 关注上限 2000 | `50010` |
| 拉黑上限 500 | `50012` |
| 私信相关 | `50013`~`50016` |
| 举报相关 | `50017`~`50019` |
| 目标不存在/已下架 | `50020`/`50021` |
| 收藏夹上限/重名 | `50023`/`50024` |

`docs/PRD` 不改：PRD 是需求基线，偏差在本文记录。

### D-02 `target_type`：新表用字符串枚举，`t_notification.target_type` 保持 TINYINT

- `t_comment` / `t_like` / `t_collect` / `t_share`：`VARCHAR(20)`，取值 `SONG` / `PLAYLIST` / `ALBUM` / `COMMENT` / `ROOM` / `ROOM_MESSAGE` / `USER` / `MESSAGE`。
  这与 PRD 10 的数据模型一致，也避免「以后加一种内容就要改表」。
- `t_notification.target_type` 是模块 04 既有列（`TINYINT`），本次**不改列**（改列会影响已上线的通知数据与后台）。新增映射：

  | 值 | 类型 |
  |---|---|
  | 1 | SONG |
  | 2 | PLAYLIST |
  | 3 | ALBUM |
  | 4 | COMMENT |
  | 5 | USER |
  | 6 | ROOM（沿用 `RoomNotifier.TARGET_ROOM`） |
  | 7 | ROOM_MESSAGE |
  | 8 | MESSAGE |

  通知接口额外返回字符串 `targetTypeName` 由服务端映射，前端不必硬编码。

### D-03 评论「转义存储」改为「剔除 HTML 标签后按纯文本存储」

PRD BR-19-012 要求转义存储。实际前端全部用 React 文本节点渲染、没有 `dangerouslySetInnerHTML`；如果服务端把 `<` 存成 `&lt;`，React 再转义一次，用户会看到字面量 `&lt;`。

落地方式：

1. 提交时用 `ContentSanitizer` **剔除 HTML 标签**（`<[^>]*>`）与控制字符；
2. 剔除后为空则拒绝；
3. 数据库存纯文本，前端按文本渲染。

这既满足「不执行脚本」，又不会出现双重转义。外部链接按 BR-19-013 一并降级为纯文本（正则保留 URL 字符，不生成 `<a>`）。

### D-04 审核：只做「敏感词拦截 + 新用户先审后发」，不做机审

模块 18（内容安全）尚未交付，没有 AI 审核服务。当前实现：

- 命中 `search.sensitive.words` → `50002`；
- 注册 ≤ `newmusic.social.comment.new-user-audit-days`（默认 7 天）且非运营/管理员 → `status=0`（仅作者可见）；
- 其余 → `status=1` 立即发布；
- 无异步机审。后续接入模块 18 时只需在 `CommentService#create` 的「状态判定」处替换。

### D-05 点赞/收藏/关注：MySQL 是权威，Redis 是加速与去重镜像

PRD 以 Redis Set 为主、异步落库。本项目的取舍：

- 写入先走 MySQL 唯一索引（`INSERT IGNORE`）保证**幂等与不丢**；
- 同时维护 Redis Set（`ml:like:*`、`ml:follow:*`、`ml:blacklist:*`），用于「是否已点赞/已关注」与黑名单双向判定；
- 计数读 MySQL 冗余列（`t_song.like_count` 等）并在同一事务内 `GREATEST(x + delta, 0)` 更新；
- Redis 不可用时全部退化为 MySQL，不阻断主流程。

理由：本机 Redis 是共享实例、可能被清空；把唯一性寄托在 Set 上会出现「缓存丢了就重复计数」的脏数据。PRD 的异步刷盘方案适合大规模，当前规模用 DB 权威更简单且可对账。

### D-06 通知类型扩展

`t_notification.notify_type` 是 TINYINT，模块 04 已定义 1~9。本次追加：

| 值 | 含义 |
|---|---|
| 10 | 关注歌手发新歌 |
| 11 | 账号处置（封禁/禁言） |
| 12 | 申诉结果 |
| 13 | 推荐提醒 |
| 14 | 关注的房主开播 |

`NotificationService.wsType` 同步补 `notify.new_song` / `notify.ban` / `notify.appeal` / `notify.recommend` / `notify.room_follow`。

### D-07 通知设置与隐私设置分表

- `t_notification_setting`：分类开关（点赞/评论/关注/私信/系统/新歌/已读回执）。
- `t_user_privacy_setting`：谁能私信/评论/@、关注与粉丝列表可见性、播放历史可见性等。

两表都按 `user_id` 唯一，缺省行按「全部开放 + 播放历史仅自己」处理，首次 PUT 时插入。

### D-08 私信实时事件命名

PRD 13 章用大写 `PRIVATE_MESSAGE` / `MSG_READ` / `MSG_REVOKE`。本项目 WS 既有事件全部是 `域.动作` 小写（`room.chat`、`notify.like`），因此私信采用：

- `msg.new`：新私信
- `msg.read`：对方已读回执
- `msg.revoke`：消息撤回

前端在 `wsStore` 内统一映射，接口契约以本文为准。

### D-09 短链

- 短码 6 位 Base62，字符集剔除 `0O1lI`；
- Redis `ml:social:short:{code}` 存 Hash，TTL 30 天；MySQL `t_share` 落库用于统计；
- `GET /s/{code}` 返回 302 到 C 端页面（`newmusic.social.share.web-base-url`，默认 `http://localhost:5173`），带 `from=share&sharerId=`；
- 点击计数 Redis `ml:social:short:click:{code}` + DB `t_share.click_count`。

### D-10 举报合并

提交时若同一 `target_type + target_id + reason_type` 已有待处理举报，则新举报记为 `status=4`（已合并）并写 `merged_into_id`，不再生成新审核任务。

模块 09 的 `ReportService` 在处置主举报后，会额外查询 `merged_into_id = 主举报ID` 的记录并逐一通知举报人——这样「多人举报合并」与「举报人收到结果」两个验收点同时成立。

### D-11 分页与可见性

- 评论/收藏/关注/通知/私信统一用 `PageResult`。
- 评论列表按 `pageSize ≤ 100`，深分页沿用模块 05 的「超过 100 页由前端改用最热」策略，本期不做游标。
- 被拉黑者的评论在服务端过滤（双向）；过滤后当页可能少于 `pageSize`，这是预期行为。

## 3. 数据表

新增 12 张表，全部 `CREATE TABLE IF NOT EXISTS`，只作用于 `newmusic` 库：

| 表 | 公共实体 | 说明 |
|---|---|---|
| `t_comment` | `BaseEntity` | 二级评论，`root_id`/`parent_id` |
| `t_like` | `BaseLinkEntity` | 唯一键 `(user_id,target_type,target_id)` |
| `t_collect` | `BaseLinkEntity` | 收藏，`folder_id` 可空 |
| `t_collect_folder` | `BaseLinkEntity` | 收藏夹（物理删除，避免重名唯一键冲突） |
| `t_share` | `BaseLinkEntity` | 短链与点击统计 |
| `t_follow` | `BaseLinkEntity` | 唯一键 `(follower_id,following_id)` |
| `t_user_artist_follow` | `BaseLinkEntity` | 唯一键 `(user_id,artist_id)` |
| `t_blacklist` | `BaseLinkEntity` | 唯一键 `(user_id,blocked_user_id)` |
| `t_conversation` | `BaseEntity` | 唯一键 `(user_a_id,user_b_id)`，`a < b` |
| `t_private_message` | `BaseEntity` | 双侧删除标记、撤回标记 |
| `t_notification_setting` | `BaseEntity` | `user_id` 唯一 |
| `t_user_privacy_setting` | `BaseEntity` | `user_id` 唯一 |

DDL 同时写入 `sql/schema.sql`（全新安装）与 `sql/10-social-seed.sql`（存量库升级，幂等）。

## 4. 接口与验收

接口清单见 PRD 12 章。自动化验收脚本 `scripts/verify-10.mjs` 覆盖：

- 评论：发表/列表/二级回复/删除/敏感词/重复/限流/新用户审核；
- 点赞：幂等/取消/批量状态/我的喜欢/计数落库；
- 收藏：幂等/取消/列表/收藏夹 CRUD/移动；
- 关注：关注/取关/自己/上限/列表/互关标记/歌手关注；
- 拉黑：自动取关/评论过滤/解除/上限；
- 通知：列表/已读/全部已读/清空/设置；
- 举报：原因字典/提交/去重/自举报/我的举报；
- 分享：短链生成/302 跳转/点击计数；
- 私信：会话唯一/发送/未读/已读/撤回/拉黑拦截/非互关 3 条；
- 隐私设置读写；
- 共享实例完整性（`ranking:*`、`emp_db`/`music_db` 前后一致）与精确 ID 清理。

运行：

```bash
MYSQL_PASSWORD=<本机 MySQL 口令> node scripts/verify-10.mjs
```
