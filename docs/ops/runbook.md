# 应急预案（Runbook）

> 模块 19 交付。种子数据在 `sql/19-ops-seed.sql`，运行时通过后台
> `GET /api/v1/admin/ops/runbooks` 读取，告警规则用 `runbook_key` 关联到这里。
> 本文件是同一份内容的离线副本，方便故障时在无后台访问的情况下查阅。
>
> 共 11 条，P0 5 条、P1 6 条。新增/修改预案时**先改种子脚本再同步本文件**，
> 避免数据库与文档各说一套。

## 0. 通用处置顺序

1. **止血优先**：先降级 / 限流 / 回滚，再定位根因。后台 `/ops` → 降级页可直接切等级。
2. **确认爆炸半径**：看 `/api/v1/admin/ops/overview` 与 `/system/status`，区分单接口、单依赖、全站。
3. **留证**：记下 `traceId`、告警记录 ID、发布记录 ID；发布/备份/告警/混沌记录不要删。
4. **恢复要逐项确认**：依赖恢复后再降等级，避免二次故障。
5. **复盘**：P0 30 分钟内出初步报告，2 小时内复盘；P1 当日复盘。

## 1. `app-all-down` — 应用实例全部不可用（P0，SRE）

**现象**：健康检查失败，所有实例 5xx。

1. 查 Pod / 进程状态与启动日志（`StartupSelfCheck` 缺表会直接启动失败并打印修复脚本）。
2. 查最近发布记录，必要时一键回滚。
3. 查 DB / Redis 依赖是否可用。
4. 资源不足则扩容。
5. 无法快速恢复时启用静态兜底页。

## 2. `app-slow` — 接口 P99 突增（P1，开发）

**现象**：P99 > 1s 或慢 SQL 告警。

1. 看 `/api/v1/admin/ops/metrics` 与 `/metrics/routes` 找慢接口。
2. 查慢 SQL 与连接池水位。
3. 查 GC 与线程池（`/metrics/threadpools`）。
4. 必要时开启降级等级 1/2。
5. 保留 `traceId` 复盘（`/admin/ops/traces`）。

## 3. `redis-down` — Redis 全量不可用（P0，SRE）

**现象**：缓存 miss 暴增、DB 压力上升。

1. 查 Redis 状态与内存；**不要** `FLUSHDB` / `FLUSHALL`，6379 是共享实例。
2. 限流自动切本地滑动窗口（`LocalRateLimiter`），无需人工干预；确认 429 比例可接受。
3. 锁降级为 DB 乐观锁。
4. Feed 降级为全拉。
5. 恢复后预热热 key。**关键是先保护 DB**。

## 4. `mysql-down` — MySQL 主库不可用（P0，DBA）

**现象**：写操作失败，连接池耗尽。

1. 查主库进程 / 复制 / 磁盘。
2. 触发主从切换（生产用 Orchestrator，本机无从库）。
3. 应用重连。
4. 校验数据一致性。
5. 前端提示稍后重试（降级等级 5 只读模式）。

## 5. `play-drop` — 播放量骤降（P0，SRE）

**现象**：播放指标环比下降 > 30%。

1. 先确认埋点是否正常（模块 17 采集链路）。
2. 查 CDN 404 / 超时。
3. 查播放签名与接口错误（`/api/v1/player`）。
4. 查前端 JS 错误。
5. 判断是否全站故障。

## 6. `content-leak` — 高危内容漏出（P0，内容安全）

**现象**：发现违规内容已公开。

1. 立即下架。
2. 定位词库 / 机审 / 人工误判。
3. 热更新词库（后台 → 内容安全 → 词库热加载）。
4. 全量回溯同类内容。
5. 30 分钟初步报告、2 小时复盘。
6. 涉及监管红线按流程上报。

## 7. `ai-cost` — AI 成本突增（P1，算法/运营）

**现象**：AI 日成本达到预算 80%（`ops.cost.daily-budget-cent`）。

1. 按场景聚合 `t_ai_call_log`。
2. 查缓存命中率（模块 14 网关缓存）。
3. 查刷量用户并封禁。
4. 对高消耗场景限流。
5. 必要时熔断该场景 AI（熔断器列表可见状态）。

## 8. `ws-storm` — WebSocket 连接数异常（P1，开发）

**现象**：连接数远超预期或骤降。

1. 查客户端重连风暴。
2. 查实例分布。
3. 下发退避重连间隔。
4. 调整一致性 hash。
5. 扩容 WS 实例。

## 9. `disk-full` — 磁盘写满（P1，SRE）

**现象**：日志 / 备份写入失败，磁盘可用 < 15%。

1. 清理滚动日志。
2. 检查大文件与备份保留期（`ops.backup.retention-days`，默认 7 天）。
3. 扩容磁盘。
4. 验证日志采集恢复。

## 10. `degrade` — 人工降级/恢复（P1，SRE）

**现象**：错误率或依赖故障需要降级。

1. 在后台 `/ops` → 降级页选择等级 1~5（或单独关闭某个功能开关）。
2. 确认 C 端顶部降级公告出现、受影响功能列表正确。
3. 观察 DB / Redis / 错误率变化。
4. 恢复前逐项确认依赖已恢复。
5. 记录等级变更事件（`t_degrade_event`，后台「最近降级事件」可查）。

> `feature.safety`（安全与申诉）级别为 99，任何等级下都不关闭。

## 11. `chaos` — 混沌演练异常（P1，SRE）

**现象**：演练期间错误率 / 延迟超出预期，或实验未按时结束。

1. 确认当前实验的故障类型与爆炸半径（`GET /api/v1/admin/ops/chaos/current`）。
2. 超出爆炸半径立即停止实验（`POST /api/v1/admin/ops/chaos/stop`）。
3. 观察降级开关与限流兜底是否按预期生效。
4. 实验最长 120s 自动结束；超时未结束按 P1 上报。
5. 复盘记录演练结论与改进项。

**硬上限**：时长 ≤ `newmusic.ops.chaos-max-duration-seconds`（默认 120s），
爆炸半径 ≤ `chaos-max-blast-radius`（默认 100），同一时刻只允许一个实验。
